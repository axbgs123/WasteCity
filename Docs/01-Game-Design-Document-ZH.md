# A 卷：首版 Demo 执行设计

## A0. 文档使用说明

本文件是项目唯一主设计文档。A 卷用于指导首版 Demo 的实际制作、测试与验收；B 卷保留原始正式版世界观、系统、内容库和长期设想。后续开发不应只删除暂缓功能，而应更新其状态、依赖和验证结论。

### A0.1 范围状态

| 标记 | 含义 |
|------|------|
| **D1-实装** | 首版 Demo 必须真正开发，并参与核心玩法 |
| **D1-简化** | 保留玩家体验，但采用固定内容或简化规则实现 |
| **D1-预告** | 只通过界面、文本、演出或结尾展示 |
| **正式版** | 完整设计保留在 B 卷，首版 Demo 不开发 |

### A0.2 强制扩展原则

首版减少的是内容数量，不是系统扩展能力。

- 资源、建筑、敌人、命轨、科技、领袖、事件均采用数据驱动；
- 新增同类内容原则上通过配置接入，不修改核心流程代码；
- 首版固定事件同样使用通用事件条件，不直接写死在场景脚本中；
- 系统间通过明确的输入、输出和事件通信，避免互相读取内部状态；
- 每项配置使用带命名空间的稳定 ID，不以显示名称作为逻辑键；
- 所有玩家可见文字使用本地化 Key，不在规则代码中写中文显示文本；
- 存档按版本号和系统模块组织，为后续字段迁移预留空间；
- Demo 专用演出可以定制，但不能绕过资源、战斗、科技等核心规则伪造结果。

扩展接口按两级处理：

- **首版必须保留的内容扩展**：资源、建筑、敌人、科技、命轨、角色、事件；
- **首版只避免堵死、不提前抽象的规模扩展**：多城市、跨星球、外交、继承政治、复杂运输。

原则是“内容扩展现在做，规模扩展以后做”。没有首版调用者的抽象层不得仅因正式版设想而提前开发。

### A0.3 AI 执行边界

向 AI 分派首版开发任务时，必须附带以下约束：

> 只以 A 卷为当前版本需求。B 卷只用于理解正式版背景；除非任务明确引用，否则禁止实现 B 卷功能。A、B 冲突时执行 A 卷。不得自行增加系统、资源、敌人、建筑或技术架构。

每次任务只提供当前功能所需章节和依赖，避免将整份 B 卷作为无差别实现上下文。

## A1. 产品定义

### A1.1 一句话介绍

一款俯视角移动城市游戏。玩家驾驶前代文明留下的城市残骸穿越废土，在资源点展开生产与防御；发展越快，越容易引起未知存在的关注，迫使玩家在坚守与转移之间持续决策。当前 Demo 使用 2D 灰盒验证规则，正式表现目标为保持同一俯视交互的 3D 场景，不改为第三人称。

### A1.2 Demo 产品目标

1. **玩家目标**：首次 30-40 分钟内体验完整的“移动→展开→生产→防守→坚守或撤离→升阶”循环，并产生继续探索正式版的欲望。
2. **作品集目标**：展示产品定位、用户体验、版本范围、系统拆解、数值设计、AI 生产管理、测试和迭代能力。
3. **正式版目标**：Demo 是可继续扩建的纵向切片，不是完成后全部推翻的一次性原型。

### A1.3 目标玩家

- 喜欢《Mindustry》《Thronefall》《Factorio》等生产、建造或塔防游戏的 PC 玩家；
- 喜欢废土、文明成长与幕后危机叙事的玩家；
- 能接受中等学习成本，但希望开局数分钟内获得明确操作反馈的玩家。

### A1.4 时长目标

- 首次完整体验：30-40 分钟；
- 熟练玩家：20-25 分钟；
- 不通过强制等待、重复波次或压低生产速度凑时长；
- 通关后允许继续游玩当前地图，但不再解锁正式版后续主线。

### A1.5 核心体验支柱

1. **城市就是角色**：城市能移动、碾压、展开、受伤和撤离，不是普通基地。
2. **生产服务战斗**：生产线必须直接改变防御能力，资源瓶颈必须可观察。
3. **力量引来目光**：建造、研究、命轨和升阶会提高关注度。
4. **命轨改写规则**：命轨改变布局、经济或时间规则，而非普通数值 Buff。
5. **世界存在异常**：Demo 只制造怀疑和悬念，不一次讲完全部世界观。

### A1.6 首版非目标

- 不验证多星球、多城市、外交、继承政治和完整四路线；
- 不追求无限重玩、完整沙盒或正式版内容量；
- 不以底层技术复杂度作为首要卖点；
- 不为了系统齐全牺牲可理解性和完成度；
- 不要求所有玩家必须玩满 40 分钟。

## A2. 核心循环

### A2.1 长循环

```text
移动探索
  → 发现资源与风险
  → 选择展开位置
  → 建造生产与防御
  → 获取力量并提高关注度
  → 应对定向攻击
  → 收起转移或继续坚守
  → 在新区域重复并完成文明升阶
```

### A2.2 中循环

约 5-10 分钟：

```text
发现矿区 → 展开生产 → 扩建防线 → 承受怪潮 → 回收或转移
```

### A2.3 短循环

约 30-60 秒：

```text
击杀或采集 → 获得资源 → 建造或补充弹药 → 防御能力提高
```

### A2.4 核心设计假设

以下结论尚未被试玩证明，必须进入测试：

- 移动城市比固定建城更有趣；
- 展开收益与暴露风险能够形成真实取舍；
- 玩家能理解生产瓶颈并愿意主动扩产；
- Boss 阶段的坚守与撤离都是合理解法；
- 命轨能够显著改变玩家策略；
- 生产、领袖和塔防操作不会造成过高认知负担。

## A3. 六幕体验流程

### A3.1 第一幕：遗产苏醒（0-3 分钟）

**玩家目标**：理解城市能移动、碾压怪物并回收尸体。

- 100 名幸存者意外激活上一循环留下的移动城市；
- 遗产系统弹出三条命轨，玩家三选一；
- 城市开始缓慢移动，引导玩家使用 WASD；
- 玩家碾过“啃噬者”，尸体转化为生物质；
- 控制台从乱码中出现少量可读文字，暗示城市并非当前文明制造。

**验收**：

- 开局 30 秒内完成第一次有效操作；
- 90 秒内获得第一次资源；
- 玩家知道移动城市本身也是武器。

### A3.2 第二幕：寻找落脚点（3-7 分钟）

**玩家目标**：在资源收益、敌人密度和位置安全之间做第一次选择。

- 地图提供安全但贫瘠的浅层铁矿；
- 同时提供怪物更多、产量更高的结晶裂谷；
- 驶近后自动扫描矿脉；
- 玩家可以立即展开，也可以继续探索；
- 扫描与长时间停留会轻微提高关注度。

**范围**：

- 固定地图骨架：**D1-简化**；
- 资源、巡逻怪和非主线遗迹局部随机：**D1-实装**；
- 完整程序化世界：**正式版**。

### A3.3 第三幕：第一次展开（7-11 分钟）

**玩家目标**：理解移动与展开两种状态的收益和限制。

- 玩家启动展开，城市进行约 5 秒变形；
- 展开后出现建筑网格，移动能力关闭；
- 城市自带仓库、住房和三段残破城墙；
- 玩家建造第一座采矿站；
- 少量游荡怪靠近，城市核心的低效自卫武器暂时兜底。

**验收**：

- 展开后 60 秒内看到铁矿产量变化；
- 玩家能够找到建造入口；
- 第一次展开不因 8 秒纯等待破坏节奏。

### A3.4 第四幕：生产服务战斗（11-20 分钟）

**玩家目标**：建立第一条完整、可观察的生产链。

```text
采矿站 → 铁矿 → 冶炼厂 → 合金 → 装配厂 → 弹药 → 机枪塔
```

- 城市物流范围内自动共享资源；
- 建筑显示输入、输出、库存、效率和阻塞原因；
- 第一座塔建成后立即出现小规模怪群；
- 初始弹药保证塔可立即射击，但无法长期跳过生产；
- 第二座塔制造明显弹药压力，推动玩家扩产。

**验收**：

- 玩家能够回答“为什么缺弹药”；
- 玩家知道增加哪种建筑能解决当前瓶颈；
- 2 座采矿站的完整生产链可稳定支持 1 座持续射击的机枪塔。

### A3.5 第五幕：关注与领袖（20-29 分钟）

**玩家目标**：理解发展速度会转化为外部压力。

- 建造、研究和命轨使用推动关注度达到首次阈值；
- 领袖候选人“岑烬”通过求救事件出现；
- 玩家可以立即救援，牺牲矿区发展时间；
- 也可以先扩充防御，使岑烬受伤并降低 Boss 战技能效果；
- 岑烬加入后提供一个主动技能和一个城市被动；
- 第一轮定向攻击开始，加入重甲与远程敌人。

**验收**：

- 玩家因为资源或时间不足放弃一部分收益；
- 救援选择产生可感知、但不锁死流程的结果；
- 玩家开始怀疑怪物在针对生产设施。

### A3.6 第六幕：坚守、撤离与升阶（29-40 分钟）

**玩家目标**：在高潮中回收移动城市、生产、关注度和命轨四个核心设计。

- 关注度达到第二阈值；
- Boss“晶壳母体”带领怪潮出现；
- 玩家可留在原阵地，用生产线持续供弹；
- 也可收起城市，牺牲部分外围建筑或资源，转移到有利地形；
- 两种方案均可通关，但结算评价不同；
- 击败 Boss 后满足文明升阶条件；
- 玩家主动升阶，命轨升级一次；
- 升阶信号被未知存在捕捉，触发结尾扫描；
- 结算后可继续游玩当前地图。

**验收**：

- 坚守与撤离均通过内部测试；
- 玩家至少考虑过一次城市转移；
- 结尾同时完成战斗高潮、系统回收和叙事悬念。

### A3.7 事件触发接口

六幕由统一事件条件驱动，支持：

- 游戏时间；
- 资源数量；
- 建筑状态；
- 科技状态；
- 击杀和敌人状态；
- 地图位置；
- 关注度；
- 人口与生产力；
- 前置事件与玩家选择。

事件结果支持资源、人口、关注度、建筑、科技、角色状态、对话和后续事件，不把分钟数写成唯一触发条件。

### A4.2 移动与展开

> 已批准需求：`IDEA-0001`、`IDEA-0005`；已实现待验证需求：`IDEA-0014`。准确状态与未完成人工验收见 `Docs/06-User-Feedback-and-Change-Control-ZH.md`。

```text
移动中 → 展开中 → 已展开 → 收起中 → 移动中
                  ↓
                 摧毁
```

- 移动中可探索、碾压小怪、回收尸体，并在移动城市本体的内城网格进行轻型施工；
- 移动中不能施工地面建筑或运行重型工业生产；生活、维修和轻型生产允许以降低后的效率继续；研究站可建在内城并随城移动，研究在堡垒态按 100% 推进，在移动、展开中和收起中按 50% 连续推进；
- 住房属于内城与地面皆可：移动形态只能在内城施工，要塞形态可在内城或外城施工；当前内外城住房生命值、人口容量和效率相同，并统一经过施工与撤离规则。未来允许把外城住房调整为更低生命值和更少人口容量，但必须先另行确定数值并批准，不得提前加入隐藏修正；

### A4.4 资源与制作

> 已批准需求：`IDEA-0011`、`IDEA-0012`、`IDEA-0016`。`IDEA-0011`、`IDEA-0012` 先形成并观察机枪塔之前的生产闭环，同时接入玩家背包、两条应急手工合成、首版科技树界面、文明式资源状态栏、真实仓库库存和统一资源图标；其“敌人、炮塔和弹丸不在本阶段”的限制保留为历史范围。后续已实现待验证的 `IDEA-0013` 只按 A4.6/A16 的最小切片接入机枪塔、啃噬者、教学波和城市核心受击，不反向扩大前述历史里程碑。`IDEA-0016` 在这些既有真值之上批准资源与制作体系、四路线科技树和统一二维图标表现的正式扩展边界；准确资源清单、配方、产量、消耗和地图投放数值仍须由后续批准的设计规格确定，本节不提前锁定。

```text
铁矿 → 合金 → 弹药 → 机枪塔
怪物尸体 → 生物质 → 维修 / 救援 / 命轨代价
```

- 每种基础原料至少拥有两个用途；弹药等明确服务单一系统的中间品可以只有一个最终用途，但其产销瓶颈必须可见；
- 领袖允许少量手工采集或回收，用于开局和紧急缺口，但效率与携带量不能长期替代采矿建筑；
- 自动生产严格采用 A6.2 与 A16.3 的配方、周期和内部容量；输入批次在周期开始时一次性取得或预留，完成时才生成输出，整个周期必须保持原子性；
- 已取得输入批次的生产，即使随后脱离物流范围也允许完成；完成品优先卸入可访问的城市库存，不能卸载时保留在建筑输出库存；
- 生产停滞只显示一个当前首要原因：缺少输入、输出已满、不在物流范围、矿脉已枯竭或玩家暂停运行；全局战术/系统暂停冻结规则时间，但不覆写建筑自己的暂停状态；
- 玩家背包与城市库存、建筑内部库存分离。自动生产不直接读取或消耗背包，只能通过玩家发起的统一原子转移改变归属；
- 背包内开放两条低效率应急合成，且只消耗和产出背包物品：`4 铁矿 → 1 合金 / 12 秒`、`4 合金 → 2 弹药 / 12 秒`；它们用于救急，不能替代自动化生产；
- 首版不制作电力系统；
- 能晶、水、石料沿用既有稳定资源 ID，可进入背包和资源状态显示；采矿站允许从兼容的铁矿、能晶和石料节点采出节点真实资源，但本阶段不为石料、水或路线资源增加后续加工链。四路线资源的完整产销仍保留在 B 卷，并在发现或解锁前隐藏；
- 数值全部进入配置表，不写入代码。

`IDEA-0016` 的资源与制作扩展采用三层模型：

1. **通用原材料层**：来自地图资源点、环境采集、回收、战利品或其他已批准来源，是多路线共同消费的基础输入；
2. **路线中间品层**：由科技、修仙、血肉、灵能各自的加工建筑或配方从原材料转化而来，承担路线辨识和生产瓶颈；
3. **终端制作品层**：包括组件、消耗品、装备和建筑输入，并允许通过已解锁的跨路线精炼或融合配方组合多个路线的产物。

每一种材料必须以稳定资源 ID 进入同一资源目录，并由正式配置声明来源类别、用途类别、发现/可见条件和可用配方；库存、资源状态栏、背包、合成、仓库、科技成本、建造成本和世界浮标只读取该目录，不得各自维护材料名称、图标或用途副本。来源与用途真值边界如下：

- 地图资源点的类型、坐标和剩余储量仍由 `WorldMapModel` 持有；生产建筑、回收、战利品或事件只通过各自既有权威运行时入口产出，不建立第二套资源点或库存真值；
- 精炼配方的输入必须引用已有稳定资源 ID；跨路线融合配方必须显式声明来自多个路线的输入或解锁前置，不能用 UI 文案暗示不存在的来源；
- 科技树展示全部节点不等于未发现资源提前进入背包、库存或资源状态栏；材料可见性仍服从正式资源目录的发现规则；
- 在本轮资源规格获批前，seed `8128` 的既有 `32×24` 内容区和 `IDEA-0006` 的 `64×48` 外圈地图保持冻结：不得为配合资源扩展而静默新增、移动、删除或重随机资源点。新增地图资源类型、投放区域或储量分布必须作为独立地图制作变更审批；
- B 卷中的材料和路线配方目前只描述产品方向与结构示例，不自动成为本轮最终清单或数值。后续设计规格必须先明确每项材料的来源、用途、配方、容量影响和地图依赖，再进入实现。

## A5. 人口与城市生产力

### A5.1 首版人口

首版人口不通过 30 分钟内的自然生育增长，而通过救援幸存者增加。

- 初始人口：100；
- 初始容量：150；
- 住房：容量 +50；
- 可选遗迹救援：人口 +20；
- 岑烬救援：人口 +40；
- 正常通关人口：140-160；
- 首轮研究站属于初始可建建筑，人口门槛为 `0`；长期人口门槛必须等正式人口增长循环可达后另行平衡和批准。

### A5.2 生产力公式

```text
生产力倍率 = 50% + 当前人口 × 0.5%
首版上限 = 250%
实际建造时间 = 基础建造时间 ÷ 生产力倍率
```

| 人口 | 生产力 |
|------|--------|
| 100 | 100% |
| 120 | 110% |
| 140 | 120% |
| 150 | 125% |
| 160 | 130% |
| 200 | 150% |
| 400 | 250%（达到首版上限） |

首版生产力影响：

- 建筑建造；
- 建筑拆除；
- 城市展开与收起；
- 战后建筑维修。

首版生产力暂不直接影响采矿、冶炼和装配速度，防止人口同时放大全部经济环节。后续使用统一修正来源：

```text
城市生产力
├─ 人口：D1-实装
├─ 领袖：正式版
├─ 科技：正式版
├─ 士气：正式版
├─ 城市模块：正式版
├─ 环境地形：正式版
└─ Buff / Debuff：正式版
```

每个修正项包含来源 ID、作用对象、加成方式、数值和持续时间。建筑逻辑不能直接读取人口。

|------|------|-----------|
| 城市核心 | 2000 | 碾压 100/秒 |

| 岑烬 | 500 | 炮塔过载 5 秒 |

### A7.2 关键交互

- 资源状态栏采用文明式概览：铁矿、能晶、石料、生物质、水五种基础资源常驻；合金与弹药在发现或解锁后动态加入；每项显示图标、当前量/有效容量和近期净变化，正负趋势使用颜色与符号共同表达；
- 悬停资源补充近期收入/消耗、预计耗尽或装满时间与容量来源；点击资源打开只读明细账。状态栏和明细账只读取统一库存/资源账本快照，不自行维护第二份资源真值；
- `E` 打开背包与手工合成页：左键拿起、放置、合并或交换，右键拆分一半/逐个放置，`Shift+左键` 在当前允许访问的背包与库存之间快速转移；
- 背包为 `10×3` 共 30 格。相同稳定资源 ID 才能堆叠，首轮每格上限统一为 100，但数值必须来自正式资源配置；所有既有资源均可由同一格子模型承载，未发现的路线资源不提前显示；
- 手工合成页可显示自动化配方供玩家比较，但只能把 A6.2 的两条应急配方加入手工队列；建筑物品和自动化建筑配方不可手工排队；
- 点击建筑：输入、输出、库存、效率、停工原因；
- 点击机枪塔：生命、当前目标、射程、射击/玩家暂停状态、本地弹药和物流连接；点击啃噬者：生命、目标、目标距离和移动/攻击状态。两者必须经过正式 Input System 的世界选择主循环，不能只靠测试或 UI 直接调用内部方法；
- 建造面板：常用快捷栏 + 分类列表；已获得线索但条件不足的建筑置灰并显示原因，尚未发现的隐藏建筑、尚未接触的路线建筑和唯一特殊建筑不进入普通列表；
- 放置建筑：选中目录卡片后、确认放置前持续显示半透明三维建筑、真实占格、明确朝向箭头、资源成本与红绿合法性原因；`R` 旋转必须在同一锚点立即同步模型朝向、矩形占地和合法性评估，不得跳格、错位或只旋转其中一层；支持连续放置、拖动城墙和取消未施工规划；
- 所有可见建筑的选择失败和蓝图放置失败，都必须固定显示在位置不变的建造栏正上方，包括人口、研究、前置建筑、城市形态、范围、占用、地形、障碍、资源节点和材料条件；提示只投影统一解锁与放置评估，不得阻挡世界点击或另建判断真值；尚未发现的隐藏内容继续隐藏；
- 当材料不足时，预览与点击确认反馈必须从正式成本和库存快照逐项列出资源名称、拥有量、需要量和缺口，例如“缺少石料 6（拥有 0，需要 6）”，不得只显示笼统的“材料不足”；
- 进入建造模式后，外城覆盖层直接读取统一范围规则，使用低透明度格网和边界表达“属于外城建造范围”；它不代表逐格最终合法性，占用、地形、障碍、资源和其他规则仍由当前蓝图的红绿预览及失败原因表达；
- 选择采矿站后，显示当前外城范围内全部兼容资源节点；存在通过完整统一放置评估的 `2×2` 锚点时标出绿色合法锚点，兼容但没有合法锚点的节点显示暗黄色，范围外节点不显示；铁矿、能晶和石料节点都必须显示统一资源图标、正式名称与剩余储量，图标自动浮在节点上方并保持可读；
- 常态资源节点标记按正式镜头缩放分级：近景显示图标、名称与储量，中景显示图标与储量，远景只保留图标或受控聚合；进入采矿站放置指引时仍以合法性优先显示必要名称、储量和锚点。分级只改变表现密度，不得隐藏节点真值、修改储量或建立第二份节点状态；
- 点击生产力：当前人口贡献和未来修正来源槽；
- 撤离清单显示每项处理方式、预计退款、耗时、未完成比例、内部物资后果、仓库迁移条件和具体失败原因；完整拆除处理中显示稳定队列、当前项目和剩余时间。清单不自动暂停规则时间，但必须允许玩家继续使用战术暂停；容量阻塞时允许按 `E` 打开背包与城市库存腾出空间，关闭后返回同一冻结批次并重新检查当前项目，不得重建新的和平批次；
- 点击关注度：最近三条变化；
- Boss 预警：方向、倒计时和风险说明；
- 镜头默认跟随当前控制对象，允许中键自由拖动，并提供快速返回当前对象的动作；
- `Space` 战术暂停时允许查看信息、调整生产、放置规划和下达命令，但规则时间、施工、运输与战斗不推进；

- 新系统使用一次短提示，之后不重复阻塞；
- 教学可跳过并可在帮助页重新查看。

## A8. Demo 叙事

### A8.1 叙事目标

Demo 只需让玩家知道：

1. 城市来自前代文明；
2. 灾难和怪潮可能并非自然形成；
3. 文明升阶后，玩家被某种存在确认。

Demo 不直接解释联邦完整历史、高维玩家、监察者名称、三派、白点预言、循环次数和升维条件。

### A8.2 信息揭示

**开局**：城市控制台原本是乱码；命轨选择后，部分内容变为可读，而幸存者看不见玩家看到的完整界面。

**中段**：怪物定向攻击生产节点；遗迹中的灾难周期过于精确；攻击前出现无法追踪来源的倒计时。

**结尾**：升阶后天空出现规则扫描，系统截获：

> “异常变量确认。遗产响应程度：超出历史样本。”

随后被未知信息覆盖：

> “它们已经看见你了。下一次，不会只派这些东西。”

### A8.3 正式版愿景预告

- 科技、修仙、血肉、灵能四路线；
- 单城发展为多城市网络；

## A9. 视听规范

### A9.1 视觉方向

俯视角 3D、工业功能主义、锈蚀废土、低饱和环境和高识别度功能色。借鉴工业建造和 4X 游戏的信息清晰度，不直接复制具体作品的画面风格。

| 用途 | 色彩 |
|------|------|
| 废土地表 | 深褐、灰绿、暗赭石 |
| 城市建筑 | 枪灰、锈红、旧铜 |
| 正常运行 | 暖黄、橙 |
| 科技遗产 | 青蓝、冷白 |
| 敌人与危险 | 暗红、品红 |
| 生物质 | 污绿 |
| 可交互 | 高亮琥珀 |

规则：

- 建筑优先依靠轮廓区分；
- 运行、缺料、堵塞、停机状态可见；
- 敌人按类型形成体型梯度；
- 玩家与敌人不共用主色；
- 危险同时使用颜色、形状和动画；
- 特效与主体分层，不把烟雾和光效画死在主体图片中。
- 地形远景优先使用低频综合色块与清楚的色相/明度家族，不能让高频写实纹理淹没路线、资源、建筑和危险信息；
- 地形中景边界柔和但必须可辨，特殊 Traversal、深水岸线、废墟与悬崖接缝需要比普通装饰更高的规则可读性；
- 地形近景才展示裂纹、沙砾、污染、水面和材料细节，细节不得形成明显重复图案或把七类地貌重新拉回同一种棕色；
- 地图、资源标记、建造/物流/危险覆盖层相互独立，任何视觉层都不得成为玩法或存档真值。
- 建筑逻辑 footprint 与表现尺度分离：建筑保持配置化占地、旋转和碰撞规则，表现层按 Ground/Inner cell size、建筑类别和状态计算统一高度、退让与轮廓；InnerCity 的三个轴都必须随 `.32` 格尺寸缩放。
- 炮塔由建筑表现层提供低矮基础座、防御表现层提供武器上层，不得再把完整通用建筑与炮塔结构叠在同一格。
- 世界标记按目标屏幕像素与地面格屏幕相对高度分级；正式 UI 图标使用统一语义尺寸档位。两者只负责表现，不改变节点、库存、建筑或输入真值。
- `IDEA-0023` 的 F6 图像子阶段允许把尚无正式三维模型且拥有权威世界坐标的单位小队、地点与运输先表现为面向镜头的透明贴图/公告板；没有独立世界坐标真值的角色先使用政务面板正式头像，不伪造世界位置。图片只承载主体轮廓，运行时配置拥有缩放、锚点、偏移和排序；稳定视觉 ID、缺图回退与玩法对象 ID 分离，确保以后替换模型不改军队、世界、角色、存档或输入真值。军队、世界和政务面板可使用无文字的正式 UI 部件与状态徽记，但名称、数值、状态和按钮必须保持实时数据驱动。

`IDEA-0023` 当前实现记录：上述图像子阶段已经以 20 张正式透明图、140 项统一视觉目录和七类 SpriteAtlas 接入正式 3D；军队页显示四单位，世界层使用小队/次城/前哨/运输公告板，政务页显示三角色头像，M/N/P 共用正式框体、页签选中反馈和守卫、跟随、远征、撤退、运输、通信、忠诚、救援八项运行时徽记。完整自动化、项目质量门和三项现役构建已通过，但人物风格、比例、遮挡和信息密度仍待用户试玩，真实 Windows 验收仍未完成；模型、动画、VFX 与 SFX 继续未实现。

## A15. 已知不足与后续验证

1. 核心移动是否比固定建城有趣，必须试玩验证；
2. 收起时建筑和资源损失强度尚需平衡；
3. 生产、塔防和领袖操作可能造成认知过载；
4. 固定骨架与局部随机的重玩价值有限；
5. 三条命轨强度可能不平衡；
6. 坚守与撤离可能存在明显最优解；
7. AI 生成美术的一致性和商用授权需要持续管理；
8. 两周周期最容易低估 Unity 集成和 Bug 修复；
9. 世界观完整，但首版人物情感抓手仍依赖岑烬单一角色；
10. 正式版“持久世界”和“肉鸽”的关系尚未完全定义；
11. 多城市、外交、政治、四路线、多星球同时存在，正式版长期范围风险极高；
12. A 卷数值是测试基线，不能未经试玩直接视为最终平衡。
13. 正式开放 Mod 后会形成长期 API、存档和兼容维护成本，不能在核心玩法未稳定时承诺脚本 Mod。

展开、收起、建造、完整拆除和维修的表内时间均为基础时长，实际规则时长均以“基础时长 ÷ 城市生产力倍率”计算；快速拆除和遗弃为立即执行，不应用时长倍率。

展开基础时间为 `5` 秒，收起基础时间为 `8` 秒。展开或收起中取消会返回转换前稳定状态并丢失本次转换进度。首个教学波以第一名敌人实际生成作为战斗开始，以存活敌人数归零作为战斗结束；战斗状态下收起推进速度为正常值的 `70%`，即每步先按城市生产力计算正常规则进度，再乘 `0.7`，预警阶段不触发该惩罚。

撤离清单预览随权威战斗状态更新；玩家确认一个处理批次时，为该批次冻结和平或战斗处置上下文和正式城市生产力，队列中的退款比例与基础耗时不因随后敌人死亡而改变。仓储内容和容量不冻结：每项提交前必须重新执行原子容量预检，失败时不得移除建筑或丢失资源，原批次上下文、工作项和未提交撤离锁继续保留。玩家可用 `E` 把城市网络物资移入背包腾出容量，再对原项目重检；容量失败不得自动重建为新的和平批次。

两座安全矿站约 12 分钟耗尽，形成中段迁移压力；结晶裂谷支持 Boss 前持续扩产。资源枯竭后矿站停止工作并显示“矿脉已枯竭”。

生产周期与物流事务规则：

- 每个确定性物流步先按稳定建筑实例 ID 尝试把既有内部输出卸入城市，再从城市库存补足内部输入，最后推进生产；生产周期只从内部输入库存一次性取得完整输入批次，不直接跨过缓存扣城市库存；不足时不开始，也不部分扣除；
- 冶炼与装配在周期完成时一次性产生完整输出并先写入内部输出库存，本物流步新产物等待下一物流步再尝试卸入城市；任一目标容量不足时不得吞掉或截断单个配方批次；采矿站不在周期开始时扣减矿脉，只在周期完成时通过 `Harvest` 原子取得产物并扣减节点储量；
- 建筑脱离物流后保留全部内部输入、已预留批次、进度和输出。已开始周期可完成，后续周期只能使用内部输入；重新进入范围后恢复统一城市库存访问；
- 采矿站读取 `WorldMapModel` 的资源类型与剩余储量真值，每次周期完成时调用既有 `Harvest` 原子扣减对应节点储量并取得产物；铁矿、能晶和石料节点只能产出各自对应资源；不得复制资源节点兼容性或放置合法性判断；seed `8128` 必须在既有 `32×24` 内容区确定性提供至少一个可到达的石料节点，`IDEA-0006` 新增外圈仍保持无资源；
- 全部 `15` 种既有资源使用同一正式图标目录。世界资源节点、资源状态栏、背包、合成、仓库、科技成本和建造成本只引用资源稳定 ID 获取图标与名称；世界节点额外显示 `WorldMapModel` 的剩余储量，不创建第二套资源类型或储量真值；缺少正式美术时使用清晰、可替换且有稳定映射的占位图标；
- 每座仓库拥有独立共享库存与可选资源过滤，固定总容量 `150`。物流入库和玩家转移都必须先通过过滤与剩余总空间；过滤切换、跨城市核心/仓库/背包转移和自动物流均采用可回滚原子事务。资源总览和生产访问通过统一聚合边界读取城市核心与当前可访问仓库，不得由 UI 重算、复制仓库内容或把共享空位按每种资源重复计算；
- 建筑运行详情公开周期进度、输入/输出库存、城市物流连接和一个首要停工原因。优先级为玩家暂停 → 矿脉已枯竭 → 输出已满 → 缺少输入；仅当缺少的输入本可从城市取得但物流断开时，显示“不在物流范围”；
- 玩家背包、城市库存和建筑内部库存之间的显式转移允许目标容量部分接收：先计算实际可接收量，再只对该实际量执行原子扣除与加入；实际量为零则完全不发生。快速转移不得绕过访问资格、容量或堆叠上限。建筑库存访问资格由当前直接控制目标判断：控制城市或已招募领袖时，目标到建筑 footprint 边缘距离必须不大于 2 格；资格绑定受控目标，不绑定建筑自身。城市库存则在控制城市时始终可访问，控制领袖时仅在领袖距城市核心不大于 2 格时可访问。

自动配方与应急手工配方进入同一正式配方目录，但必须是不同稳定 ID、不同数值的独立条目；研究解锁和 UI 引用目录条目，不得复制配方数值或把自动配方当成手工配方。

首版机器配方稳定 ID 为：采矿 `core.production.extract-node-resource`、冶炼 `core.production.smelt-alloy`、装配 `core.production.assemble-ammunition`。上述 `3/6/6` 秒是 3D 首版最终有效周期，不叠加 legacy 2D 历史规则中的 `CityOperationalRules.FortressProductionMultiplier`；城市形态只通过现有建筑运行资格与物流连接影响本轮生产。未来若增加生产倍率，必须另行批准并进入正式配置。

`IDEA-0016` 把正式科技树目标总量确定为 `43` 个全显示节点。六节点表仍是当前 3D 可玩 release profile 的已批准数值基线；除这六项已有定义外，`43` 节点的逐项名称、稳定 ID、成本、时间、效果和解锁对象必须由后续批准的可执行设计规格给出，本节不依据 B 卷示例擅自补齐或改写。正式配置至少为每个节点提供：稳定研究 ID、本地化名称键、所属路线、层级与确定性目录顺序、前置 ID 数组、成本数组、研究时长、效果引用、可研究/预览规则和二维图标 ID。四路线节点共存；桥节点的前置数组必须同时包含两条路线所需节点，运行时只读取这一份配置，不在界面另写一套连接或解锁判断。

研究运行时规则：

- `T` 打开科技树；界面读取科技目录与研究模型，不持有解锁真值；
- 同时只允许一个研究任务，首版不设研究队列；开始和推进都要求至少一座已完成、归玩家所有且未进入撤离锁定的研究站；失去最后一座合格研究站只暂停，不取消、不退款，恢复后继续；锁定节点必须显示缺失前置、资源或研究站条件；
- 研究任务在堡垒态以 `100%`、移动/展开中/收起中以 `50%` 推进；战术暂停和系统暂停冻结规则时间；
- 在当前六节点 release profile 中，六个节点继续全部可见：废料加工根节点已解锁，基础冶金与弹药装配可研究且完成后立即解锁对应生产与应急合成；`IDEA-0013` 将自动防御改为 `Researchable`，继续使用前置弹药装配、`12` 合金 + `10` 生物质和 `35` 秒，完成后解锁机枪塔；加固结构与遗产解析仍为 `PreviewOnly`，不可启动且不接入效果；切换到 `IDEA-0016` 的正式目录投影后则必须全量显示 `43` 个节点，不得继续用六节点裁剪冒充完整树；
- 正式科技树自下向上排布并向上分叉；界面支持拖动、缩放、搜索、路线筛选和状态筛选，桥节点同时绘出两条前置连接。打开时依据配置层级和稳定目录顺序定位最新可研究节点；进行中节点另有明确的一键定位入口。筛选、相机位置、缩放值和搜索词均为表现状态，不进入研究模型；
- 研究资源、完成状态与进行中剩余时间继续由统一研究模型持有；`IDEA-0015` 的 schema `31` 保存科技稳定 ID 与剩余时间，研究站资格、城市模式倍率和界面投影在恢复后重算。`IDEA-0016` 保持 schema `31` 不变；若实施证明必须保存现有字段无法表达的新规则真值，必须先单独提交 schema 升级申请，获批前不得修改版本号或写入新格式。

`IDEA-0016` 的二维表现遵循同一资产契约和人工选型流程：

- 二维资产分为六大类：**UI、物品、科技、建筑、人物、世界标记**。资源与路线材料归入物品类，地图资源浮标和地点提示归入世界标记类；不得为同一语义在不同界面建立平行资产；
- 每一类开始生成前，必须先形成简短制作简介，说明该类的内容范围、世界观依据、对象来源与玩法用途，以及透明背景、轮廓识别、留白、安全区、缩放可读性等视觉约束；简介确认后才进入该类风格样图生成；
- 六大类分别提供 `5` 张具有代表性的透明背景风格样图供用户人工选择，即总共六组、每组五张。五张用于比较该类别的候选画法，不是要求每一个正式资产各制作五个版本；
- 每一类的风格由用户分别确认。某类确认后，该类目录中的每个正式资产只制作一张正式版本；同类资产必须统一画法、轮廓语言、光影和留白，跨类别需要在世界观、色彩层级和识别体系上协调，但允许 UI、人物、建筑等类别采用适合自身用途的不同画法；
- 原“`10` 张透明通用样图”方案及其产物正式废弃，不作为参考基准、占位图、源文件或正式资产进入项目、质量目录和可复用目录；
- 所有正式二维资产通过稳定视觉资产 ID 映射到统一目录，运行时界面不得直接依赖临时文件名或散落路径。图标与标记主画布继续统一采用 `1:1` 比例和透明背景，并在导入与界面缩放时保持宽高比；同类资产使用统一安全区、像素密度和留白规则，具体导出尺寸由后续美术制作规格确定；
- 用户确认某类风格后才允许该类批量生产，并把确认结果、稳定 ID 映射和可替换源文件登记到正式质量目录与可复用项目目录。节点状态、锁定蒙版、选中框和连线由界面层表达，不烘焙进基础图标。

### A16.8 Boss 规格

**阶段一：100%-70%**

- 每 12 秒召唤 2 个啃噬者；
- 每 10 秒使用一次地面冲击，预警 1.5 秒，造成 60 伤害；
- 缓慢接近城市核心。

**阶段二：70%-40%**

- 获得 600 点结晶护盾；
- 护盾存在时本体物理减伤提高至 50%；
- 召唤 3 个啸叫者；
- 每 14 秒制造持续 6 秒的结晶危险区。

**阶段三：40%-0%**

- 移速提高 40%；
- 每 15 秒向城市核心进行一次冲锋，预警 2 秒；
- 每 10 秒召唤 3 个啃噬者；
- 不再恢复结晶护盾。

撤离路线在 Boss 战开始后开放。Boss 追踪移动城市，但不会穿越预设结晶障碍；玩家可以利用地图地形争取重新展开时间。

### A17.2 第 4 天核心门

第 4 天结束必须亲自连续玩灰盒核心闭环至少 20 分钟，并回答：

- 移动是否具有操作价值，而不只是赶路；
- 展开位置是否影响生产和防御；
- 弹药瓶颈是否清晰；
- 收起是否产生紧张决策；
- 城市碾压是否有爽感但不过强。

如果三项以上答案是否定的，第 5 天不增加新功能，优先修正核心闭环。

### A17.3 功能冻结

第 10 天起：

- 禁止增加新资源、建筑、敌人、命轨和系统；
- 只允许修复、调数值、替换素材和改善反馈；
- 任何新想法进入正式版待办，不直接进入首版；
- 阻断流程问题优先于画面细节；
- 打包版本问题优先于编辑器专用体验。

### A17.4 AI 任务验收

每个 AI 任务必须：

- 对应一个可观察的玩家价值；
- 明确只能修改的目录或系统；
- 提供数据配置示例；
- 提供正常和边界测试步骤；
- 说明存档兼容影响；
- 说明新增扩展点的当前调用者；
- 由开发者在 Unity 场景和打包版本中亲自验收。

AI 生成代码不得因“未来可能用到”自行引入 ECS、大型依赖注入框架、联网框架或完整多城架构。

## A18. 试玩验证方案

### A18.1 测试轮次

| 轮次 | 时间 | 样本 | 目的 |
|------|------|------|------|
| R0 自测 | 每日 | 开发者 | 功能正确、核心节奏、明显 Bug |
| R1 灰盒 | 第 7 天 | 3 名未参与设计者 | 引导、核心循环理解、首次流失点 |
| R2 内容版 | 第 11 天 | 5-8 名目标玩家 | 节奏、数值、命轨、Boss 与叙事 |
| R3 回归 | 第 13 天 | 开发者＋2 名复测者 | 修复验证、存档、性能、完整构建 |

测试者优先选择：

- 1/3 熟悉工厂或塔防；
- 1/3 普通 PC 游戏玩家；
- 1/3 对复杂系统不熟悉的玩家。

### A18.2 观察记录

测试过程中不主动教学，只记录：

- 第一次停顿超过 10 秒的位置；
- 第一次打开错误界面的位置；
- 是否知道当前目标；
- 是否理解建筑缺料；
- 是否注意到人口和生产力；
- 是否查看关注度原因；
- 第一次防线失败的原因；
- Boss 阶段是否考虑收起；
- 命轨是否实际改变行为；
- 主动表达兴奋、困惑或无聊的位置；
- 每幕实际完成时间；
- 崩溃、卡死、存档和严重性能问题。

### A18.3 事件记录

首版使用本地测试日志，不需要联网分析服务。至少记录：

```text
run_start
fate_selected
city_first_move
city_expand_start / complete
building_placed / destroyed / recycled
production_blocked
tech_started / completed
attention_changed / threshold_triggered
leader_choice
wave_started / completed
city_pack_start / complete
boss_phase_changed / defeated
checkpoint_loaded
player_failed
demo_completed
```

每条记录包含运行 ID、版本号、游戏时间、事件参数和当前关键资源。

### A18.4 访谈问题

试玩后按顺序提问，不提前透露标准答案：

1. 你觉得这个游戏最特别的地方是什么？
2. 你刚才主要在解决什么问题？
3. 哪个时刻最有成就感？
4. 哪个时刻最困惑或最无聊？
5. 你为什么选择坚守或撤离？
6. 你的命轨改变了哪些做法？
7. 关注度在你看来代表什么？
8. 如果继续玩，你最想解锁什么？
9. 哪个系统你认为可以删除？
10. 你愿意再次游玩吗？为什么？

### A18.5 决策阈值

| 现象 | 处理 |
|------|------|
| 超过 20% 测试者 1 分钟内不会移动 | 重做开局镜头、提示和输入反馈 |
| 超过 20% 在 8 分钟前无法展开 | 缩短探索、强化目标标记 |
| 超过 30% 不懂弹药瓶颈 | 重做建筑状态、资源流向与提示 |
| 超过 50% 不注意人口生产力 | 提高效果或减少首版曝光权重 |
| 超过 70% Boss 选择同一路线 | 调整坚守/撤离成本，消除明显最优解 |
| 超过 30% 因缺弹药首次失败 | 增加初始弹药或延后第一轮压力 |
| 超过 20% 在第 15-25 分钟表达无聊 | 压缩生产等待或提前领袖事件 |
| 多数玩家说不出“移动城市” | 核心定位失败，暂停外围内容开发 |

### A18.6 版本记录模板

```text
版本：
测试日期与样本：
观察到的问题：
证据：
设计假设：
修改内容：
预期影响：
回归结果：
是否保留：
```

作品集至少保留一个完整的“问题→证据→修改→复测”案例。

## A19. 产品定位与竞品差异

### A19.1 定位表达

首版对外类型描述：

> 移动基地 × 自动化生产 × 塔防经营 × 规则选择

首版不将“多星球文明”“完整肉鸽”“割草”作为已实现卖点。这些只能作为正式版方向，避免玩家和面试官产生错误预期。

### A19.2 用户需求

| 用户需求 | 本作回应 |
|----------|----------|
| 建造系统能产生可观察结果 | 生产链直接供给炮塔弹药 |
| 防守不能只有堆数值 | 选址、物流、领袖、碾压与撤离共同决定结果 |
| 基地经营不能长期静止 | 资源枯竭和关注度推动迁移 |
| 随机选择需要改变玩法 | 命轨改变布局、经济或时间规则 |
| 世界观需要由玩法表达 | 关注度和针对性攻击表现“被观察” |

### A19.3 竞品功能对照

| 作品 | 主要借鉴 | 本作不照搬 | 本作差异 |
|------|----------|------------|----------|
| Mindustry | 生产直接服务防御、资源瓶颈可视 | 不在首版制作复杂传送带网络 | 整座城市可移动并主动撤离 |
| Thronefall | 紧凑的建造与战斗节奏 | 不采用严格昼夜两阶段 | 压力由关注度与玩家行为触发 |
| Factorio | 工业可读性、自动化反馈 | 不追求首版超大工厂和物流复杂度 | 生产线随移动城市承担迁移风险 |
| 戴森球计划 | 建造分类、配方可读性、连续规划和蓝图效率 | 不复制具体界面布局和星际生产尺度 | 内城、地面和前哨具有不同建设条件 |
| 群星 | 多目标受袭通知和可点击定位 | 不采用暂停驱动的纯宏观战斗 | 警报服务于实时城市、角色与前哨响应 |
| 吸血鬼幸存者 | 低门槛战斗反馈和规则级构筑感 | 不把角色自动攻击割草作为唯一玩法 | 命轨同时作用于城市经营与风险 |
| 文明 6 | 文明成长、多城愿景和战争迷雾的信息分层 | 不在首版实现回合制宏观管理 | 以实时城市生存验证文明起点 |
| RimWorld | 角色事件和涌现叙事 | 不在首版实现复杂人物模拟 | 固定领袖服务于核心流程抉择 |

### A19.4 核心差异化验证

差异化不能只写在文档中，必须通过试玩满足：

- 玩家会因为生产与关注度主动改变城市位置；
- 坚守和撤离不是剧情按钮，而是由当前布局与库存决定；
- 命轨会导致不同的建造或风险选择；
- 玩家在不知道完整世界观时，也能从系统行为感到“被观察”。

若多数玩家只将其描述为“普通塔防加一个会移动的基地”，说明核心差异尚未成立。

## A20. Mod-ready 与内容扩展设计

### A20.1 当前目标

首版目标是 **Mod-ready**，不是 **Mod-supported**。

| 能力 | 首版目标 |
|------|----------|
| 开发者在 Unity 内增加内容 | D1-实装 |
| 玩家编辑外部数据增加内容 | 正式版早期 |
| 玩家加载图片、音频、预制体 | 正式版中期 |
| Steam Workshop | 正式版中期 |
| Lua 等受限脚本 Mod | 核心玩法稳定后评估 |
| 任意 C# DLL 或系统级代码 Mod | 不提供官方支持 |

首版不开发 Mod 浏览器、加载器、依赖管理、创意工坊和脚本运行环境。首版只保证未来加入这些能力时，不必重做全部内容 ID、存档和文本系统。

### A20.2 稳定 ID 规范

所有内容 ID 使用：

```text
命名空间.类型.名称
```

核心内容示例：

```text
core.resource.iron
core.resource.alloy
core.building.machine_gun_tower
core.enemy.devourer
core.tech.basic_metallurgy
core.fate.pocket_universe
core.event.leader_rescue
```

未来 Mod 内容示例：

```text
baiyan.expansion1.building.railgun_tower
author.mod.mod_name.enemy.custom_beast
```

规则：

- 仅允许小写英文字母、数字和下划线；
- 至少由三段组成；
- ID 发布后不因改名、翻译或美术调整而改变；
- ID 废弃时通过迁移映射指向新 ID，不能直接复用给其他内容；
- 重复 ID、未知引用和循环依赖必须在启动校验阶段报告；
- 核心命名空间 `core` 只允许官方内容使用。

### A20.3 内容注册表

所有内容通过唯一 `ContentCatalog` 注册，而不是由系统分别扫描文件夹。

每条注册记录至少包含：

```text
StableId
ContentType
ContentSource
SchemaVersion
Definition
AssetAddress
LocalizationPrefix
```

首版 `ContentSource` 固定为：

```text
SourceId: core.content.demo
Version: 1.0.0
```

未来 Mod 使用自己的来源和版本。加载顺序为核心内容→官方扩展→用户 Mod；默认禁止静默覆盖相同 ID。需要覆盖时，Mod 必须在清单中明确声明目标和兼容版本。

### A20.4 本地化 Key

所有显示文本使用 Key：

```text
ui.action.build
ui.status.production_blocked
building.machine_gun_tower.name
building.machine_gun_tower.description
event.leader_rescue.choice_now
event.leader_rescue.choice_delay
```

首版只提供简体中文表，但数据结构支持多个语言表。缺失 Key 时：

1. 开发构建显示 `[missing:key]`；
2. 发布构建回退到简体中文；
3. 同时写入错误日志；
4. 不允许直接显示空字符串。

### A20.5 Mod 分阶段路线

**阶段 D1：内部内容扩展**

- ScriptableObject 配置；
- 命名空间 ID；
- 内容注册和校验；
- 本地化 Key；
- 版本化存档；
- 不扫描外部 Mods 目录。

**正式版早期：数据 Mod**

```text
Mods/
└─ ExampleMod/
   ├─ manifest.json
   ├─ resources.json
   ├─ buildings.json
   ├─ enemies.json
   ├─ tech.json
   └─ localization/
```

`manifest.json` 至少包含：

```json
{
  "id": "author.mod.mod_name",
  "name": "Example Mod",
  "version": "1.0.0",
  "gameVersion": ">=0.4.0 <0.5.0",
  "dependencies": [],
  "loadAfter": [],
  "contentSchema": 1
}
```

**正式版中期：资产与分发**

- Addressables 或受控 AssetBundle；
- Mod 管理界面；
- 启用、禁用、排序和错误报告；
- Steam Workshop；
- 存档记录启用的 Mod 和版本；
- 安全模式启动。

**脚本 Mod**

只有当数据 Mod 无法满足主要创作需求时再评估。优先采用受限制事件 API 和沙箱脚本，不加载任意外部 C# DLL。

### A20.6 Mod 存档行为

- 存档记录游戏版本、存档结构版本、内容源和版本列表；
- 未知建筑加载为“缺失内容占位体”，保留位置、占格和原始 ID，但停止生产；
- 未知资源保存在孤立资源表中，重新启用 Mod 后恢复；
- 未知科技和事件状态保留原始 ID，不自动视为完成；
- 禁用 Mod 前提示该存档依赖的内容；
- 安全模式允许忽略外部内容并生成新的恢复存档，不覆盖原存档。

## A21. 更新兼容与开发治理

### A21.1 版本策略

使用语义化版本：

```text
主版本.次版本.修订版本
```

- 修订版本：Bug 和数值修正，不破坏存档；
- 次版本：增加兼容内容，允许存档迁移；
- 主版本：规则或数据结构大幅变化，可以声明不兼容，但必须保留旧版分支或导出方案。

每个存档包含：

```text
gameVersion
saveSchemaVersion
contentSources
createdAt
updatedAt
```

本节与 `Docs/06-User-Feedback-and-Change-Control-ZH.md` 的 `IDEA-0015` 双向引用：本节定义正式产品边界，变更记录维护审批、实现与验证状态。schema `31` 是正式 3D 首版存档；首版只有一个进度槽，自动检查点与“保存并退出”写入同一槽，重开从该槽恢复。当前实现先把完整内容写入同目录 `.tmp`，刷新并复读解码、校验；已有有效主档先更新为经过同样验证的 `.bak`，再原子替换主档。主档无效时可回退 `.bak`，保存失败时保留上一份有效主档和备份，并显示可理解中文结果。

保存边界：

- 保存城市位置、目的地、形态、转换剩余和人口，世界 seed 与资源节点余量，稳定建筑实例及其施工、方向、内外城和矿点绑定，城市核心与仓库内容和过滤，生产内部库存、预留、进度和玩家暂停，背包、合成队列、科技、教学敌袭与防御状态，以及已确认撤离批次；活动转换、战斗和阻塞中的已确认撤离必须可恢复；
- 建筑网格、自动驾驶路径、物流连接与聚合容量、生产停工原因、研究站资格、炮塔目标、撤离容量缺口和所有只读投影，在加载后由保存的权威事实重算；
- 不保存面板开关、选中与悬停、蓝图预览、短时提示与资源流、表现对象、观察快照及其 revision/hash、事件订阅、开发夹具或开发时间倍率。

### A21.2 存档迁移

- 每次结构变化新增单向迁移函数，例如 `V1→V2`；
- 不直接修改旧迁移逻辑；
- 迁移前自动备份；
- 迁移失败保留原文件并显示可理解错误；
- 官方 ID 改名必须维护旧→新映射；
- 至少保留当前和上一正式版本的存档回归样本。
- schema `1–30` 继续由旧 2D 读取路径兼容和回归，不得静默转换为 schema `31`、覆盖原档，或把旧场景状态冒充正式 3D 状态；
- schema `31` 的实现现已覆盖保存与加载、活动转换、战斗、撤离批次、自动检查点、原子写与回归样本，当前为“已实现待验证”；实现 HEAD `a8f30af` 的日常 EditMode `2069/2069`、完整 PlayMode `127/127`、项目质量门、四个退役前正式构建和正式验证记录均已通过。独立 Task 14 已退役 `FormalPrototype`、47 个只服务 legacy 2D 的运行时脚本（共 51 个 `MonoBehaviour` 类型）及 legacy build 入口，当前只保留正式 3D 场景和 Windows Release 3D、Windows Development 3D、macOS universal 3D 三类构建；退役后的聚焦 EditMode `317/317`、日常完整 EditMode `2039/2039`、完整 PlayMode `77/77`、项目质量门、三项构建、官方文档生成/校验和正式验证记录均已通过。共享纯规则、稳定 ID、schema `1–30` decoder、固定 fixtures 和旧档中文识别继续保留。用户人工试玩与真实 Windows 10/11 的视觉、GPU、显存和内存验收仍未完成。
- `IDEA-0017` 已实现 schema `32`，只为通用塔、十波战役、建筑生命和完整会话统计增加明确持久字段。当前 codec、validator、防御适配器和 DTO 已覆盖 schema `32` 完整往返；schema `31` 通过单向迁移继续读取，并保持既有城市、库存、生产、研究、防御和撤离语义，无法追溯的旧局统计显式标记为部分数据。schema `1–30` 身份没有被重写，UI、对象池和表现缓存仍不入档。此状态为自动化通过待人工验证。

### A21.3 AI 架构治理

项目只允许存在一套：

- 内容注册表；
- 库存；
-事件总线；
- 游戏时钟；
- 存档入口；
- 本地化入口；
- 输入动作表。

AI 任务开始前必须搜索现有接口，不得新建同义系统。新增跨系统抽象必须同时说明：

- 当前调用者；
- 玩家价值；
- 为什么已有接口不能满足；
- 测试；
- 存档影响；
- 删除或替代的旧接口。

关键架构决策记录在 `Assets/_Project/Docs/ArchitectureDecisions.md`，每条包含背景、选择、替代方案、后果和日期。

### A21.4 Windows 实机验收

虽然开发设备可以是 macOS，但每个候选发布版本必须在真实 Windows 设备验证：

- 中文字体和缺字；
- Windows 路径与存档权限；
- DPI、窗口、全屏和多分辨率；
- 键鼠焦点和输入法；
- 解压、首次启动和退出保存；
- 杀毒软件误报；
- 打包资源引用；
- 30-60 分钟性能和内存；
- 无开发者本机绝对路径泄漏。

没有 Windows 实机结果的构建不能标记为公开发布候选版。

## 一、世界背景

### 1.1 核心世界观：循环纪元

#### 1.1.1 前代：星海人类联邦

在入侵者降临之前，这个世界的统治者是 **星海人类联邦**（Starsea Human Federation）——一支纯粹的人类文明。他们在漫长的发展中走过了多条路线（科技、修仙、灵能、血肉），最终抵达了**九级巅峰**，开始向十级（神级文明）发起冲击。

"升维"——将整个文明从低维物理宇宙提升到更高维度的存在形态——需要**全路径统合**。科技、灵能、修仙、血肉：四条路线必须在同一个文明体内实现真正的融合，而非简单的混搭。星海联邦虽然在多路线上有卓越成就，但他们终究是以人类的框架去理解每一条路线——修仙被当作"灵气工程学"，血肉被当作"生物改造技术"，灵能被当作"意识科学"。他们**没有真正成为**每条路线的信徒，只是用人类的视角在模仿。

**升维失败**。十级的门槛反弹，世界法则大面积破碎——物理常数开始漂移、时间在某些区域静止、生物在另一些区域失控变异。这就是"怪物"的起源：它们是被破碎法则扭曲的本土生物，是这个世界的**免疫反应**。

联邦意识到失败不可逆。在缓慢崩解的过程中，他们用最后的力量做了两件事：

1. **"时流观测"**——联邦在九级巅峰时已经掌握了概率预测技术。不是自由的时间旅行（那是十级的领域），而是看到未来时间线的"概率簇"。他们看到了三条线：
   - 自己的毁灭（确定）
   - 入侵者的降临（确定）
   - 一个“白点”——在遥远概率分支中，有一支**本世界诞生的文明**，在一个来自更高维度的外部意识的帮助下，会在未来完成升维（模糊但存在）

2. **赌在白点上**——联邦没有选择与入侵者正面对抗（对抗不在那条通往白点的路径上），而是将全部残余力量注入**遗产系统**：编码到世界法则深处、融入本世界文明的血脉、设计为自适应隐形和阶梯式释放、隐藏到入侵者找不到的层面。

#### 1.1.2 入侵者："监察者"的寄生

升维失败引发的时空波动像一道信号，跨越星系团传到了 **"监察者"**——一个八级巅峰的寄生种族。它们降临这个破碎的世界、寄生、掠夺、开始研究。

监察者的核心目标：**找到并控制星海联邦留下的遗产**（九级巅峰产物，监察者离九级还差最后一步）。遗产绑定在世界本土文明的血脉中——毁灭了就永远找不到。所以监察者不毁灭世界，而是：

- 不断重启文明循环
- 暗中操控世界机制（关注度、标准线、天劫、怪物进化）
- 观察每一次循环中本土文明的发展路线
- 试图破解遗产的锁定机制
- 一旦当前循环的文明发展到可能发现真相，就收割重启

**但遗产是跨循环积累的**。每次循环中被毁灭的文明，其研究路线、失败教训、创新尝试都被遗产默默吸收。研究派从扫描数据中能看到遗产在增长——但他们陷入了囚徒困境（见 1.3.1）。N个循环之后，遗产已经积累了足够的认知，等待那个能承载它的文明——以及那个外部意识——出现。

当前循环中诞生的，就是玩家。

#### 1.1.3 三层世界结构

| 层级 | 构成 | 状态 |
|------|------|------|
| **底层** | 星海人类联邦的废墟 + 之前多个循环中被毁灭文明的叠加遗迹 | 被入侵者掩盖，但遗产跨循环积累中 |
| **中层** | 玩家文明 + 其他AI势力（当前循环的原生文明） | 在循环中挣扎发展，尚未意识到真相 |
| **上层** | "监察者"（八级巅峰入侵者） | 暗中操控循环、压制文明突破、三派内斗 |

### 1.2 星海人类联邦：崩解中的布局

#### 1.2.1 "时流观测"与白点预言

联邦在九级巅峰时掌握的**时流观测**技术（非时间旅行，而是概率簇可视化）揭示了三件事：

1. 十级的门槛——需要全路径的**真正统合**，不是人类的框架去"包容"其他路线，而是每条路线都被**平等地活出来**。联邦做不到——他们太"人类"了
2. 入侵者必然降临——升维失败引发的时空波动会像血在水中扩散一样被远处的掠食者嗅到
3. 一个"白点"——在所有概率分支的尽头，联邦看到了一件无法解释的事：N 个循环之后，**一个来自更高维度的意识**会与一支本土文明建立连接。这个外部变量不在因果链内——时流观测能看到它的"影响痕迹"但看不到它本身。它的出现会让原本必然失败的路径拐弯。联邦无法预测这个高维意识会做什么，只能确定**它出现后，升维概率从零变成了非零**

联邦没有选择对抗。对抗不在通往白点的路径上。他们把每一分残余力量都用来为那个白点铺路——遗产的一切设计，都是为了等到那个外部意识（即**玩家**）降临，为它准备好一套"操作系统"：不用理解，只需操作。

> **打破次元壁**：联邦时流观测预测到的"高维意识"就是屏幕前的玩家。你不是在扮演一个角色——你就是你，一个来自比游戏世界更高维度的真实存在。游戏中前期的叙事暗示这点（遗迹残响提到"不在因果链内的变量""外来的观察者"），后期直接揭示。

#### 1.2.2 遗产的工程设计

联邦的遗产不是一堆蓝图和武器的堆砌。它是一个**文明的种子**——设计为五层保护机制：

| 保护层 | 机制 | 效果 |
|--------|------|------|
| **血脉锁** | 遗产只对本世界出生的文明产生共振响应 | 监察者能看到遗迹的物理存在，但读不出遗产核心数据——它们不是"本地人" |
| **阶梯释放** | 遗产按承载文明的当前等级分层解锁 | 一级文明只看到一级的内容；遗产全貌到玩家接近九级时才完全展现——也防止玩家"噎死" |
| **自适应隐形** | 遗产嵌入世界物理法则底层 | 监察者的扫描工具无法将其与正常物理波动区分开 |
| **跨循环积累** | 每次被重启，遗产吸收该循环文明的创新与失败日志 | N个循环后，遗产数据库已经包含海量的"已证伪路径"和"最近似成功路径" |
| **外部激活锁** | 遗产的"翻译层"需要外部高维指令才能启动 | 前 N-1 个循环，遗产的操作系统越来越完善，但键盘前没人坐。本土文明只能用遗产的"基础功能"（部分科技加成、遗迹感应），永远无法让它全功率运转。直到这一轮——玩家坐下、点击"建造"——遗产才第一次完整响应。监察者研究了几十个循环都没搞明白的遗产全貌，不是因为锁难破解，而是**锁的钥匙不在因果链内** |

> **灵感来源**：阿西莫夫《基地》的"谢顿计划"（文明级数学预测 + 关键节点引导）；《我的模拟长生路》"还真"系统（轮回锚点 + 跨循环信息积累）+ "法不可同修"（每条路线需要真正的专属承载者）

#### 1.2.3 崩解中的遗民：五种存续形态

联邦不同路线、不同地区的人类选择了不同的方式渡过崩解：

| 存续形态 | 描述 | 游戏内互动 |
|----------|------|-----------|
| **数据残响** | 部分人将意识上传至遗产系统，化为AI引导程序。已不是"活着"，但能在关键文明节点主动与玩家沟通（类似《基地》里谢顿的全息录像——"谢顿危机"机制） | 中期解锁遗迹深处的通讯终端后可对话 |
| **深眠者** | 科技路线冷冻休眠者，藏于最深层遗迹中，等待"白点"出现时唤醒。醒来时发现世界已面目全非、自己的文明已成为传说 | 后期可唤醒为特殊顾问/角色加入文明 |
| **融入法则者** | 修仙路线放弃肉身，神识融入物理法则。已无法对话，但表现为世界机制中的"偶然善意"——一次莫名避开的天劫、一个"恰好"出现的逃逸窗口 | 贯穿全程的隐性存在；后期揭示其来源 |
| **变异后裔** | 血肉路线幸存者，肉体崩解中变异，已无人形。在偏远星区的暗处形成独立种族，有自己的文化和语言 | 可作为隐藏势力接触；他们可能视玩家为"背叛肉身的后代"，极度敌视纯粹机械路线 |
| **残响记录** | 预设的加密信息，在文明达到特定里程碑时自动触发。一段全息录像、一段加密文本、一组坐标 | 叙事片段形式推进——但玩家不知道这些残响的线索是否还在当前循环中有效（世界已被篡改） |

#### 1.2.4 留白：联邦刻意未留的东西

联邦在遗产中有意**未留下**某些知识：

- **完整的升维蓝图**——如果直接给后人画好路径，后人会走在联邦设下的框架里。而联邦自己正是因为"框架"太人类化才失败的。升维的最后一步——十级的门槛——必须由后人用自己的方式跨过去
- **监察者的弱点**——联邦知道，如果在遗产中写明"怎么杀监察者"，遗产一旦被监察者破解就会被反利用。他们选择了信任后人：一个能从循环中活到揭露真相的文明，自己一定有能力找到监察者的致命缺陷
- **一段关于"白点"中被看到的那支文明是谁的确认信息**——玩家全程不知道白点中那个人"究竟是不是自己"，只能靠行动去证明。这也是联邦留下的最后考验

### 1.3 外来入侵者（"监察者"）

监察者自称 **"监察者"**。在它们的文明体系里，这个被锁死的循环世界是一个**研究标本**——编号、归档、按周期观察。

#### 1.3.1 基本参数

- **文明等级**：八级巅峰，差一步到九级（空间折叠、预见危险、自由星系团间航行）
- **形态**：有实体的种族；大后期通过剧情揭露真实形态与舰队集群
- **已融入世界机制**：关注度、标准线压制、天劫、怪物自适应进化——背后都是监察者铺设的调控网络
- **核心恐惧**：遗产是九级巅峰产物。监察者离九级还差一步——遗产一旦被完全激活，反噬的可不只是本世界内的监察者驻军，而是它们的**整个文明**
- **囚徒困境**：研究派**知道**遗产在跨循环积累。每次重启循环，遗产数据库就多一层——他们从扫描数据中能看到。但他们陷入了死局：停止循环 = 毁灭世界 = 遗产随世界一起消失 = 永远拿不到九级巅峰的秘密。继续循环 = 遗产继续积累 = 终有一天积累满。这不是一个蠢不蠢的问题，而是一场赛跑——**在遗产积累满之前破解它**。他们选了继续跑，赌自己跑得过。起跑线站在遗产那边

#### 1.3.2 内部三大派系

##### 研究派（主流 / 占多数席位）

- **主张**：维持循环、继续观察。遗产是危险，更是千载难逢的**研究样本**。彻底破解遗产机制之前不能毁灭世界
- **行为**：系统性压制文明（标准线、天劫、怪潮）；对玩家做"极限测试"；偶尔**反向保护玩家**——如果毁灭派要提前灭世破坏数据
- **玩家感知**：感受到的"世界机制"大多来自研究派

##### 毁灭派（少数激进派）

- **主张**：遗产太危险，必须立刻终结。八级文明研究九级巅峰遗产 = 蚂蚁解剖大象。宁可不拿
- **行为**：绕过研究派独走，用超规格手段（陨石、轨道轰炸、局部法则崩溃）。内部的独走给了玩家可乘之机
- **玩家感知**：某些"自然灾害"回头想才意识到有组织在动手

##### 田园派（少数叛变/被同化者）

- **来源**：之前N个循环中，部分监察者只是在**观察和动摇**——目睹文明反复被收割，私下与本世界的数据残响/融入法则者产生微弱交流，但从未出手。它们不敢。但每一次循环都积累一层疑虑。到了这一轮，积累突破了临界点——它们第一次实际行动。这也解释了为何玩家这一轮线索集中涌现：不是每轮都有，就这一轮
- **行为**：暗中留下线索（遗迹中的不明来源信息）、干预机制（微调关注度、抹掉超标记录）、在关键时刻制造"信息雾"帮玩家逃避锁定
- **接触梯度**：
  - 早期：遗迹中的来源不明文字、反常的机制波动
  - 中期：特定遗迹 → 单向加密通讯
  - 后期：直接接触（形态已本土化改变），可结盟——代价是文明可能被同化物质污染，科技路线产生不可预知变异

#### 1.3.3 三派博弈时刻表

| 时刻 | 动态 | 玩家窗口 |
|------|------|---------|
| 接近文明标准线 | 研究派加压 vs 毁灭派抹除 vs 田园派拖延 | 三派僵持 → 额外备战时间 |
| 毁灭派独走 | 研究派封锁，田园派泄露信息 | 从打击中提取"非自然"证据 |
| 发现关键遗迹 | 研究派提高监控，毁灭派准备破罐破摔 | 田园派引导绕开监控 |
| 遗产部分激活 | 研究派恐慌、毁灭派暴怒、田园派看到希望 | 三派内讧 → 监察者效率下降 |
| 大后期真相揭露 | 三派全面分裂 → 监察者内战 | 与田园派结盟，利用内战反击 |

#### 1.3.4 前期入侵者线索

- "自然灾害"有精准规律
- 关注度数值莫名剧烈波动
- AI势力突然改变行为模式（友好伙伴一夜宣战）
- 遗迹入口被异常力量刻意封堵
- 某些研究在接近特定层级时频繁"偶然失败"

#### 1.3.5 压制梯度

- 越远离监控核心，压制越小
- 偏远星球监控密度远低于中心星域
- 关键性突破（文明升阶、遗产激活）时距离无差别——全舰队级响应

## 二、游戏核心机制

### 2.1 命轨（星海联邦的遗产）🌟

#### 2.1.1 本质

**命轨**是星海人类联邦为「白点」（玩家）准备的**规则级能力种子**。它是九级巅峰文明的遗产——差一步就是神级（创造空间、重写物理法则、发现平行宇宙）。

命轨不是数值增益。每一条命轨**改写一条世界规则**——和以撒的结合中 Brimstone 把眼泪变成激光、Mom's Knife 替换攻击方式一样，命轨让你在某些维度上**和所有人玩的不是同一套规则**。

- **开局命轨**：三选一。每局从 24 条命轨池中随机抽取三条。你选择的不是 build，是**你的文明如何作弊**
- **升级命轨**：每条命轨 1-9 级，共 8 次升级。核心数值 = 基础值 × 2^等级。升级方式待定

#### 2.1.2 命轨升级节点（Demo 40 分钟内）

| 等级 | Demo 触发节点 | 时间 |
|------|-------------|------|
| Lv.1 | 开局选择 | 0 min |
| Lv.2 | 首次展开（第三幕） | ~8 min |
| Lv.3 | 首次升阶（第六幕） | ~35 min |
| Lv.4-9 | 后续文明等级 | Demo 后 |

#### 2.1.3 命轨池（24 条，按类别）

每条命轨的格式：**效果 · 代价 · 叙事**

---

**空间系**

| # | 命轨 | 效果 | 代价 | 叙事 |

### 2.2 文明等级系统

玩家**主动选择**升阶。升阶条件通过剧情/事件提示，不公开透明。越高阶越困难，入侵者压制越强。

| 等级 | 名称 | 描述 |
|------|------|------|
| **一级** | 行星文明 | 完全吸收并控制母星能量资源，管理行星表面环境 |
| **二级** | 恒星文明 | 控制并利用恒星能量，对整个星系进行操控 |
| **三级** | 星系文明 | 银河系内自由穿梭，多元能源（暗物质、黑洞等） |
| **四级** | 超星系文明 | 超越星系限制；"降维概念"在此阶段形成 |
| **五级** | 时间文明 | 突破时间限制，自由访问时间轴任意节点 |
| **六至八级** | — | 空间穿越、星系团间航行、操控生物能量、预知规避危险 |
| **九级** | 时空边缘文明 | 超星系团航行、空间折叠技术（飞船小如芥子内有乾坤） |
| **十级** | 神级文明 | 创造空间、发现平行空间、创造新宇宙 |

> 监察者为**八级巅峰接近九级**。玩家从一级开始，开局命轨提供九级巅峰能力种子——理论上监察者压不住你，但种子需要时间成长。

#### 2.2.1 叙事揭示节奏

真相不是到了九级忽然砸下来，而是随着文明升阶层层剥开：

| 等级 | 叙事揭示 | 玩家感知 |
|------|----------|----------|
| **1-2 级** | 世界"不对劲"——自然灾害有规律、关注度莫名波动、遗迹中的记录互相矛盾 | 直觉：我不是第一个住在这里的人 |
| **3-4 级** | 循环存在的证据浮现——不同文明的遗迹叠在同一地层，时间跨度远超正常文明寿命 | 确信：世界在反复重启。有人在操控 |
| **5-6 级** | 确认外部操控者（监察者）的存在 + 发现三派系的痕迹 | 发现敌人有名字、有组织、有分歧 |
| **7-8 级** | 理解遗产本质——为什么你能用多路线 + 联邦白点预言 + 监察者内部分裂 | 明白自己不是侥幸，是被等到的 |
| **9 级** | 一切汇合：遗产全貌解锁 + 田园派正式结盟 + 正面对抗监察者 | 从「被研究」到「主动打」 |

### 2.3 文明发展方向

#### 2.3.1 核心路线

| 路线 | 特征 | 军队形态 | 示例能力 |
|------|------|----------|----------|
| **纯粹科技** | 机械、能量武器、自动化 | 机甲军团、无人机蜂群 | 激光塔、等离子护盾 |
| **灵能** | 精神力量、意识操控 | 灵能战士、心灵操控者 | 精神力场、心灵链接 |
| **血肉飞升** | 生物改造、基因进化 | 变异兽群、生化士兵 | 酸液喷射、再生护甲 |
| **修仙** | 灵气修炼、法宝炼制 | 傀儡道兵、剑修 | 飞剑阵列、符箓阵法 |

#### 2.3.2 路线机制

- **无惩罚混搭**：解锁 ≠ 必须使用。大多数路线自由混搭
- **跨侧融合**：专属科技需要多种路线的前置（机械+修仙 → 灵能机甲）
- **路线可见性**：尚未接触的路线不在普通建造列表中；发现并解锁路线入口后，其建筑与科技正常显示，不阻止自由混搭
- **隐藏科技提示**：拥有多侧前置后出现融合提示；只有线索但尚未满足条件的内容显示为锁定，完全未知内容继续隐藏
- **跨侧促进**：不同侧的前置加速高等科技研究
- **互斥路线**：极少数极端路线互斥
- **参考《我的模拟长生路》"法不可同修"的逆向设计**：玩家的"遗产"恰恰打破了"一条路走到底"的束缚——联邦正是被单一框架限制才失败的

### 2.4 时代演进系统

玩家解锁关键超前科技或升阶时触发**全局统一**的时代演进。

#### 2.4.1 时代类型

玩家行为积累对应**轨道值**（见 4.4），配合科技进度触发时代演进：

| 走向 | 触发条件 | 世界变化 | 掉落物 |
|------|----------|----------|--------|
| **机械飞升** | 异化度 ≥ 40 + 科技路线已研究 ≥ 6 节点 | 赛博废土，怪物机械化 | 芯片、超导材料 |
| **深渊变异** | 变异度 ≥ 40 + 血肉路线已研究 ≥ 6 节点 | 孢子覆盖，巨型变异体 | 生物质 |
| **维度降临** | 灵震度 ≥ 40 +（修仙或灵能路线）已研究 ≥ 6 节点 | 重力异常，时空裂缝 | 虚空物质 |

> 触发时代后，对应轨道 **+10**——时代本身会加速危机进程。

#### 2.4.2 抵抗 vs 适应

每座城市可独立选择：

| 选择 | 代价 | 收益 |
|------|------|------|
| **抵抗时代** | 额外针对性攻击 | 该侧完整研究路径 + 进度 + 材料 + 独特剧情奖励 |
| **适应时代** | 无额外奖励 | 该时代科技研究大幅加速 |

> 复合科技路线可**提前触发**时代。未控制的城市自动**被动适应**（解锁少量基础科技作为生存底线）。

### 2.5 移动城市与多城系统

#### 2.5.1 移动 vs 展开

| 状态 | 优势 | 限制 |
|------|------|------|
| **移动态** | 自由探索、随时撤离、内城轻型施工和维持、研究以 50% 速度连续推进 | 地面施工关闭、重型工业降停、研究效率低于堡垒态 |
| **展开态（堡垒）** | 防御加成、生产加成、大规模研究 | 初始读条（科技缩短 → 最终秒开） |

> 也可永久扎根为固定基地。选择权在玩家。

移动城市拥有与外部世界同场景的有限内城网格。建筑模板标记为内城、地面或两者皆可：生活、维修、轻型加工和部分路线建筑可随城运行；采矿、重型工业和依赖地形的建筑必须部署在地面。城市升级可扩展内城面积，但不能让所有地面工业无代价搬入城市。

住房首阶段标记为内城与地面皆可：移动形态仅允许在内城建造，要塞形态允许在内城或外城建造。当前两种位置使用相同生命值、人口容量和效率，外城实例仍参加统一撤离。未来外城住房计划采用更低生命值和更少人口容量以形成安全与容量取舍，但数值与接入阶段必须另行批准。

- 移动态默认直接控制城市，领袖实际存在于内城并由 AI 执行休息、维修或防守；展开后默认切换为直接控制领袖；
- 默认支持 WASD 直接驾驶，也可在地图上指定目的地自动寻路；
- 普通地形可自由通行，悬崖、深水和大型障碍阻挡，泥地与废墟等地形降低速度；
- 自动驾驶、避险、跨地形能力和路线规划随科技升级；
- 展开需要满足面积、坡度和障碍条件；地形可影响展开速度、防御与生产；
- 展开和收起允许取消，过程中受击会减速、中断或造成额外损伤。
- 城市装甲通常先承受攻击；装甲突破、特殊攻击或敌人登城后，内城建筑才会单独受损。

#### 2.5.2 多城市管理

- **同时运转**：所有城市自主运作（参考文明6）
- **查看切换**：可随时查看已建立通信的城市状态、警报和最后情报
- **直接控制**：一次只直接控制一城；前期切换需领袖亲自前往
- **城主委派**：任命角色/继承人管理
- **自动防御 + 通知**：未控制城市受攻击自动防御，系统通知
- **远程指挥**：科技解锁后允许跨城下达完整命令和直接控制；通信中断时退回委派角色自治
- **领土 + 迷雾**：领土内可见，外需侦察/科技

#### 2.5.3 城市定位与基础设施

- **定位自由**：工业城、军事要塞、修仙圣地、贸易枢纽...由玩家决定
- **面积**：无上限，超过文明标准线吸引大量袭击
- **仓库**：可多建，科技线扩容
- **资源传输**：城市间交通线；运输方式随科技升级（道路→铁路→管道→无人机→传送门）
- **运输安全**：可沿途造塔形成走廊 / 派护卫队 / 绕路 / 后期科技替代
- **自给 vs 分工**：完全由玩家决定

#### 2.5.4 地面建筑与前哨

- 城市物流范围外允许建设，但施工资源必须由角色、城市或运输单位实际送达；
- 脱离城市物流的建筑保留内部库存，并按补给、能源、维护和通信状态分别降效；
- 多座城外建筑可组成前哨，拥有自己的库存、视野、防御、管理角色和物流请求；
- 前哨会被敌人单独侦察和攻击。警报分级显示位置、威胁与预计失守风险，点击后才定位镜头，不强制打断当前操作；
- 城市离开前提供撤离清单，可单体、多选或按类别拆除并回收，或将建筑留作前哨；
- 城市重新进入范围后自动恢复通信和调度，但实体库存仍通过运输流动，不瞬间传送；
- 早期只能远程查看已通信前哨；修改生产、维修和建设需角色到场，后期科技解锁完整远程操作。

### 2.6 领袖 / 英雄系统

#### 2.6.1 角色定位

玩家持续控制**文明**，并通过当前文明领袖作为直接行动角色。领袖是具体、可成长、可受伤和可替换的高战力单体，不是不可失去的玩家本体，也不是只站着提供 buff 的抽象指挥官。

- 可亲自下场（割草/打Boss）
- 可在任意城市间调动；直接控制其他城市前期需旅行前往，远程指挥科技解锁后可跨城接管
- 专精方向取决于个人技能树和天赋
- 基础行为可以交给 AI，玩家可随时主动接管移动、瞄准、闪避与技能

#### 2.6.2 成长体系

| 维度 | 机制 |
|------|------|
| **个人经验** | 战斗独立成长，不依附城市 |
| **外部装备** | 需城市工厂/炼器/研究系统制作 |
| **个人技能树** | 专属天赋树——决定战斗风格 + 管理加成 |
| **天赋** | 每个角色随机生成，不可更改 |

#### 2.6.3 角色类型与城市联动

| 类型 | 在场效果 |
|------|----------|
| **战士型** | 附近炮塔攻速加成（"士气"） |
| **科研型** | 坐镇城市研究速度翻倍；本人脆皮 |
| **修仙型** | 远程为塔附魔；需打坐回复灵力 |
| **经商型** | 贸易收入增加、外交成本降低 |

#### 2.6.4 死亡与继承

- 倒地后进入救援时限；基础时间受伤害类型、环境、体质、装备、医疗科技和文明路线修正，并明确显示剩余时间与主要原因
- 可派其他角色接触并持续救治，也可调动移动城市进入范围，使用医疗设施更快、更安全地救援；救援过程可被攻击或中断
- 成功救援后进入重伤恢复，并可能因延迟、多次倒地或特殊伤害留下永久伤势；不同路线可用义体、生物改造、丹药或灵能治疗缓解
- 超时后永久死亡，遗体和装备留在现场；装备可能损坏、需要回收或被其他势力夺走
- 死亡 → 国家**短暂发展停滞** + 可能叛乱（如果忠诚不够）
- 玩家控制权继续属于文明，不因一名领袖死亡直接结束游戏
- 已培养继承人保留自己的经验、技能、天赋和装备；紧急选举产生的新角色从低成长起步
- **开局无领袖**（初始100人自由状态）：
  - 废土中招募随机角色
  - 人口满1000 → 选举产生首位领袖

### 2.7 继承人与内部政治

#### 2.7.1 继承人

- **独立角色**：自己的天赋、技能树、专精方向
- **上岗前作用**：管理第二城、带队远征
- **培养意义**：避免领袖死后文明从零开始
- **提前指定**：玩家可指定并培养继承人，获得合法性优势但不保证必然接班
- **竞争候选**：高威望、掌军、管理城市或受派系支持的角色可加入竞争

#### 2.7.2 继承过程

- 领袖死亡后由临时议会低效维持城市，玩家仍可处理防御、救援和资源调度；
- 必须在限定时间内完成继承事件；拖延越久，忠诚下降、停滞和叛乱风险越高；
- 长期没有合格继承人时举行紧急选举，从人口中产生能力较弱、政治代价更高的临时领袖；
- 继承方式由文明路线与制度决定，可表现为选举、前任指定、议会推举、宗门推举、意识共鸣、决斗或武力夺权；
- 玩家可强行扶持支持度不足的候选人，但可能触发政变、内战、谈判或政治让步；
- 新领袖不会清空城市、科技和文明进度。其路线倾向通过政策、科研和派系逐渐影响文明，长期改革才可改变既有方向；
- 意识备份等路线专属能力可以支付代价改写正常死亡与继承流程，但必须经过统一事件和存档规则。

#### 2.7.3 叛变与反利用

- 可能叛变（独立意志 + 权力斗争）
- 会带走管理的城市（如果该城忠诚度不够）
- **预警**：忠诚下降、私下囤资源、拒绝命令
- **应对**：镇压 / 安抚 / 先下手
- **反向**：可策反敌人势力的将领/继承人

**克制矩阵（130/100/70 三值体系）**：

| ↓伤害 \ 护甲→ | 轻甲 | 重甲 | 灵能盾 | 生物壳 | 灵力罩 |
|---------------|------|------|--------|--------|--------|
| **物理** | 100 | 70 | 130 | 100 | 100 |
| **能量** | 100 | 130 | 100 | 70 | 130 |
| **灵能** | 100 | 100 | 70 | 130 | 130 |
| **真元** | 100 | 100 | 100 | 130 | 70 |
| **生物** | 100 | 130 | 130 | 70 | 100 |

#### 2.9.5 Buff / Debuff 体系

**通用 Buff**（所有路线共享）：

| Buff | 效果 | 来源 |
|------|------|------|
| 攻击增幅 | 伤害 +N% | 研究站、奇点 |
| 防御加固 | 建筑耐久 +N% | 城墙升级、奇点 |
| 移速提升 | 城市/军队速度 +N% | 道路、奇点 |
| 生产效率 | 采矿/冶炼/研究速度 +N% | 领袖坐镇、奇点 |
| 射程扩展 | 塔/远程单位范围 +N% | 奇点、建筑升级 |
| 再生 | 建筑/军队缓慢自回血 | 血肉增益、奇点 |

**路线专属机制**：

| 路线 | 机制 | 描述 |
|------|------|------|
| **科技** | **过载** | 激活后 5s 内攻速翻倍 + 能量伤害 +30%，结束后过热停火 3s。CD 30s |
| **修仙** | **剑意** | 飞剑命中叠层（上限 20），满层时触发斩杀：层数×5% 最大生命值的真实伤害。斩杀后清零 |
| **血肉** | **感染** | 生物伤害附加感染（持续 2%/s），满 10 层爆发 → 周围 3 格全部获得 5 层 |
| **灵能** | **共鸣** | 灵能命中标记目标（5s），任意被标目标受灵能伤害时全标目标同步承担 30%。上限 10 目标 |

**Buff 来源层级**：

```
奇点选择 ──→ 永久被动 (全局生效)
科技研究 ──→ 可切换 (解锁后手动激活)
领袖技能 ──→ 区域Buff (领袖在场)
丹药/消耗品 ──→ 临时 (有持续时间)
命轨 ──→ 规则破格 (如"过载无过热")
```

**Debuff（敌方可施加）**：瘫痪（建筑停摆）、腐蚀（持续掉血）、冻结（移速骤降）、灵力压制（修仙/灵能减弱）、信号干扰（物流区减半）

### 2.11 开局流程

1. **开局状态**：一座上一循环文明留下的移动城市残骸 + 100个无意中激活了它的幸存者 + 无领袖。城市不是玩家建造的——它是一堆勉强运转的废墟。这 100 人不是管理者，只是栖居其中的流浪者。研究、建造、领袖——这些都是激活城市之后才逐渐学会的
2. **命轨选取**：激活城市的瞬间，遗产响应——弹出命轨三选一。这是遗产第一次等到外部指令，它给出了三条最可能通路
3. **背景**：默认随机（落难军阀遗孤 / 流放科学家 / 流浪修士 /...），也可主动选择
4. **起始位置**：默认随机，可选（安全荒原 vs 资源丰富多怪的辐射区）
5. **领袖获取**：招募 或 人口满1000选举

### 2.12 胜利与失败

| 条件 | 结果 |
|------|------|
| 所有城市被摧毁 | **失败** |
| 世界被毁灭 | **失败** |
| 带领文明离开这个世界 | **伪胜利（坏结局）** ⚠️ |
| 解决世界危机 | **胜利** |
| 完成星海联邦未竟的升维 | **真胜利** |

> ⚠️ **关于「离开世界」**：遗产的血脉锁决定了一件事——遗产绑定的是这个世界，不是这个文明。如果玩家选择逃离、穿越传送门去另一个宇宙，遗产不会跟随。这意味着玩家抛弃了遗产、抛弃了联邦的赌注、也抛弃了「白点」的使命。监察者不会追击——因为他们要的是遗产，不是你这支逃走的文明。世界会在玩家离开后被重启，等待下一个循环、下一个文明、下一个外部意识的降临。**这不是胜利，这是放弃。** 但从玩家的视角，在逃离的那一刻他们不会知道——屏幕只会显示「你的文明存活了下来」，只有通关后回头看，才会发现这其实是循环中的又一次失败

#### 2.14.6 建筑解锁方式

- **科技树解锁**：通用建筑 + 路线基础建筑
- **命轨/奇点解锁**：独特专属建筑
- **探索事件解锁**：遗迹中发现失传建筑图纸
- **条件解锁**：人口达标、击杀 Boss、文明等级等

建造菜单可见性：

- 已解锁建筑正常显示；
- 已获得线索但前置、资源、地形或物流条件不足的建筑显示并置灰，同时说明原因；
- 尚未发现的隐藏建筑和尚未接触的路线建筑不显示；
- 保留多路线自由混搭；解锁路线入口后，该路线建筑进入正常显示与建造流程；
- 唯一特殊建筑通过事件、任务或专门界面建造，不进入普通建造列表。

#### 2.14.7 建筑升级

允许同建筑原地升级（如机枪塔 → 重型机枪塔 → 等离子炮塔），无需拆除重建。

#### 2.14.9 建造、配方与蓝图交互

- 常用快捷栏与完整分类面板并存，支持生产、物流、防御、城市、路线等分类和搜索；

### 3.3 数值框架（阶梯式增长）

#### 3.3.1 怪物与防御塔 DPS 阶梯

#### 3.3.2 资源产出与消耗

> **历史草案提示**：下表不用于首版 Demo。按照本表原数值，一座持续开火的机枪塔实际需要约 12 座采矿站，而非 1 座。首版统一执行 A6.2 的“2 采矿站→2 冶炼厂→1 装配厂→1 机枪塔”基线。

| 建筑 | 产出 | 消耗 |

## 四、世界危机设计

### 4.1 危机全貌

```
表面危机（开局即感知）
    ↓
真实危机（中期通过遗迹/线索逐渐发现）
    ↓
衍生危机（中后期基于玩家选择浮现）
```

### 4.2 表面危机

怪物潮、天劫、资源枯竭、文明标准线压制——监察者调控网络制造的日常威胁。

### 4.3 真实危机

循环纪元——发展过高的文明会被收割。一切灾难背后有规律跟推手。星海联邦的崩解、监察者的寄生、循环的本质——需要在遗迹和线索中拼接。

### 4.4 衍生危机轨道

玩家的路线选择不仅带来收益，也积累**不可逆**的轨道值。每条轨道只升不降（棘轮），与关注度的可逆性形成短期/长期两条压力线：

| 轨道 | 对应行为 | 40 预警信号 | 60 小危机（可逆） | 80 大危机（不可逆） |
|------|---------|------------|------------------|-------------------|
| **异化度** | 攀机械科技 | 工厂偶尔产出「异常零件」 | 流水线短暂停摆，修复后可降回 50 | 矩阵意志觉醒，部分机甲反叛 |
| **灵震度** | 修仙/灵能过深 | 天空极光、灵气读数异常 | 法术有概率失效，调低输出可降回 50 | 灵力波动引高维净化 |
| **变异度** | 血肉飞升极端 | 菌落池脉动、单位外观异常 | 培育单位有概率失控，暂停可降回 50 | 身体被植入「失控武器」标记 |
| **暴露度** | 多城/多星球扩张 | 侦察机在领土边缘频繁出现 | 一座前哨站被精准打击 | 监察者投放「镜像文明」 |

**轨道机制**：
- 每条轨道 0-100，**只升不降**（棘轮法则）
- 40：叙事预警，不产生实际惩罚
- 60：小危机触发，玩家可采取行动降回 50（暂停研究/停止扩张/调低输出）
- 80：大危机触发，不可逆，永久改变游戏局面
- 轨道值来源：每研究一个对应路线科技 +3~5、每建造一个对应路线建筑 +2、触发对应时代 +10

#### 4.4.1 非轨道衍生危机

以下危机不由数值轨道驱动，由玩家具体行为触发：

| 触发行为 | 引发的危机 |
|----------|------------|
| 掠夺前代遗迹 | 前代遗民仇恨积累 → 有组织反攻 |
| 保护/收容遗民 | 隐藏路线：联合前代破解收割；代价是科技树被污染 |
| 龟缩不作为 | 循环收割来得更早更猛烈 |

### 4.5 胜利路径

- 收集资源建造**跨世界传送门/方舟**，带领文明离开
- 利用九级巅峰遗产（命轨 + 奇点积累） + 联合前代遗民 → 正面对抗监察者
- 完成星海联邦未竟的**升维**——带着世界跳出当前物理宇宙
- 联合其他被监察者压制的平行世界文明 → 多世界联手
- 与田园派合作，从内部瓦解监察者
- 其他涌现式路径

## 七、设计原则

1. **玩家自由决定一切**：移动或定居、科技或修仙、扩张或坚守、抵抗或适应
2. **克制是个人开发者最重要的美德**：美术做减法，精力在打击感、数值、叙事
3. **数据驱动**：不把数值写死在代码里
4. **核心循环**："获得 → 被觊觎 → 备战 → 碾压 → 世界升级"
5. **持久世界**：不做局内局外分离
6. **开局外挂**：九级巅峰遗产（命轨 + 奇点） = 不对称优势
7. **三层叙事**：表面危机 → 怀疑异常 → 揭露监察者真相
8. **跨循环视角**：玩家不是第一个挑战者——站在N代前人的尸体上，而这些前人的遗产正在遗产系统中与你对话
