# WasteCity 九条正式命轨池设计规格

## 1. 范围与目标

本规格对应 `IDEA-0028`。它只覆盖九条已经定稿的命轨、每局确定性三选一、六条新增 Lv.1 真实规则、现役 Lv.2 稳定化、关注度坐标锁定和 schema `36`。文明 Lv.3、命轨 Lv.3–9 与十五条草案不进入本阶段。

## 2. 不可改变的兼容语义

- `IDEA-0020` 已发布的选择 Lv.1、文明 `1→2` 升 Lv.2 保持不变。
- schema `35` 的固定三候选、候选顺序、已选 ID、等级、袖珍宇宙、虚空债和回溯锚点状态原样迁移。
- 回溯锚点继续每次成功读取增加 `12` 关注度；虚空债只允许施工透支。
- 现有地图 `64×48`、seed `8128`、24 个资源节点、44 科技、49 条边、6 桥及 schema `1–30` legacy 身份不改变。

## 3. 内容目录与抽取

正式池按稳定顺序登记：袖珍宇宙、量子纠缠、空间模板、回溯锚点、局部时加、预知迟滞、虚空债、因果透明、虚空宝箱。稳定 ID 复用历史字符串，但正式运行时不得引用 `WasteCity.Legacy`。

`FormalFateOfferSelector` 接受 `worldSeed`、非空 `sessionId` 和固定 `selectionVersion=1`，以平台无关整数哈希和无放回 Fisher-Yates 产生三个唯一 ID。新进度在 session ID 建立后生成一次并立即进入检查点；恢复永远读取存档 `offeredIds`，不重新计算。测试用相同三输入必须得到同序结果，并用固定输入集合证明九条均可到达。

## 4. 所有权

| 数据 | 唯一 owner | 消费者 |

| 九条定义和等级文本 | `FormalFateCatalog` | 选择、详情、管理台 |
| 本局三候选、选择、等级 | `FormalFateRuntime` | UI、升阶、保存 |

| `3×3` 模板槽 | `SpatialTemplateRuntime` | 统一建造预览/提交 |

| 已显示计划/周期次数 | `ForesightDelayRuntime` | Pressure/Campaign 计划投影 |
| 完整原因访问与扫描标记 | `CausalTransparencyRuntime` | Attention 详情 |

UI、管理台、存档 DTO 和组合根都不是第二玩法真值。

## 5. 六条新增命轨

### 5.1 量子纠缠

Lv.1 将铁矿、石料、水和生物质定义为基础共享资源。已接入通信的主城、次城和前哨通过既有 `ISettlementInventoryEndpoint` 访问同一可用量；提交仍由原库存事务完成，不复制余额。断联聚落保留本地库存。首次跨聚落共享提交建立一次可观察同步压力记录。Lv.2 只稳定化，不扩大资源集合。

### 5.2 空间模板

Lv.1 拥有一个 `3×3` 模板槽，记录相对锚点、正式建筑 ID 和旋转。放置时逐项调用现有建造预览、占格、物流/节点兼容、费用与施工入口；任一项不合法时整组不提交，并列出失败建筑和原因。模板本身不存建筑实例、内部库存或施工进度。Lv.2 只稳定化。

### 5.3 局部时加

Lv.1 每个配置化规则周期拥有 `60` 秒预算，选定一个生产、研究或防御权威域时该域规则增量乘 `5`，预算按真实规则秒消耗；全局暂停冻结预算与目标。不得修改 `Time.timeScale`。目标销毁或失去资格时自动停用但保留剩余预算。Lv.2 只稳定化。

### 5.4 预知迟滞

Lv.1 每个配置化规则周期最多显示一次、持续 `3` 秒的命运片段。片段只能来自已经由 Pressure/Campaign owner 安排但尚未开始的事件，并保存计划稳定 ID 与已显示周期；没有计划时诚实显示“暂无可确认片段”。不得创建、推迟或取消事件。Lv.2 只稳定化。

### 5.5 因果透明

基础 UI 继续向所有玩家显示最近三条原因和下一阈值。Lv.1 额外开放 Attention owner 保存的完整历史、稳定来源 ID、一次性/可重复属性、已锁存阈值和已安排压力关联；它不改变关注度数值。Lv.2 只稳定化。

### 5.6 虚空宝箱

Lv.1 对普通敌人的第 `n` 个稳定死亡事件作 `1%` 灰烬箱判定。RNG 输入只含 session、稳定死亡事件 ID、掉落序号和目录版本；箱内从铁矿、石料、水、生物质中确定性选择一种并给出配置化数量及叙事碎片 ID。生成箱、领取奖励、标记领取在一个可回滚事务内完成；读档、重复死亡通知和重复领取都不得发第二次。Lv.2 只稳定化。

## 6. 坐标锁定

`CoordinateLockRuntime` 只从三个权威事实准备计划：遗产解析完成、60 阈值高危压力已完成、流程进入第六幕等价阶段。提交使用稳定事件键，将 Attention 最低提升到 `90` 并交由现有 Pressure 目录安排 Boss；失败恢复 Attention、锁定状态和 Pressure 队列。降低关注度不撤销已提交锁定。

## 7. schema 36

schema `36` 在 progression 下增加六个状态 DTO 与坐标锁定 DTO。codec 必须为 schema `33/34/35` 使用精确旧投影计算旧哈希，再迁移到新 DTO；不得用新增默认字段参与旧哈希。`35→36` 保留旧三候选和既有状态，六状态与坐标锁定均为空。新进度保存抽取版本与候选结果。

校验拒绝：候选非三个、重复/未知/空白 ID、选择不属于候选、非法等级、模板越界/重复格、非法预算/倍率/目标、预知悬空计划、宝箱重复序号/奖励键、未知资源和坐标锁定半提交。

## 8. UI 与输入

三卡 View 只接收 snapshot 的三个候选定义。详情使用通用“规则、代价、等级、状态、动作”投影，不为九条继续增加固定字段。空间模板、局部时加和宝箱领取动作都从命轨详情发出；二次确认和错误反馈复用正式模态层。Development 管理台由目录生成九条中文选择项，并提供各状态的只读查询及安全操作。所有 PlayMode 验收从正式 Input System 点击进入。

## 9. GitHub 参考结论

- Mindustry：内容定义与目标状态分离，稳定内容身份不等同运行时实例。
- Unciv：效果、参数和条件可组合，UI 从同一规则定义生成说明。
- Freeciv：effect type、value、requirements 分离，稳定规则名承担存档兼容。

本项目只采用这些边界思想，不复制代码、数值、美术或布局，不增加第三方依赖。
