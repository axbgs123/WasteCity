# IDEA-0017：单城十波防御战役设计规格

> 需求 ID：`IDEA-0017`<br>
> 适用版本：Unity `2022.3.62f1`，正式 3D 入口，schema `32`（兼容读取 schema `31`）<br>
> 权威依据：GDD A4.6、A4.11、A6.4、A6.5、A7.1、A7.2、A11.1、A16.1、A16.7、A16.10、A18.3、A21.1；`IDEA-0013`、`IDEA-0015`、`IDEA-0016`、`IDEA-0017`<br>
> 状态边界：本文件是经确认范围的可执行设计，不代表代码、自动化、构建、真实 Windows 验证或用户人工试玩已经完成。

## 1. 目标与非目标

本阶段把 `IDEA-0013` 的单座机枪塔、单种啃噬者和教程波扩展为一场可保存、可恢复、可胜负结算的单城十波防御战役。玩家可以研究并建造机枪塔、激光塔和孢子塔，对抗啃噬者、晶壳兽和啸叫者；敌人能攻击城市核心与既有建筑，建筑拥有真实生命值并会被摧毁。整场战役统一服从 `0 / 1 / 2` 倍规则速度，结束后显示可核对的战斗与生产统计。

本阶段不实现：

- Boss、结晶掘地者、敌人掉落、注意力驱动波次、前哨、多城市、防御支援、战争迷雾或地图扩建；
- A*、导航网格、局部避障、动态重寻路或单位之间的物理挤压；
- 新敌人/塔模型、正式角色建模、物理弹丸或命中判定弹道；
- 电力系统、独立激光能源网络、新资源、新矿点或现有地图内容调整；
- 建筑维修、复活、拆毁退款、残骸回收或掉落物；
- schema `31` 写回。升级后只写 schema `32`，但必须无损兼容读取现有 schema `31`。

## 2. 现状审计与冲突处理

### 2.1 可直接复用的真值

- `BuildingCatalog` 已有三座塔的稳定建筑 ID、尺寸、成本、建造时间、生命上限、研究前置和建筑前置。
- `DefenseTowerCatalog` 已有三座塔的伤害类型、DPS、射程、耗材和每份耗材的有效射击时长；这些数值直接成为本阶段正式配置，不在运行时另写一份。
- `EnemyCatalog` 已有三类敌人的稳定 ID、生命、移速、DPS、攻击距离、护甲类型和目标偏好。
- `TutorialDefenseRuntimeModel`、`WaveDirectorModel`、`GrayboxDefenseRuntime3D`、防御 HUD/世界视图和 schema `31` 防御 DTO 已经证明单波确定性固定步进、核心受伤、机枪塔供弹、存取和视觉投影链路可用。
- `GameSpeedModel` 与既有暂停域已提供请求速度、有效速度及暂停原因；正式保存运行时已能接入。
- 城市库存、建筑内部库存、物流资格、生产、科技、正式放置、建筑实例和资源账本均已有唯一所有者，本阶段只通过既有门面读取或提交命令。
- `SessionStatisticsModel` 已有会话时间、击杀、生产周期、建筑损失等基础字段，但不足以表达逐波、逐敌人和逐塔统计；schema `32` 扩展而不复制造第二份统计真值。

### 2.2 当前占位或缺失

- 现有正式 3D 防御运行时只接受啃噬者，只有教程波；长期 `WaveDirectorModel` 的定向、高危和 Boss 配置不是当前正式战役运行时。
- 现有波次完成条件包含“击败 90%”的历史规则。本阶段明确废止该条件：**只有本波全部计划敌人已经生成且全部死亡，波次才完成**。
- `DefenseTowerCatalog` 已列出激光塔和孢子塔，但两者尚未接入正式单城防御运行时、供给缓存、真实输入选择详情和保存恢复。
- `EnemyCatalog` 已列出晶壳兽和啸叫者，但晶壳减伤、生产建筑优先及正式 3D 可观察化尚未形成完整闭环。
- 建筑定义有最大生命值，正式战役仍缺少建筑实例当前生命、受伤、摧毁残骸、运行失效、统计和保存合同。
- 当前结算、十波推进、逐波统计和 schema `31 → 32` 迁移完全缺失。

### 2.3 文档冲突裁决

1. GDD A16.7 的教程、定向、高危、Boss 四段长期节奏保留为长期方向；`IDEA-0017` 先交付不含 Boss、前哨和注意力门槛的确定性十波单城战役，不得把本阶段写成长期战斗全部完成。
2. GDD 历史“击杀 90% 结束波次”由本规格替换为“全灭结束”。任何测试、UI 或迁移不得再以 90% 判完成。
3. GDD 的教程波 `40` 秒生成时长保留为唯一例外；第 2–10 波的生成时长全部落在 `45–75` 秒。
4. GDD 失败条件中的 Boss 分支本阶段不可达；单城战役仅以核心生命归零判负，以第十波全灭且核心存活判胜。
5. `IDEA-0016` 中弹道学、能量武器和孢子散布为 `PreviewOnly`。本阶段必须在消费者真实接入后把 `core.research.ballistics`、`core.research.energy-weapons` 与 `core.research.spore-dispersal` 改为 `Researchable`，并让现有稳定效果引用真实接入；其余预览节点不趁机转正。
6. `Docs/05` 中将 Boss、完整敌人和结算描述成既有基线的文字不能作为代码事实。收尾时按实际交付状态修正文档，但本设计阶段不预先声称完成。

## 3. 权威所有权与依赖方向

```text
BuildingCatalog / DefenseTowerCatalog / EnemyCatalog / CampaignWaveCatalog
                         │ 只读定义
                         ▼
         SingleCityDefenseCampaignModel（唯一战斗真值）
          │         │            │             │
          │         │            │             └─ SessionStatisticsModel
          │         │            └─ BuildingInstanceHealthStore
          │         └─ 既有库存/物流原子事务
          └─ schema 32 Capture / Restore
                         │
                         ▼
           Controller / Snapshot / HUD / WorldView
                     （只投影与发命令）
```

- `CampaignWaveCatalog` 只拥有波次编号、预警、生成时长、敌人组成和出生方向；不得持有运行进度。
- `SingleCityDefenseCampaignModel` 拥有当前波、阶段、规则时钟、敌人实例、塔战斗缓存、核心生命、终局和统计事件，是战斗唯一运行时真值。
- 建筑定义生命上限继续属于 `BuildingCatalog`；建筑实例当前生命和摧毁状态由一个随建筑实例 ID 保存的健康存储拥有。放置、施工、撤离和占格合法性仍只由既有系统判断。
- 塔的本地耗材缓存属于塔建筑实例。城市库存只通过既有物流资格和原子提取接口补给，不允许战斗运行时直接改资源字典。
- 科技是否完成由正式研究运行时拥有；建造菜单只消费其解锁快照，不复制研究前置。
- UI 只消费不可变快照并提交命令；世界视图、示踪线、激光束和孢子轨迹不参与命中、伤害或目标判断。
- 统计通过已提交的规则事件累加。视图不得根据动画数量、屏幕文本或当前 GameObject 反推统计。

## 4. 正式稳定 ID 与配置合同

### 4.1 三座塔

| 建筑 | 稳定 ID | HP | 伤害类型 | DPS | 射程 | 本地容量 | 耗材 | 每份耗材支持有效射击 |
|---|---|---:|---|---:|---:|---:|---|---:|
| 机枪塔 | `core.building.machine-gun-turret` | 250 | Physical | 20 | 10 | 30 | 弹药 `technology.resource.ammunition` | 3 秒 |
| 激光塔 | `core.building.laser-tower` | 280 | Energy | 48 | 12 | 30 | 能晶 `core.resource.energy-crystal` | 4 秒 |
| 孢子塔 | `biological.building.spore-tower` | 280 | Biological | 18 | 9 | 30 | 生物武器 `biological.resource.weapon` | 5 秒 |

表中 HP 来自 `BuildingCatalog`，武器字段来自 `DefenseTowerCatalog`。实现可以把三种本地容量一并移入正式塔定义，但 `MachineGunAmmunitionCapacity=30` 的既有公开兼容合同不得改变。激光塔消耗既有能晶只是武器供给，不代表新增电网或发电系统；孢子塔直接造成生物伤害，本阶段不叠加感染、扩散、减速或持续伤害状态。

塔必须同时满足以下条件才可射击：建筑已完成、归玩家所有、当前 HP 大于零、未被撤离锁定、存在射程内合法目标且本地耗材剩余有效射击时长大于零。物流范围只决定能否从城市库存补给；脱离物流时保留本地耗材并可继续用完，耗尽后停火，恢复物流后再补给。补给、射击消费和暂停都使用规则时间。

目标选择统一为：射程内 `当前生命 > 0` 的敌人中先取离塔更近者，再按敌人稳定实例 ID 升序打破平局。已锁定目标仍合法时持续攻击；只有目标死亡、出射程或塔失效时重选。这样重建、存取和不同帧率下不会因集合遍历顺序改变目标。

伤害每 `0.1` 规则秒固定步进结算，内部保留浮点余量，生命 UI 向上取整显示。伤害类型与护甲倍率只调用既有 `DamageMatrix`；运行时和本规格不建立晶壳专用减伤表。命中没有随机暴击、散布或闪避。

### 4.2 三类敌人

| 敌人 | 稳定 ID | HP | 移速 | DPS | 射程 | 特性与目标优先级 |
|---|---|---:|---:|---:|---:|---|
| 啃噬者 | `core.enemy.gnawer` | 60 | 1.8 | 8 | 2 | 轻甲；始终以城市核心为目标。 |
| 晶壳兽 | `core.enemy.crystal-beast` | 220 | 0.9 | 20 | 2 | 重甲；优先最近的已完成玩家城墙，否则攻击核心。 |
| 啸叫者 | `core.enemy.howler` | 100 | 1.2 | 12 | 7 | 轻甲、远程；优先最近的已完成玩家生产建筑，否则攻击核心。 |

本阶段把 `EnemyTargetPriority` 扩展为可直接表达 `Core / Walls / Production` 的正式目录字段，并将三类敌人映射到上述目标；不得给啃噬者另写目录外的核心特例。`生产建筑` 由正式生产目录是否存在该建筑定义判断，不允许在敌人代码维护名称数组。建筑目标必须已完成、玩家所有、HP 大于零。多个同类候选距离相同时按建筑稳定实例 ID 升序决胜。

敌人只做“朝当前目标直线移动，进入攻击距离后原地攻击”。建筑格子不参与寻路；敌人不会绕墙、互相避让或重规划道路。目标摧毁后在下一固定步按上述规则重新选择；若没有该类型候选则直接回退核心。若目标在城市转换中移动，敌人追踪该目标当前战斗位置，不生成导航路径。

### 4.3 建筑生命与摧毁

- 新建建筑：施工期间 `CurrentHealth = MaxHealth`，但未完成前不进入敌人合法目标集；完成后正式可受伤。已有 schema `31` 建筑迁移时也取定义最大生命。
- 受伤：只有战役模型可以提交战斗伤害；每次提交同时产生 `building_damaged` 统计事件。城市核心仍用现有 `CityCoreCombatModel`，最大生命 `2000`。
- 摧毁：`CurrentHealth <= 0` 时原子进入 `Destroyed`，同一建筑实例只发一次 `building_destroyed`；立即停止生产、研究资格、物流容量、塔射击和其他效果。
- 残骸：摧毁后保留原稳定实例 ID、旋转、占格和无功能残骸投影，避免同一固定步被立即覆盖放置；残骸不可选择为生产/物流/研究主体。本阶段没有清理命令，战役结算后继续沙盒也保留残骸。
- 内容损失：建筑内部库存、生产预留和塔本地耗材在首次摧毁事务中清除，不退款、不转背包、不生成掉落；损失量进入战斗统计，保存恢复不得重复清除或重复计数。
- 容量收缩：仓库摧毁导致城市剩余总量超过新容量时，复用既有超容量语义——禁止新增但允许消费/转出；不得为了配平再删除其他仓库或核心中的资源。
- 撤离：进入撤离锁定的建筑仍保存当前 HP，但不再是合法目标或战斗贡献者；当前敌人下一固定步重选。不得借撤离恢复生命或复制库存。

## 5. 十波战役目录

### 5.1 固定配置

战役以 `campaign.single-city-defense.v1` 为稳定目录 ID。教程波由第一座已完成且归玩家所有的任一正式防御塔触发且只触发一次，不依赖物流、耗材或玩家暂停；后续波在上一波全灭后直接进入下一波预警。预警期间玩家可以建造、生产、研究和补给。暂停冻结所有计时。

| 波次 | 预警 | 生成时长 | 啃噬者 | 晶壳兽 | 啸叫者 | 出生方向 |
|---:|---:|---:|---:|---:|---:|---|
| 1（教程） | 15 秒 | 40 秒 | 8 | 0 | 0 | 东 |
| 2 | 20 秒 | 45 秒 | 10 | 0 | 0 | 东 |
| 3 | 20 秒 | 50 秒 | 12 | 2 | 0 | 东、北 |
| 4 | 25 秒 | 50 秒 | 14 | 3 | 0 | 东、北 |
| 5 | 25 秒 | 55 秒 | 16 | 4 | 2 | 东、南 |
| 6 | 30 秒 | 55 秒 | 18 | 5 | 3 | 东、北、南 |
| 7 | 30 秒 | 60 秒 | 20 | 6 | 4 | 四向 |
| 8 | 35 秒 | 60 秒 | 22 | 8 | 5 | 四向 |
| 9 | 40 秒 | 65 秒 | 24 | 9 | 7 | 四向 |
| 10 | 45 秒 | 75 秒 | 28 | 10 | 8 | 四向 |

第一波生成时长 `40` 秒是已批准教程例外；第 2–10 波均在 `45–75` 秒。单波按目录顺序确定性轮转各敌人类型，使高威胁单位不集中在同一帧；同类内部按波次、目录项和序号生成稳定实例 ID。最后一个敌人应不晚于生成时长结束时出现。

“东、北、南、西”不是新地图对象。运行时从既有世界边界和核心当前位置投影四个入口：从核心沿对应轴到已揭示地图边界内侧一格，再用固定 `Y → X` 顺序选择最近的可通行非建筑格。入口在预警开始时冻结并进入 schema `32`；整波不得因城市移动或存取重新抽选。当前地图不增加格子、矿物、地形贴图或手工场景锚点。

### 5.2 阶段机

固定阶段为：

```text
Idle → Warning → SpawningAndCombat → CombatCleanup
       ↑                    │             │
       └────────────────────┴─────────────┤ 全部生成且存活数为 0，进入下一波
                                          ├ 第 10 波 → Victory
                       核心 HP = 0 ───────┴→ Defeat
```

- `Idle`：尚未满足第一波触发条件。
- `Warning`：显示波次、方向、敌人构成和剩余规则秒；计时到零开始生成。
- `SpawningAndCombat`：按生成时钟产生敌人并进行战斗。
- `CombatCleanup`：最后一个计划敌人已生成，但仍有存活敌人。此阶段没有超时强制结束。
- `Victory / Defeat`：终局不可逆，战斗、生产、研究和施工规则时间冻结，显示结算。

完成条件必须同时满足 `SpawnedCount == PlannedCount` 与 `AliveCount == 0`。逃离视野、视图对象销毁、进入残骸、存档卸载、击杀 90% 或生成计时结束均不能完成波次。

核心 HP 归零在同一固定步优先于第十波胜利判定；若最后一名敌人死亡与核心归零同一步发生，结果为失败。终局只产生一次事件并清空尚未提交的视觉命令。

## 6. 规则速度与暂停

- `GameSpeedModel.RequestedSpeed` 的正式可选值只有 `0`、`1`、`2`；旧值或输入先夹取再提交。`EffectiveSpeed` 在系统菜单、战术暂停、终局或其他既有暂停原因存在时为 `0`。
- `Space` 切换战术暂停：从 `1/2` 进入 `0` 时记住最后一个非零速度；解除后恢复该速度。`1`、`2` 直接请求对应速度，`0` 不作为玩家速度快捷键，继续保留为 Development 修改器入口。
- 数字键在建造快捷栏、搜索框或其他模态输入获得焦点时先由高优先级界面处理，不能同时改速度；屏幕速度按钮走同一命令门面和真实输入循环。
- 防御、敌人移动/攻击、塔耗材、波次、施工、生产、研究和统计时钟都消费同一规则增量。实现必须确保增量只乘一次速度，不得同时通过 `Time.timeScale` 和业务 delta 双倍加速。
- 暂停时允许镜头、UI、选择、结算浏览和存取命令；不允许伤害、补给、生产批次、研究、施工、波次或统计时间推进。解除暂停不得补算现实时间。
- schema `32` 明确保存规范化 `RequestedSpeed` 与 `LastNonZeroSpeed`；schema `31` 迁移时若处于战术暂停则恢复暂停理由，否则请求速度默认 `1`，最后非零速度也默认 `1`。终局载入后有效速度保持 `0`，但保留玩家最后非零速度供“胜利后继续沙盒”使用。

## 7. 结算与统计

### 7.1 胜负

- 胜利：第十波全部计划敌人已生成、全部死亡且核心 HP 大于 `0`。
- 失败：任意固定步结束时核心 HP 等于 `0`。
- 胜利后可选择“继续沙盒”：关闭结算、恢复终局前最后非零速度，不再生成新波；残余建筑伤害和残骸保留。
- 失败后可选择“读取最近波前检查点”或“返回标题”。不得在失败态原地恢复核心生命。
- 每一波预警开始前，在不存在活动写盘事务时创建波前检查点；第 1 波使用战役开始检查点。检查点继续服从既有原子写入、备份和验证规则。

### 7.2 权威统计字段

| 字段 | 定义 |
|---|---|
| 战役规则时间 | 从第一波触发到终局的规则秒；暂停不计，`2` 倍时按游戏规则时间增加。 |
| 完成波次 | 已全灭完成的波数；失败时显示 `n/10`。 |
| 击杀 | 总数及三类敌人分项；只在生命首次跨到零时计数。 |
| 最高同时存活 | 任意固定步结束时的最大 `AliveCount`。 |
| 核心状态 | 当前/最大 HP、累计承受伤害；过量伤害只计到实际扣除量。 |
| 建筑损失 | 总数及按建筑稳定 ID 分项；同一实例只计一次，核心不计入建筑损失。 |
| 塔伤害 | 按三座塔建筑 ID 累计实际伤害；过量伤害不计。 |
| 战斗耗材 | 弹药、能晶、生物武器实际消费量；只在耗材租约提交时计。 |
| 生产批次 | 战役期间完成的正式生产批次数；复用生产事件。 |
| 生产效率 | 所有已完成、未摧毁生产建筑在规则运行时的 `ActiveProgressSeconds / EligibleSeconds`。无配方、撤离锁定和终局时间不进入分母；缺输入、输出满或脱离物流进入分母但不进入分子。分母为零显示“无数据”。 |
| 防守方式 | 战役开始后从未成功收起城市为“坚守”；至少成功收起一次为“机动防守”。不评价好坏。 |

统计由稳定 ID 分组并按目录顺序显示。schema `31` 迁移后无法可靠重建的历史塔伤害、建筑伤害和生产效率标记 `PartialFromMigration=true`，结算显示“迁移前未统计”，不得填零冒充完整记录。

统计 UI 至少显示：结果、规则时间、完成波次、总击杀/分项、最高同时存活、核心剩余、建筑损失、三塔伤害、三类战斗耗材、生产批次、生产效率和防守方式。开发修改器产生的资源或研究变化不改战斗统计；若战役期间使用过修改器，结算增加“开发修改器已使用”标记，但不阻止胜负。

## 8. 3D 可观察化与真实输入

### 8.1 常驻 HUD

- 顶部危险区显示 `第 n/10 波`、阶段、预警倒计时、已生成/计划、存活数、核心 HP 和当前有效速度。
- 预警至少显示入口方向和三类敌人数量；不依赖颜色区分敌人。
- 常驻速度控件提供暂停、`1×`、`2×`，当前请求速度与因菜单造成的有效暂停要分别可见。
- 既有文明式资源状态栏和建造栏位置不重排；战役 HUD 适配其安全区，不能遮住下方缺料提示。

### 8.2 选择详情

- 选择塔：名称、当前/最大 HP、伤害类型、DPS、射程、当前目标、本地耗材/容量、耗材名、预计可持续射击秒数、物流状态和停火原因。
- 选择普通建筑：名称、当前/最大 HP、运行状态；生产建筑继续显示原有内部库存、配方和停工原因。
- 选择敌人：名称、当前/最大 HP、移速、DPS、射程、护甲/减伤、当前目标和距离。
- 选择残骸：原建筑名称、“已摧毁”、损失内容摘要；不显示可运行按钮。
- 停火原因固定优先级：已摧毁 → 未完工 → 撤离锁定 → 玩家/系统暂停 → 无目标 → 缺少耗材 → 不在物流范围且本地耗材耗尽。详情可以列出全部原因。

### 8.3 表现边界

- 机枪示踪线、激光束、孢子轨迹都从已结算的攻击事件生成，使用池化对象，长度和命中点只做视觉插值。
- 粒子、线条、动画、声音丢失或被裁剪不能影响伤害；同一攻击事件重复投影不能重复伤害。
- 不新增建模。三类敌人复用可替换的低模/胶囊轮廓，以尺寸、颜色、轮廓附件和头顶图标区分；三塔复用现有建筑几何和正式二维图标。所有占位必须在可复用视觉目录登记。
- 屏幕外敌人仍参与规则；HUD 存活数来自模型快照，不从场景对象计数。

## 9. schema 32 与 schema 31 兼容

### 9.1 新权威状态

schema `32` 在既有 envelope 下新增或扩展以下稳定 DTO：

```text
DefenseCampaignState
  CampaignId
  Phase
  CurrentWaveNumber
  WarningRemainingSeconds
  SpawnClockSeconds
  Planned / Spawned / Defeated counts by enemy id
  FrozenSpawnAnchors
  NextEnemyOrdinal
  FixedStepAccumulatorSeconds
  CoreCurrentHealth
  EnemyStates[]          // instance id, enemy id, position, health, target id, attack remainder
  TowerCombatStates[]    // building instance id, consumable id, amount, lease remainder, target id
  BuildingHealthStates[] // building instance id, current health, destroyed
  StatisticsState
  Result
  RequestedSpeed
  LastNonZeroSpeed
```

目录定义、DPS、射程、最大生命、波次组成、目标优先级、显示文字和视图对象不写入存档；恢复时从正式目录解析。每个数组按稳定实例 ID 排序后编码，未知定义不能通过数组下标误配。

### 9.2 `31 → 32` 迁移

1. schema `31` 教程未触发：创建 `Idle / Wave 0` 战役，核心和建筑当前生命取定义最大值，统计为空。
2. schema `31` 教程处于预警、生成或战斗：映射为第 1 波对应阶段；所有敌人定义为 `core.enemy.gnawer`，保留位置、生命、计时、顺序和核心生命；冻结东侧入口为原生成原点。
3. schema `31` 教程已完成：映射为第 2 波 `Warning`，剩余 `20` 规则秒；不得重新触发教程波。
4. schema `31` 已有机枪塔供弹状态映射到同一建筑实例；激光塔和孢子塔若已存在，创建空本地缓存，不自动赠送耗材。
5. 所有已完成建筑当前生命取 `BuildingCatalog.MaxHealth`，不存在已摧毁建筑；未知建筑继续按既有未知内容往返策略处理，不凭猜测分配战斗生命。
6. 可可靠得到的教程击杀、规则时间和核心生命进入统计；无法重建的逐塔伤害、建筑伤害和效率标记 `PartialFromMigration`。
7. 研究完成 ID、库存、建筑实例、世界、物流、生产、背包和修改器使用标记沿用原 schema `31` 迁移规则，不重新扣成本、不重复解锁。
8. 迁移成功后只写 schema `32`；失败必须返回可诊断错误并保留原文件和备份，不写半迁移数据。

schema `1–30` 的历史身份、解码器、迁移和固定样本测试必须继续保留且不得覆写；schema `31` 的解码器和全部固定样本也必须继续保留。schema `32` 还必须验证：十波任意阶段、三敌人混合、三塔缓存、受伤/摧毁建筑、终局、统计、请求速度、最后非零速度、固定步余量和未知 ID 的确定性往返。

## 10. 性能与稳定性门

- 固定步 `0.1` 秒；第 10 波计划敌人总数 `46`，低于 GDD 当前单区域活跃敌人 `150` 的目标预算。
- 敌人、攻击表现、血条和伤害数字必须池化。十波、重试、读档、返回标题后 GameObject、监听器、材质和池容量不得无界增长。
- 目标查询使用稳定、可复用缓冲；禁止每帧 `FindObjectsOfType`、全场景 LINQ、字符串拼接、临时列表或按塔复制全部敌人。
- HUD 只在战斗/建筑/库存/速度 revision 变化时刷新；静止暂停、无波次和未变化快照不能每帧重建文本。
- 聚焦性能证据至少覆盖第 10 波 `46` 敌人、三种塔各 `8` 座、混合建筑受伤和常驻 HUD：预热后 `300` 帧规则/投影稳定路径无持续托管分配，单次波次切换快照分配不超过 `64 KB`。
- 连续完成十波、连续 `20` 次读档恢复同一战斗帧、连续 `20` 次胜负结算开关后，对象、监听器、敌人实例 ID和统计结果稳定。
- 自动化和 macOS 本机结果不能写成真实 Windows 10/11 GPU、显存、内存或用户视觉验收；这些继续单列待验。
