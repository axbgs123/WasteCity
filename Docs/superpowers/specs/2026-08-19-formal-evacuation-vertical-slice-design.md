## 1. 权威性与阶段边界

本文把 `Docs/06-User-Feedback-and-Change-Control-ZH.md` 中已批准的 `IDEA-0014` 转化为可执行的运行时、数据所有权、事务、UI、输入和验证设计。实施计划可以细化任务与文件名，但不得改变本文规则；若出现无法同时满足的产品冲突、需要 schema `31` 或必须扩大排除项，先停止并回到变更控制。

本阶段复用并升级现有能力：

- `CityDeploymentModel` 的 Mobile、Deploying、Fortress、Packing 状态；
- `GrayboxMobileCityController3D` 的移动、展开位置校验与表现；
- `BuildingEvacuationRules`、`GrayboxEvacuationController3D` 和 `GrayboxBuildingSession3D` 的清单、稳定队列、撤离锁、遗弃与拆除；
- `CityResourceStorageModel` 的城市核心、独立仓库、过滤、确定性路由与原子事务；
- `GrayboxProductionRuntime3D` 的建筑内部输入、活动批次和输出；
- `GrayboxDefenseRuntime3D` 的教学波、存活敌人、塔内弹药与城市核心；
- `GrayboxOperationsController3D`、现有系统菜单、战术暂停与正式 Input System 主循环。

本文不把 `IDEA-0003` 的灰盒实现误写为已经完成的正式撤离，也不把本规格写成实现或验证证据。用户人工试玩与真实 Windows 10/11 视觉、GPU、显存和内存结论仍须由实际验收确认。

## 2. 目标体验与完成路径

玩家必须能通过同一正式 3D 会话连续完成：

```text
驾驶或寻路
  → F 展开
  → B 建成研究站
  → T 依次研究基础冶金、弹药装配、自动防御
  → B 建成生产链和机枪塔
  → 真实生产弹药并在教学波中消耗弹药
  → 敌袭中 F 打开撤离清单
  → 处理全部外城资产
  → 完成 Packing
  → 返回 Mobile 并再次驾驶
```

该路径不允许测试直接完成研究、直接创建建筑、直接注入最终产物、直接触发伤害或直接调用撤离提交来冒充玩家操作。测试夹具只允许提供确定性初始资源和加速规则时间。

## 3. 设计原则

1. 城市形态、战斗状态、建筑生命周期、库存和资源节点各自只有一个权威真值。
2. UI 只读不可变投影并发送命令，不计算战斗、退款、时长、容量或合法性。
3. 清单预览使用实时权威上下文；确认后冻结批次规则，不因随后敌情变化改写已确认工作。
4. 仓储内容和容量不预留到未来；每个项目提交前以当前网络重新预检，并以整项原子事务提交或拒绝。
5. `IsEvacuationLocked` 继续作为生产、研究、仓库和防御共同的生命周期门，不建立第二套“撤离中可运行”判断。
6. 规则状态与表现分离。Renderer、GameObject、HUD 文本、按钮状态和动画不能成为玩法真值。
7. 所有顺序使用稳定 ID；不得依赖场景遍历、Dictionary、HashSet、碰撞结果或 UI 行顺序。
8. schema 保持 `30`；新增状态都是 3D 会话态。

本阶段按最小扩展实施：继续以现有 `BuildingEvacuationWork` 作为项目工作值、以 `CityResourceStorageModel` 和其 `TryCommitBatch`/内部 `StoragePlan` 作为唯一城市仓储事务、以现有生产和防御不可变快照作为观察来源。允许给这些边界增加本需求必需的字段或窄重载，但不得新建平行撤离工作类型、平行仓储模型、平行生产缓存或平行防御状态。

## 4. 领域与程序集所有权

### 4.1 `WasteCity.Game`

拥有不依赖 Unity 场景的正式规则：

- 城市部署与收起状态机、基础时长、进度和取消；
- 展开/收起推进上下文与生产力、战斗减速公式；
- 现有 `BuildingEvacuationTreatment`、`BuildingEvacuationWork` 的批次上下文、退款和基础拆除时长扩展；
- 建筑资源载荷、容量缺口和事务结果值对象；
- 确定性取整、稳定排序和失败原因代码。

纯规则层不读取 `Time`、键盘、场景对象、HUD、敌人 GameObject 或仓库 UI。

### 4.2 `WasteCity.Graybox3D.Building`

拥有正式 3D 会话适配和编排：

- 从防御运行时读取权威战斗上下文；
- 复用 `WasteCity.Population.PopulationModel` 的正式人口生产力公式，并由 3D 建筑会话公开一个统一只读生产力入口；正式会话使用 GDD 的初始人口 `100`、容量 `150`，开发修改器的规则时间加速保持为独立倍率，不能冒充玩法生产力；
- 将规则推进上下文提交给 `CityDeploymentModel`；
- 构造实时撤离预览、确认批次和稳定工作队列；
- 通过 `GrayboxBuildingSession3D` 获取并锁定建筑状态；
- 从既有生产观察快照与 `GrayboxDefenseRuntimeSnapshot3D`/塔快照读取载荷，并协调其窄提交/恢复入口；
- 通过现有 `CityResourceStorageModel.TryCommitBatch` 及同一内部 `StoragePlan` 的仓库移除扩展，协调仓库内容、退款、占格与建筑实例的事务；
- 生成不可变 UI view-model；
- 把成功后的领域状态投影到建筑和城市表现。

该层不得复制 `BuildingRangeRules`、`WorldMapModel`、生产配方、科技前置、塔索敌或仓库过滤规则。

### 4.3 `WasteCity.Graybox3D.Usability`

拥有正式输入协调、系统菜单、战术暂停和 UGUI 表现：

- `F` 展开、取消转换、打开撤离清单或开始收起；
- `Space` 战术暂停；
- `Esc` 分层取消清单或打开系统菜单；
- 清单单项、分类、全部、混合赋值及确认按钮；
- 队列、倒计时、容量失败和后果文本。

它只发送稳定 ID 与命令，不持有可变建筑实例、库存对象或战斗模型。

### 4.4 Editor 与质量目录

`GrayboxSceneAuthoring` 只负责幂等地建立显式序列化引用；不能用 `FindObjectOfType`、对象名称查找或运行时临时补组件掩盖缺失接线。新增生产文件必须进入项目质量目录、可复用目录和自动生成项目清单。冻结 2D 场景不接入新组件。

依赖方向保持：

```text
WasteCity.Game
    ↑
WasteCity.Graybox3D
    ↑
WasteCity.Graybox3D.Building
    ↑
WasteCity.Graybox3D.Usability / Editor / Tests
```

## 5. 城市部署与收起状态机

### 5.1 正式基础时长

正式配置为：

| 转换 | 基础时长 |
|---|---:|
| Mobile → Deploying → Fortress | `5` 秒 |
| Fortress → Packing → Mobile | `8` 秒 |

`5/8` 必须来自正式配置或构造参数；不得散落在控制器、UI、测试和动画中。旧灰盒 `3/5` 秒被正式值替代。

`CityDeploymentModel` 继续以“基础秒剩余量”持有进度。每个规则步的基础秒推进量为：

```text
normalAdvance = max(0, ruleDeltaSeconds) × max(0, productivityMultiplier)
deployAdvance = normalAdvance
peacePackingAdvance = normalAdvance
combatPackingAdvance = normalAdvance × 0.7
```

若上下文在整个转换中恒定：

```text
actualDeployDuration = 5 / productivityMultiplier
actualPeacePackDuration = 8 / productivityMultiplier
actualCombatPackDuration = 8 / (productivityMultiplier × 0.7)
```

生产力倍率每步从 3D 建筑会话持有的 `PopulationModel.ProductivityMultiplier` 统一入口读取；正式初始 `100/150` 得到 `100%`，公式和 `250%` 上限不在部署或撤离层复制。开发修改器现有施工加速改为独立的规则时间倍率，只用于测试/开发加速；部署、施工与完整拆除的推进量可以再乘该开发倍率，但 UI 和玩法生产力显示不得把它算作人口贡献。战斗 `0.7` 在正式生产力与可选开发时间倍率之后应用。非有限值、负值或缺少权威来源必须转为安全的零推进并报告配置错误，不得让剩余时间变为 NaN。

### 5.2 状态转换与取消

正式 `F` 行为为：

```text
Mobile    --F且部署合法--> Deploying
Deploying --F取消-------> Mobile
Fortress  --F且资产已处理--> Packing
Packing   --F取消-------> Fortress
```

- 取消只返回转换前稳定状态；本次已推进时间全部作废。
- 再次开始时从完整 `5` 或 `8` 基础秒重新计时。
- 取消不退款、不扣资源、不创建进度债务，也不改变建筑、研究、生产和库存。
- Deploying 取消不需要重复放置校验；下一次从 Mobile 开始时必须重新执行完整 `3×3` 部署校验。
- Packing 取消后保持全部已经提交的撤离结果；已拆除建筑不会恢复，遗弃废墟不会返还所有权。
- 状态改变事件每次真实转换只发布一次；无效命令不增加 revision。

系统暂停和战术暂停向规则时钟提供零 delta。暂停期间仍可读 UI，但 Deploying、Packing、拆除、生产、研究和战斗均不推进。

### 5.3 表现和移动

城市 Transform、Collider 和视觉插值只消费 `Mode` 与规范化进度。移动仍只允许在 Mobile；Deploying、Fortress、Packing 均不接受驾驶位移。取消后表现必须在同一规则帧回到对应稳定形态，不保留半展开 Collider。

## 6. 权威战斗上下文

### 6.1 唯一来源

战斗上下文由 `GrayboxDefenseRuntime3D` 的教学波运行时发布，只读值至少包含：

- 是否已有敌人实际生成；
- 当前存活敌人数；
- 是否处于战斗；
- 防御 revision。

正式判定为：

```text
isInCombat = hasSpawnedEnemy && aliveEnemyCount > 0
```

`15` 秒 Warning 阶段没有实际敌人，因此不是战斗。HUD 的 `WavePhase`、倒计时文字、敌人 GameObject 数量、敌人距离、核心最近是否受伤都不能替代该判定。若存活数降为零，实时预览回到和平；后续又有敌人实际生成且存活数大于零时重新进入战斗。

### 6.2 消费者

同一只读战斗快照供以下消费者使用：

- `CityDeploymentModel` 当前 Packing 步是否乘 `0.7`；
- 撤离清单实时预览使用和平或战斗完整拆除规则；
- 确认时创建不可变 `EvacuationBatchContext`；
- UI 显示“和平/战斗批次”及战斗规则说明。

撤离控制器不从 `AliveEnemyCount` 自行推导第二套状态；它只消费防御运行时公开的权威布尔值和 revision。

## 7. 撤离批次规则

### 7.1 清单成员

清单继续只包含：

- 位于外城 Ground；
- 归玩家所有；
- 状态为 UnderConstruction 或 Completed；
- 尚未被其他撤离批次锁定的建筑实例。

内城建筑随城市移动，不进入清单。已遗弃废墟不属于玩家，不再进入清单，但继续占格。所有成员按稳定建筑实例 ID 排序。

### 7.2 四种处置

| 处置 | 退款比例 | 基础耗时 | 结果 |
|---|---:|---:|---|
| 和平完整拆除 | `80%` | 原施工基础时长 × `0.5` | 原子迁移物资和退款后移除 |
| 战斗完整拆除 | `60%` | `5` 秒 | 原子迁移物资和退款后移除 |
| 快速拆除 | `50%` | 立即 | 原子迁移物资和退款后移除 |
| 遗弃 | `0%` | 立即 | 失去所有权，成为无功能占格废墟 |

完整拆除实际时长为：

```text
actualDismantleDuration = frozenBaseDuration / frozenProductivityMultiplier
```

快速拆除和遗弃没有计时，不应用生产力倍率。

完成建筑的剩余比例为 `1`。未完成施工使用：

```text
remainingRatio = clamp(remainingConstructionBaseSeconds /
                       originalConstructionBaseSeconds, 0, 1)
refund = RoundAwayFromZero(
    originalConfiguredCost × remainingRatio × treatmentRatio)
```

每种正式成本资源独立计算并限幅到 `0..原成本`。退款必须复用 `ConstructionRefundRules` 的确定性取整，不复制公式到 UI。

### 7.3 实时预览与批次冻结

清单打开后不锁定战斗状态。预览在下列 revision 变化时重新投影：

- 防御战斗 revision；
- 城市生产力 revision；
- 建筑会话 revision；
- 生产、塔弹药或仓库内容 revision；
- 城市存储网络 revision；
- 玩家赋值 revision。

玩家确认时创建不可变 `EvacuationBatchContext`，至少冻结：

- 唯一会话内批次 ID；
- 确认时是否处于战斗；
- 对应完整拆除退款比例和基础时长规则；
- 确认时由 `PopulationModel` 统一入口读取的有效城市生产力倍率；该冻结只用于已确认拆除队列，城市部署/收起仍逐步读取当前倍率；开发规则时间加速不写入批次玩法上下文；
- 确认时的战斗与生产力来源 revision；
- 确认命令序号。

同一批次全部完整拆除工作使用该冻结上下文。确认后敌人死亡、重新生成或人口变化，不改变已确认项目的退款、基础时长或实际倒计时。只有确认前的 assignment/锁获取 prepare 失败才返回清单且尚未形成批次；确认后的容量不足进入 Blocked，并始终以原批次 context/work 重检，不能重新确认获取更有利的和平规则。

仓储数量、过滤、联网和可用容量明确不进入长期冻结；它们在每项提交前重检。

### 7.4 确认顺序

确认命令按以下顺序执行：

1. 重验清单仍处于 Fortress、每项仍归玩家、仍在外城且 assignment 完整；
2. 捕获批次上下文；
3. 扩展并复用现有 `BuildingEvacuationWork`，为每项记录稳定 ID、处置、剩余比例、逐资源退款、基础时长和批次上下文引用；不创建第二套工作项；
4. 捕获每项将被保留、迁移或损失的运行时资源载荷；
5. 按稳定 ID 获取撤离锁；任一锁失败则释放本命令已取得的全部锁，不执行任何处置；
6. 按稳定 ID 提交遗弃和快速拆除；
7. 将完整拆除按稳定 ID 放入单一串行队列；
8. 所有玩家外城项目处理完成后，仅调用一次既有 Packing 请求。

即时项目和完整队列的顺序都不得依赖 UI 行、分类赋值或 Dictionary 枚举顺序。

## 8. 建筑资源载荷

### 8.1 必须纳入事务的资源

完整或快速拆除必须守恒并迁移：

- 生产建筑内部输入缓存；
- 已开始生产周期持有的预留输入批次；
- 生产建筑内部输出缓存；
- 机枪塔本地弹药；
- 被拆仓库的全部真实内容；
- 本次拆除的逐资源建造退款。

生产进度本身不是资源；迁移已预留输入后，该周期和进度随建筑移除。采矿站尚未完成的周期没有预先扣节点资源，因此不生成额外退款，也不调用 `Harvest`。

同一资源来自多个来源时先按来源类别和稳定资源 ID 形成明细，再合并为提交总额。UI 可以显示明细，但存储预检只对合并后的正式资源数量执行一次，避免重复计算容量。

### 8.2 遗弃损失

遗弃普通生产建筑或机枪塔时：

- 内部输入、活动批次预留、内部输出和塔内弹药明确销毁；
- 不产生建造退款；
- 清单确认前按正式资源名称和数量列出损失；
- 成功后建筑变为非玩家、无生产、无物流、无防御的占格废墟。

遗弃仓库是例外：仓库内容不得销毁，仍必须先原子迁移到排除本仓库后的其余城市网络；容量不足时拒绝遗弃。迁移成功后才失去仓库所有权和容量贡献。

### 8.3 不得重复计数

- 塔内弹药只属于防御运行时，不同时作为生产输出统计；
- 仓库内容只属于 `WarehouseStorageState`，不同时计入城市核心；
- 活动生产批次已扣除的输入只在活动批次载荷中统计，不再次从输入缓存读取；
- 施工退款只来自正式建筑成本快照，不把已迁移内部资源当成退款。

## 9. 原子容量预检与提交

### 9.1 项目级事务

原子边界是“一个撤离项目”，不是整个混合批次。已经成功提交的早期项目不会因为后续项目失败而复活；失败项目和尚未提交项目必须保持或恢复到可继续操作的状态。

每项提交前，由 `CityResourceStorageModel` 复用其现有私有 `StoragePlan` 计算只读预检结果。可以为撤离增加一个仅承载预检输出的值对象，但它不持有库存、不能提交，也不是第二套仓储模型。预检结果至少包含：

- 来源建筑稳定 ID、处置和批次 ID；
- 各资源迁移量、退款量与总写入量；
- 排除来源仓库后的目标网络；
- 目标仓库过滤和稳定路由顺序；
- 当前城市存储 revision；
- 各资源可接收量与精确缺口；
- 是否可以完整提交及失败原因代码。

目标网络必须排除正在拆除或遗弃的源仓库及其 `150` 容量。其余仓库只有在已完成、归玩家所有、未撤离锁定、物流有效且过滤允许时才可接收；城市核心和仓库的路由继续由 `CityResourceStorageModel` 决定。

非仓库项目的资源写入直接复用 `CityResourceStorageModel.TryCommitBatch` 的“完整加入或不变”语义。仓库项目只在同一个模型内增加窄重载：基于同一 `StoragePlan` 同时排除源仓库、迁移其内容、加入建筑载荷与退款并移除仓库，最后只调用一次现有提交路径。不得先移仓、再分次 Add，也不得在撤离层复制仓库路由。

### 9.2 提交时重检

计时结束或即时项目准备提交时，必须重新验证：

1. 批次和工作项仍有效；
2. 建筑实例、所有权、位置、状态、方向和占格未被替换；
3. 撤离锁仍由当前批次持有；
4. 生产缓存、活动批次、塔弹药和源仓库内容与锁定载荷一致；
5. 城市存储、仓库过滤、联网、所有权和容量使用最新 revision；
6. 迁移资源与完整退款能够全部写入目标网络。

城市存储 revision 改变不是自动失败；系统先用当前状态重建计划。只有最新计划仍有缺口或其他资格失效时才拒绝。

### 9.3 提交结果

本阶段采用可执行的 prepare/commit 协议，不建立跨五个运行时的通用事务框架：

1. prepare 阶段完成所有可能正常失败的资格、锁、载荷、仓储容量、源仓库排除、占格和表现可处理性检查；任何拒绝都发生在领域状态变化前；
2. 用最新城市存储 revision 构造一次性仓储计划；revision 已变化就丢弃旧计划并重算，不把过期计划带入 commit；
3. 在 Unity 主线程同一同步调用中提交一次城市仓储计划；该计划同时完成载荷/退款写入、源仓库内容迁移和源仓库记录/容量移除，是全部城市仓储变化唯一的可观察 commit，不返回部分接收；
4. 仓储 commit 成功后，只执行 prepare 已证明有效的非仓储无失败内存收口：清除对应生产/防御状态、释放占格、移除或遗弃实例、释放撤离锁并单调增加相关 revision；
5. 最后按会话真值刷新表现；表现异常不得改写已成功的领域结果，应记录并由现有重建入口恢复表现。

完整或快速拆除成功后，全部迁移载荷和完整退款进入确定目标，建筑及相应运行态被移除。遗弃成功则保留占格，转换所有权与生命周期，清除非仓库内部载荷和运行状态；仓库内容先纳入同一次仓储计划迁移。

正常容量、资格、revision 或表现 prepare 失败必须零领域写入。revision 是单调变更通知，绝不倒退；本阶段不为进程内存损坏、`OutOfMemoryException` 或任意第三方事件处理器抛错设计分布式回滚。仓储 commit 只在全部项目内存收口已 prepare 为确定且无失败后执行，并隔离通知阶段异常，避免已提交库存与建筑生命周期分叉。不得返回部分接收，不得静默丢失退款。

### 9.4 容量失败

容量不足返回稳定失败代码和逐资源缺口，例如：

```text
无法拆除冶炼厂：城市仓储还缺 6 格
铁矿缺口 4，合金退款缺口 2
```

失败时：

- 当前建筑不移除、不变成废墟、不丢失资源；
- 已提交项目保持结果；
- 当前项目和未提交项目继续持有原批次撤离锁，冻结的退款、基础时长和载荷不改变；
- 当前批次进入 Blocked 并停止计时；
- 玩家可使用 `E` 打开既有背包/城市库存界面，把城市网络物资移入背包以腾出容量，也可使用战术暂停；不能借容量失败自动取消或重建为新和平批次；
- UI 保留失败项目、稳定原因和缺口；玩家点击“重新检查容量”时只用最新仓储 revision 重建当前项目的容量计划，成功后从原 work 继续，不重复已提交退款。

## 10. 撤离锁与跨系统生命周期

### 10.1 单一锁语义

`IsEvacuationLocked` 是唯一共同门。锁定后：

- 生产不开始或推进周期，不自动搬入搬出；内部缓存、预留批次和进度保留；
- 研究站不再满足启动或推进资格；若它是最后一座合格研究站，研究暂停而不取消、不退款；
- 仓库断开城市网络但保留内容和过滤；
- 机枪塔清除目标、停止补弹和射击，保留本地弹药；
- 人工库存转移、单建筑暂停、升级、普通拆除和其他会改变载荷的命令拒绝；
- 建筑仍由会话持有，直到提交成功。

清单仅打开、尚未确认时不加锁，世界继续运行。确认批次后才锁定工作项。

### 10.2 锁快照与回滚

锁快照至少包含：

- 稳定实例 ID、生命周期、所有权、位置、方向和占格；
- 施工剩余比例；
- 生产缓存、活动批次、进度和玩家暂停；
- 塔弹药、目标清除前状态和玩家暂停；
- 仓库内容、过滤和锁定前联网资格；
- 相关 revision。

锁获取失败时，本命令尚未开始的项目按快照恢复，并通过现有资格规则重新计算物流和运行状态，不能盲目写回过期的“已连接”布尔值。确认后的容量不足不是批次回滚：当前及未提交项目保持锁定和原批次上下文，进入 Blocked 等待重新检查。只有控制器销毁、场景退出或 prepare 阶段发生不可继续的配置失败时，才释放未提交锁；已经成功提交的项目不参与恢复。

### 10.3 队列状态机

```text
Idle
  └─ Fortress 中 F 且有玩家外城项目 → ManifestOpen

ManifestOpen
  ├─ assignment 改变 → ManifestOpen（刷新预览）
  ├─ Esc → Idle
  └─ 全部赋值并确认 → CaptureAndLock

CaptureAndLock
  ├─ 失败 → ManifestOpen（无提交）
  ├─ 即时项目容量不足 → Blocked
  └─ 即时项目完成 → FullQueue 或 Resolve

FullQueue
  ├─ 未暂停 → 顺序推进当前完整拆除
  ├─ 暂停 → 保持
  ├─ 当前项容量不足 → Blocked
  └─ 全部完成 → Resolve

Blocked
  ├─ E → 打开既有背包/城市库存并允许玩家腾出网络容量
  ├─ 重新检查仍失败 → Blocked（更新缺口）
  └─ 重新检查成功 → 从原批次当前项继续

Resolve
  ├─ 仍有玩家外城项目 → ManifestOpen
  └─ 无玩家外城项目 → RequestPacking

RequestPacking
  └─ 仅调用一次城市部署 API → Idle
```

已确认队列不支持用户任意取消；这延续 `IDEA-0003` 的稳定单队列语义。玩家仍可使用战术暂停和系统菜单。失败只由规则或事务产生，并按上节恢复。

## 11. 不可变 UI view-model

### 11.1 清单投影

UI 每次接收完整不可变 `EvacuationManifestViewModel`，至少包含：

- view revision、状态和是否处于战斗；
- 当前生产力倍率与和平/战斗规则说明；
- 是否可确认及全局失败原因；
- 按稳定 ID 排序的项目行；
- 分类和全部赋值的只读汇总；
- 最近一次失败项目与容量缺口。

每个项目行至少包含：

- 稳定实例 ID、正式建筑名、类别、施工/完成状态；
- 未完成比例；
- 当前 assignment；
- 预计逐资源退款；
- 预计基础时长和按当前生产力换算的实际时长；
- 将迁移的内部输入、活动批次、输出、塔弹药和仓库内容；
- 遗弃会损失的逐资源明细；
- 当前容量预检结果、逐资源缺口和明确失败原因。

清单预览不是提交保证。UI 必须说明“城市库存仍会变化，提交时重新检查”；不能以绿色预览绕过提交重检。

### 11.2 队列投影

确认后 UI 切换为不可变 `EvacuationQueueViewModel`：

- 批次 ID、冻结的和平/战斗上下文和生产力；
- 已完成数、总数和稳定队列；
- 当前项目、基础总时长、剩余基础秒、显示剩余实际时间；
- 即时项目结果；
- 暂停状态；
- 最近失败、逐资源容量缺口、“使用 E 腾出城市容量”的处理建议和重新检查命令状态。

倒计时只由规则剩余量投影，不由 UI 自减。UI 不持有工作队列，不直接调用 session 提交。

### 11.3 revision 与分配

- 内容未变时复用已缓存 view-model，不发布新 revision。
- 结构行只在清单成员改变时创建或回收；assignment、倒计时和文本变化更新已有行。
- 倒计时文本只在显示精度变化时重新格式化。
- 不在每个渲染帧创建列表、字符串、GameObject、材质或候选快照。

## 12. 正式输入和界面优先级

### 12.1 `F` 路由

`F` 只经过正式 Input System 与现有协调器：

- Mobile：执行部署完整合法性，成功后进入 Deploying；
- Deploying：取消并回到 Mobile；
- Fortress 且无玩家外城资产：进入 Packing；
- Fortress 且有玩家外城资产：保持 Fortress 并打开清单；
- Packing：取消并回到 Fortress；
- ManifestOpen、CaptureAndLock、FullQueue、Blocked：消费 `F`，不透传第二次部署请求。

撤离控制器只在 Fortress 的收起入口拦截；不能复制 Mobile 部署校验或直接写城市 Mode。

### 12.2 暂停、Esc 和其他输入

优先级为：

1. 系统菜单已有模态状态；
2. `Space` 战术暂停；
3. UGUI 键盘焦点和按钮；
4. 撤离清单/队列；
5. E/T/B、世界选择、移动、自动驾驶和镜头。

- `Space` 在清单和队列期间始终可切换战术暂停。
- ManifestOpen 中 `Esc` 取消未确认清单并返回 Fortress；不改变建筑。
- FullQueue 中不允许取消批次；`Esc` 可打开系统菜单，系统菜单暂停规则时间。
- E/T/B、世界选择、驾驶和自动驾驶在撤离模态界面期间不执行；唯一例外是 Blocked 状态允许 `E` 打开既有背包/城市库存以腾出网络容量，关闭后仍返回同一冻结批次。
- UI 按下、拖动、释放不得穿透到世界；关闭界面的同一帧不得继续消费为世界点击。
- 输入框或 UGUI 键盘焦点仍遵循既有焦点隔离。

清单和队列本身不自动暂停生产、研究、敌人或战斗。只有已有战术暂停或系统暂停产生零规则 delta。

## 13. 场景接线与表现

- 正式场景中只允许一个撤离控制器和一个撤离 UI 根。
- 防御运行时以显式引用提供现有 `GrayboxDefenseRuntimeSnapshot3D`；撤离 UI 不引用防御 HUD，也不另建敌情缓存。
- 生产载荷优先从现有生产不可变观察快照投影，塔弹药从现有塔快照投影；若 prepare/commit 需要当前快照尚未公开的内容，只为相应运行时增加按稳定实例 ID 的窄捕获与确定性清除入口，不公开可变内部集合。
- 仓储预检与提交只进入现有 `CityResourceStorageModel`；撤离控制器不拥有 `StoragePlan`，不实现资源路由。
- 城市部署表现继续消费 `CityDeploymentModel.Progress`；正式 `5/8` 秒不在 Animator 或协程重复计时。
- 遗弃继续使用清晰可替换的废墟占位；它没有生产、物流、战斗、回收或前哨表现。
- 场景 authoring 连续运行必须幂等，不重复监听、Canvas、EventSystem、控制器或序列化引用。

## 14. 错误处理与不变量

### 14.1 稳定失败代码

至少区分：

- 城市不在 Fortress；
- 转换进行中；
- 清单项目已变化；
- assignment 未完成；
- 建筑不再归玩家或不在外城；
- 撤离锁冲突；
- 内部载荷已变化；
- 仓库迁移容量不足；
- 退款容量不足；
- 过滤或联网导致不可接收；
- 城市存储 revision 失效且重算后仍失败；
- 城市 Packing 请求失败；
- 配置或引用缺失。

UI 使用稳定失败代码映射中文，不解析异常文字决定行为。prepare 阶段异常必须记录上下文、保持领域状态不变并释放本命令尚未形成批次的临时锁；commit 后的非领域表现异常记录并由会话真值重建，不得吞异常后假装失败或重复提交。

### 14.2 必须始终成立

- 同一资源在撤离前后满足：原网络量 + 建筑载荷 + 应返额 = 成功后网络量；遗弃明确批准的损失除外。
- 完整/快速拆除不是部分成功：资源全部迁移且建筑移除，或资源与建筑均保持。
- 仓库自己的容量不能接收它被移除后才产生的迁移和退款。
- 未提交建筑持有有效占格；已移除建筑不持有占格；废墟始终持有原占格。
- 一个工作项最多提交一次；Packing 请求最多发出一次。
- 冻结批次的退款与计时不随战斗 revision 改变。
- 暂停期间全部规则剩余量保持不变。

## 17. 混合性能与稳定重建

### 17.1 自动性能场景

固定场景至少同时存在：

- `2` 座采矿站、`2` 座冶炼厂、`1` 座装配厂并处于活跃生产；
- `1` 座机枪塔、`8` 名存活啃噬者和防御 HUD；
- 已打开的撤离清单或完整拆除队列；
- 至少 `16` 个外城清单项目，覆盖生产、仓库、研究站、塔、完成和未完成状态。

预热后检查：

- 连续 `300` 次内容和显示精度均未变化的 Tick/快照读取为 `0 B GC Alloc`；
- revision 不变时不创建候选 view-model；
- 清单行、敌人、tracer、建筑表现和 HUD 元素无对象数量增长；
- 不产生运行时材质实例；
- 工作量随相关建筑、敌人和清单项目数量线性增长，不做每项全场扫描；
- 清单构造、容量预检和项目提交分别有独立 Profiler Marker。

活动生产、防御和倒计时允许在固定规则步或显示精度变化时发布有界不可变快照，但不得每个渲染帧重建全部列表。实现计划应以 RED 基线记录一次批次创建和一次提交的实际分配，并设置不高于该线性模型的回归阈值。

### 17.2 GUI Profiler

在正式 `GrayboxPrototype3D`、`1920×1080`、关闭 Deep Profile、完成预热后记录连续 `300` 帧：

- 平均帧时不高于 `16.67 ms`；
- 无持续对象增长或逐帧 GC；
- 能分离观察生产、八敌战斗、防御 HUD、撤离 Tick、view-model 构造、容量预检和提交 Marker；
- 报告平均/最小/最大帧时、GC、SetPass、Draw Calls/Batches、长期对象数和测试机器信息。

开发机 GUI Profiler 不能替代真实 Windows Player 的 GPU、显存、内存和视觉验收。

## 18. schema 30、冻结 2D 与回退

- schema 固定为 `30`。
- 城市转换中间态、撤离清单、批次、锁、内部载荷、仓库、塔弹药、背包、生产和研究仍为 3D 会话态。
- 不修改保存 codec，不把新字段塞入旧 schema，不承诺中途退出后恢复。
- 退出当前 3D 会话继续使用既有“不保存”提示。
- `FormalPrototype` 只运行既有回归，不接 `F` 新语义、撤离 UI、仓库事务或战斗上下文。
- 若实现发生不可安全修复的问题，优先回退新策略、view-model 与事务适配，恢复到 IDEA-0003 已验证结构；不得损坏现有建筑、生产、仓储和防御真值。

## 19. 明确排除项

本阶段不制作：

- 正式 3D 存档适配、schema 修改或旧存档迁移；
- 前哨、远程仓储、前哨视野、防御、通信或运输；
- 迷雾、多城市和跨城市运输；
- 新资源、电力、传送带、具体工人或运输单位；
- 新敌人、新炮塔、新波次、敌人掉落、尸体和弹丸命中真值；
- 建筑或城墙受伤、维修和敌人建筑寻路；
- 领袖战斗、碾压、正式失败结算或核心摧毁后的完整流程；
- 完成建筑的常规非撤离拆除入口；
- 可折叠、不可折叠、可回收与规则批处理标签；
- 批量正式美术、动画、特效和音频；
- 冻结 2D 新功能；
- Release、PR 合并或自动发布。

当前遗弃物只是无功能、失去所有权且继续占格的废墟，绝不能称作前哨。

## 20. 完成定义
