# BUG-0006 / IDEA-0012 建造、仓储与资源可读性设计

## 1. 状态与边界

- 用户于 2026-08-18 在最终 macOS Player 试玩后提出反馈，并明确批准规则摘要。
- 稳定需求：`BUG-0006`、`IDEA-0012`；关联 `IDEA-0003`、`IDEA-0006`、`IDEA-0010`、`IDEA-0011`。
- Unity `2022.3.62f1`；默认正式入口仍为 `GrayboxPrototype3D`。
- schema 保持 `30`；新增仓库内容和过滤为 3D 会话态；冻结 2D 不接线。
- 不进入敌人、炮塔、弹丸、电力、传送带、跨城市运输或正式存档迁移。

## 2. 已确认的当前事实

### 2.1 旋转与预览

`R` 的正式输入、`BuildingOrientationRules` 和矩形 footprint 交换已经存在。实际故障位于 3D 表现层：预览与落地实例没有应用方向 yaw，方形建筑旋转无视觉变化；预览只是使用不透明 `GrayboxLit` 的红绿占地块，没有可辨认的建筑形体或朝向箭头。

修复只消费统一方向和放置评估：同一指针锚点保持不变，模型、旋转后 footprint、方向箭头和合法性同帧刷新。预览使用独立透明共享材质，不修改世界共用的 `GrayboxLit`。

### 2.2 石料节点与图标

seed `8128` 的既有 `32×24` 内容区已经确定性包含石料节点；扩展到 `64×48` 后只发生坐标平移，外圈仍无资源。玩家看不到石料的根因是当前世界资源只画贴地小色块，没有图标、名称和储量。另一个真实缺口是统一采矿兼容规则当前只接受铁矿和能晶，石料节点不能放置采矿站或完成采集。

因此不改 `WorldMapModel` 生成算法、不补重复节点；测试锁定既有近出生区石料点及稳定映射。统一兼容规则增加石料，生产继续通过 `WorldMapModel.Harvest` 取得真实类型和储量。

### 2.3 仓库

当前仓库没有库存，只贡献 `ActiveWarehouseCount`；城市全部物资存在一份平面 `ResourceInventory`，观察快照发布单一 `CityCapacityPerResource`。这无法真实显示“仓库里存了什么”，也无法表达共享总容量或过滤。

新增会话级 `CityResourceStorageModel`：

- 城市核心：继续使用按资源独立 `150` 容量的 `ResourceInventory`；
- 仓库：按稳定建筑实例 ID 持有 `WarehouseStorageState`，跨全部资源共享总容量 `150`；
- 过滤：`null` 表示不限，否则为一个正式资源稳定 ID；过滤只限制后续入库；
- 联网：仓库断网保留内容和过滤，但不参与城市网络的消费、接收或可用容量；重连恢复；
- 生命周期：未完成、非玩家所有或撤离锁定仓库不参与网络。非空仓库进入会导致物资丢失的移除/撤离步骤时，先尝试原子迁移到其余网络存储，容不下则拒绝并提示先清空；
- 路由：添加优先匹配过滤仓，再按稳定 ID 使用不限仓，最后城市核心；扣除优先城市核心，再按稳定 ID 使用匹配过滤仓和不限仓；批量事务先完整预检再提交；
- 快照：UI 只读不可变聚合快照；命令只传稳定实例 ID 和资源 ID，提交时重新验证容量、过滤、联网与访问资格。

某资源 HUD 容量显示为“当前网络中该资源总量 + 当前网络还能接收该资源的空间”。共享空位不能同时作为 15 种资源的独立已占容量承诺；实际写入时统一模型再次验证。

## 3. 统一资源图标

`ResourceDefinitionCatalog` 是 15 种资源稳定 ID、正式名称和 `IconFallbackKey` 的唯一语义入口。新增可复用 `ResourceIconCatalog3D`，按稳定 ID 返回同一图标表现：

- 世界节点浮标：图标、名称、`WorldMapModel` 剩余储量；
- 顶部资源栏与完整账本；
- 背包格、合成输入/输出、仓库内容；
- 科技和建造成本；
- 生产详情输入/输出。

首轮图标为清晰可替换的程序化占位资产，稳定映射与色形组合不能只靠颜色区分。世界浮标面向相机并复用稳定对象，不为每帧创建 GameObject、材质、字符串或 Sprite。

## 4. 精确缺料

新增规则层缺口值对象，由正式成本列表和当前可访问城市网络快照计算：资源 ID、拥有量、需要量、缺少量。放置预览和点击确认共用同一格式化结果，例如：

`无法建造冶炼厂：缺少石料 6（拥有 0，需要 6）`

多资源成本按正式配置顺序逐项显示。UI 不复制建筑成本、仓库内容或库存计算；确认时必须重新评估，避免使用过期预览。

## 5. 测试与性能

必须先保留 RED，再做最小实现：

1. 方形与矩形建筑四方向真实 `R` 输入；锚点、模型、footprint、箭头、合法性和提交实例一致；
2. 独立透明预览材质、稳定预览对象和 UI 输入隔离；
3. 仓库共享 150、真实内容、不限/单资源过滤、非空不兼容切换拒绝、确定性路由、批量原子回滚和总量守恒；
4. 断网/重连、完成/所有权/撤离锁定和非空移除零丢失；
5. 生产、背包、研究、建造和退款都经城市存储聚合边界；
6. seed `8128` 既有石料点、三类采矿兼容、真实 `Harvest` 与节点枯竭；
7. 15 资源图标映射唯一，世界浮标和全部材料 UI 使用同一目录；
8. 逐项缺料在预览和真实点击路径可见；
9. 静止快照、预览与浮标连续 300 次无对象增长；内容未变时不产生新 revision 或候选快照。

完成时运行聚焦 EditMode/PlayMode、日常完整 EditMode（不触发 TerrainAssetDeep）、完整 PlayMode、项目质量门、四个正式构建、macOS Player 冒烟、官方文档生成/校验和 `RecordVerification`。用户人工试玩与真实 Windows 机器结论仍由用户确认。
