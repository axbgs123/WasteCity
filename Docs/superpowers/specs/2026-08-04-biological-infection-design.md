# 血肉感染与孢子寄生闭环设计

## 目标

完成正式路线图 F1 的第二个里程碑：让所有对敌方造成的生物伤害附加感染，使孢子塔的“孢子寄生”、酸液塔和巨兽攻击共享同一套持续伤害、叠层爆发、范围传播、存档与占位表现规则。

本里程碑严格采用主 GDD 的核心数值：

- 生物伤害命中后附加 `1` 层感染；
- 感染存在时每秒造成目标最大生命值 `2%` 的生物伤害；
- 感染以 `10` 层为爆发阈值；
- 达到 `10` 层时爆发，周围 `3` 个世界单位内的敌方单位获得 `5` 层感染。

## 状态规则

- 感染只作用于存活、未被精神控制的敌方单位。
- 只有实际造成了大于 `0` 的生物伤害才附加层数；缺少弹药、目标已死亡或本次伤害为 `0` 时不附加。
- 每次直接生物伤害附加 `1` 层，孢子塔、酸液塔和巨兽没有各自独立的感染版本。
- 现有战斗以连续 DPS 而不是离散弹丸模拟命中，因此同一个攻击来源最多每 `1` 秒附加 `1` 层。伤害仍按每帧结算，感染附加使用独立的一秒命中节奏；首次有效生物伤害立即附加。
- 感染持续存在，直到目标死亡、被精神控制或感染爆发后清零。主 GDD 未规定自然衰减，因此本里程碑不添加衰减时间。
- 每满 `1` 秒结算一次持续伤害。单次原始伤害为 `max(1, ceil(目标最大生命 × 0.02))`，再按现有生物伤害与护甲矩阵、护盾规则结算。
- 达到 `10` 层时，本体感染层数清零，然后向半径 `3` 内的其他存活敌方单位传播 `5` 层。
- 传播得到的层数继续遵守 `10` 层爆发规则。一次传播链中，同一目标最多爆发一次，防止相邻目标互相反复触发形成无限循环。
- 精神控制成功时立即清除感染及计时，不把敌方寄生伤害带到友军状态。

## 结构

### `InfectionModel`

普通 C# 状态模型，负责：

- 当前感染层数；
- 一秒结算时钟；
- 接收层数并报告是否达到爆发阈值；
- 计算本次持续伤害的原始值；
- 爆发后清零；
- 捕获和恢复层数与计时。

该模型不访问 Unity 场景、不查找敌人、不直接修改生命值。

### `InfectionSpreadRules`

普通 C# 纯规则，输入爆发位置、传播半径和候选单位，输出应获得传播层数的目标 ID。规则负责排除：

- 爆发本体；
- 死亡单位；
- 已被精神控制的单位；
- 半径外单位。

范围按二维世界坐标的欧氏距离计算。

### `InfectionEmitterModel`

普通 C# 命中节奏模型，负责把连续 DPS 转换为感染附加事件：

- 首次有效生物伤害立即返回一次附加事件；
- 此后同一来源每满 `1` 秒最多返回一次；
- 没有实际伤害的帧不会附加感染；
- 孢子塔、酸液塔和巨兽各自持有独立实例。

### `EnemyInfectionStatus`

挂载在敌人对象上的运行时适配组件，负责：

- 持有 `InfectionModel`；
- 每帧推进模型，并把到期伤害交给现有 `HealthModel`；
- 通过 `PlaceholderEnemy` 暴露统一的感染入口；
- 爆发时根据 `InfectionSpreadRules` 找到附近目标；
- 用传播上下文限制同一目标在一次传播链中只爆发一次；
- 在死亡或心控后停止并清除状态；
- 同步占位表现。

`HealthModel` 和 `DamageMatrix` 保持通用，不保存路线专属状态。

### 生物伤害入口

- `PlaceholderTurret` 在孢子塔或酸液塔实际造成生物伤害后，对目标附加 `1` 层。
- `FriendlyUnitAgent` 在巨兽实际造成生物伤害后，对目标附加 `1` 层。
- 感染的每秒持续伤害不再次附加感染，避免自我叠层。
- 后续新增生物武器必须复用同一感染入口。

## 表现资源

- 感染目标显示程序化孢子环占位符，稳定 ID 为 `biological.status.infection`。
- 占位符随层数增加调整缩放和透明度，爆发后隐藏。
- 孢子塔、酸液塔和巨兽继续使用原有稳定 ID，不把感染逻辑放入美术 Prefab。
- 正式 Sprite、粒子或未来 3D 特效可通过 `VisualSlot` 替换，不修改感染规则。

## 存档

存档 schema 从 `24` 升至 `25`。每个 `EnemySnapshot` 新增：

- 感染层数；
- 距离下一次持续伤害结算的累计时间。

加载规则：

- schema `25` 恢复感染层数与计时；
- schema `24` 及更旧存档默认无感染；
- 已被精神控制的敌人即使输入快照含感染，也恢复为无感染；
- 存档中的层数归一化到 `0..9`，累计时间归一化到 `0..1` 秒以内；有效运行时状态不会停留在 `10` 层。

## 测试与验收

1. 先写 `InfectionModel` 与 `InfectionSpreadRules` 的失败测试，确认叠层、每秒伤害、爆发清零、半径边界和过滤规则。
2. 增加运行时测试，证明孢子塔、酸液塔和巨兽的实际生物伤害都会附加感染。
3. 增加运行时测试，证明爆发传播、稳定表现 ID 和心控清除行为。
4. 增加 schema `25` 往返与 schema `24` 默认迁移测试。
5. 运行全部 EditMode、PlayMode、无界面编译和 Windows 64 位构建。
6. 当前 macOS 开发机不安装 Windows 兼容层；Windows 独立程序冒烟继续明确标记为待真实 Windows 10/11 环境补验，补验前不作为候选发布版。
7. 更新路线图的基线提交、测试数量、schema 和完成状态。

## 非目标

- 不实现敌方对玩家建筑或友军施加感染。
- 不增加感染抗性、净化、研究强化或命轨破格。
- 不调整孢子塔、酸液塔和巨兽的基础伤害、射程、攻速或消耗。
- 不制作正式美术、动画和音频。
- 不实现血肉路线其他建筑、危机轨道或跨路线桥节点。
