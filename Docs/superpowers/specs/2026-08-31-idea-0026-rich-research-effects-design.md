# IDEA-0026 复合科技效果与可观察研究设计

## 目标

科技节点不再只是内容解锁。每个正式节点同时表达其内容、数值、规则、条件或代价；已经可以自然研究的节点至少拥有一项真实运行效果，玩家能在研究前看到基线值与研究后值，在完成、读档和开发修改器解锁后看到同一结果。

本阶段保持 44 个稳定科技 ID、49 条前置边、6 个桥节点、现有地图和 schema `34`。所有无状态效果只由“已完成科技 ID 集合”确定性派生，不保存 UI 快照或重复的 applied 标志。

## 参考结论

- Mindustry 将依赖、成本和目标作为节点规则，而不是由界面文案决定解锁。
- Unciv 以可组合的 uniques 表达科技能力和条件。
- Freeciv 以稳定规则名、效果值、作用范围和需求定义可叠加效果。

WasteCity 采用相同的所有权原则，但不复制第三方代码、美术、名称、数值或布局，也不引入第三方依赖。

## 数据所有权

`ResearchCatalog` 继续拥有科技身份、路线、成本、时长、前置和发布状态。新增 `ResearchEffectCatalog`，用稳定 effect ID 定义：

- 所属研究 ID；
- 类别：解锁、被动、规则、条件、代价；
- 效果种类、目标和操作；
- 数值、单位、基线、作用范围和叠加规则；
- `Executable` 或 `Preview` 接线状态；
- 玩家可见名称和简短说明。

`ResearchEffectResolver` 只读取已完成科技集合，生成不可变快照。生产、物流、战斗、研究、军队和 UI 只消费各自需要的窄查询；界面不得解析中文说明成为玩法真值。原 `EffectSummary` 保留为兼容回退，`EffectReferences` 保留为内容索引和审计引用。

## 可研究性修复

`剑阵初解` 从 `PreviewOnly` 调整为 `Researchable`。它已有正式剑阵塔目录、战斗系统和稳定前置，本次开放用于修复“御剑术在文明 Lv.2 显示开放但天然前置永远不可达”的稳定阻断。其余 PreviewOnly 节点不因拥有设计效果而自动开放。

## 运行时接入顺序

1. 类型化目录、完整性门、纯解析器和读档等价。
2. 生产周期/产量、研究速度、物流半径、建筑耐久、塔射程/伤害/攻击间隔。
3. 既有代谢、再生、预警、桥节点和多城市规则的真实消费点。
4. 科技树详情、节点标签、完成反馈和 Development 管理台。

需要临时特质、持续减益、护盾层或一次性奖励的效果保持 Preview，不在本阶段创建未保存的权威状态。

所有整数批量生产的百分比增益都通过周期缩短表达等价的单位时间吞吐，单批投入和单批产量不变。这样不需要保存小数余数或完成序号，保存恢复前后完全等价。

## UI

保留 IDEA-0024 的顶部筛选—四路线树—底部详情结构。节点增加短标签：`解锁/被动/规则/条件/代价`。详情展示多行结构化效果，例如：

`[被动] 研究效率 100% → 125%`

并显示作用范围、触发方式、叠加规则以及 `已生效/研究后生效/仅预览`。预览效果绝不能显示为已生效。研究完成和管理台精确解锁后立即重算详情。

## 验收

- 44 个节点均有类型化效果定义；稳定 effect ID 唯一，数值、单位、范围、叠加和接线状态完整。
- 1 个初始完成与所有自然 Researchable 节点至少有一项可执行非纯解锁效果；PreviewOnly 效果明确标为预览。
- 完成集合顺序无关、重复输入幂等；保存恢复前后快照相同；schema 保持 `34`。
- 生产、研究、物流、耐久和战斗至少各有真实运行时验证。
- PlayMode 通过真实 `T`、搜索、节点点击、开始/完成研究和 `0` 管理台验证，不直接调用内部 UI 方法。
- 日常完整 EditMode、完整 PlayMode、质量目录、官方文档生成/校验和现役构建完成后才可记为自动化通过；人工试玩和真实 Windows 继续由用户/真机确认。
