## 1. 目标与阶段边界

本阶段只扩展默认正式 3D 主循环，形成玩家能建造、观察和操作的第一条生产闭环：

1. 采矿站从已绑定的世界资源节点采集，并把产物放入自己的输出缓存；
2. 冶炼厂和装配厂通过城市物流访问城市库存及其它联网建筑缓存；
3. 每座建筑独立显示周期、输入、输出、物流状态和主停工原因；
4. 玩家按 `E` 打开 12 格背包，通过真实指针在已选择建筑缓存与背包之间双向拖拽；
5. 为铁矿、合金、弹药、石材、生物质、能晶和水提供统一资源图标，为五类世界资源节点提供清晰、可替换的占位表现；
6. 仓库扩大城市资源容量，但不延长物流距离。

本阶段不开发敌人、炮塔、弹丸、电力、传送带、工人、相邻共享、建筑链式中继、跨城市运输、新资源或正式存档迁移。冻结的 2D `FormalPrototype` 不增加功能、UI 或场景接线；共享代码只保留必要回归保护。schema 保持 `30`。

## 2. 已批准玩法合同

### 2.1 配方、容量与速度

| 建筑 | 输入缓存 | 输出缓存 | 基础周期 | 周期结果 |
|---|---:|---:|---:|---|
| 采矿站 | 无 | 绑定节点资源 20 | 3 秒 | 从节点采 1 单位 |
| 冶炼厂 | 铁矿 20 | 合金 10 | 6 秒 | 2 铁矿 → 1 合金 |
| 装配厂 | 合金 20 | 弹药 30 | 6 秒 | 2 合金 → 2 弹药 |

基础周期必须来自正式配置。有效推进量统一为：

```text
规则时间 × CityOperationalRules.ProductionMultiplier(cityMode)
```

要塞的现有生产倍率 `1.25` 必须继续生效；新控制器不得重新声明、隐藏覆盖或绕开该值。全局暂停使规则时间为零；建筑手动暂停只冻结该建筑。

### 2.2 节点兼容与枯竭

- `BuildingCatalog.MiningStation` 稳定 ID 不变；
- `BuildingResourceNodeCompatibilityRules` 继续是唯一兼容性真值；
- `IDEA-0010` 已验证的铁矿和能晶兼容关系完整保留；
- 采矿站每 3 秒从其绑定节点采集 1 单位节点资源，因此能晶节点产出能晶，铁矿节点产出铁矿；
- 首批完整消费链和产销验收只覆盖铁矿 → 合金 → 弹药；能晶本轮只有采集、缓存、背包与占位表现；
- 类型、坐标和余量始终由 `WorldMapModel` 唯一持有，完成周期时只能通过 `WorldMapModel.Harvest` 扣减；
- 节点余量为零时显示“矿脉已枯竭”，不得改成新资源或重新生成节点。

节点稳定身份必须由放置、高亮和生产共同消费一套创建/解析规则。生产实例在施工请求通过时保存兼容节点 ID；不得在完成后重新选择邻近节点。

### 2.3 建筑缓存与生产原子性

- 每座生产建筑独立拥有输入缓存、输出缓存、周期进度、活动周期、节点绑定、手动暂停和停工原因；
- 产物先进入来源建筑输出缓存，不自动搬到城市库存；
- 周期开始时原子检查输出空间和输入，并一次性扣除本地输入；完成时才写入输出；
- 采矿在完成周期时才调用 `Harvest`，节点扣减与缓存增加必须作为一次受控操作处理；
- 缓存不得使用负债，不允许错误资源 ID，不允许溢出、复制或静默丢失；
- 取消施工不创建缓存；撤离锁定、废弃或移除后立即停止生产且不能继续作为物流来源。

`ResourceInventory` 可作为缓存的底层计数器，但必须由限制资源 ID、容量和原子转移的 3D 缓存包装器封装，UI 不得取得可任意 `Restore` 或设置负债的接口。

### 2.4 物流连接与访问

物流连接是派生状态，不保存第二份真值：

- 内城玩家建筑随城市接入；
- 地面建筑只有在城市为 `Fortress` 且完整 footprint 逐格通过 `BuildingRangeRules.IsGroundCellInRange` 时接入；
- 不要求相邻，建筑之间不能中继或扩展范围；
- 联网消费者可以从城市库存和其它联网建筑输出缓存获得配方输入；
- 来源缓存优先于城市库存，来源按稳定实例 ID 排序，保证结果可复现；
- 同资源消费者采用逐单位轮询，避免第一座冶炼厂填满 20 而长期饿死第二座；
- 脱离物流后保留缓存，可完成已经开始的周期并继续消费本地输入；采矿可继续到节点枯竭或输出满；
- 脱离期间不得访问城市库存或其它建筑缓存；重新连接后自动恢复访问。

当联网但全网缺料时显示“缺少输入”；当本地缺料且唯一阻断是断网时显示“不在物流范围”。采矿站不因断网直接停工。

### 2.5 仓库容量

- 正式城市基础容量沿用 GDD 的每资源 `150`；
- 每座已完成、玩家拥有且未锁定撤离的仓库为每种城市资源增加 `150`；
- 仓库不修改 `GroundBuildRadius` 或任何物流范围；
- 容量降低不得调用会截断现有数量的路径静默销毁资源；若移除仓库会使城市库存超过新上限，首版应拒绝该次移除并显示原因；
- 3D Development 修改器可继续提供测试资源，但不得把开发容量写成正式玩法配置。

### 2.6 玩家背包与拖拽

- 背包固定 12 格，每格最多 99 个同类资源；
- 空格可接受任意已登记资源；同类优先合并，剩余数量按稳定格序放入空格；
- `E` 在无更高优先级文本输入时打开或关闭背包；
- 背包打开时阻止相机拖拽、建造确认和世界点击穿透，但不自动暂停生产；
- 选中已完成、玩家拥有、未锁定撤离的建筑后显示其输入与输出缓存；
- 允许“建筑输入/输出缓存 ↔ 背包”双向拖拽；建筑端仍必须遵守允许资源和容量；
- 一次拖拽是原子事务：先计算目标可接受量，再从来源扣除，目标写入失败时恢复来源；
- 左键拖动整堆，右键或修饰键拆分不是首批要求；部分接收允许，但 UI 必须显示实际移动数量和未移动原因；
- 建筑在拖拽期间失效、被锁定或不再归玩家时，事务失败且物品保持原位。

背包和建筑运行态本阶段都是会话态，不读写 `FormalSaveData`、`SaveService` 或任何 schema 字段。

### 2.7 停工原因

玩家可见主原因固定为：

1. 玩家暂停运行；
2. 矿脉已枯竭；
3. 输出已满；
4. 不在物流范围；
5. 缺少输入。

只有真正阻止推进的原因才显示。全局战术暂停或系统菜单暂停只冻结规则时间，不覆盖建筑原有原因。运行中显示周期进度和预计基础/有效周期，不伪装成停工原因。

## 3. 领域所有权与程序集边界

### 3.1 单一真值

| 领域 | 权威所有者 | 禁止做法 |
|---|---|---|
| 建筑身份 | `BuildingCatalog` 稳定 ID | 新建同名 ID 或按中文名判断 |
| 配方与容量 | 新 3D 生产配置目录 | 控制器/UI 散落数字 |
| 节点 | `WorldMapModel` | 缓存第二份余量 |
| 节点兼容 | `BuildingResourceNodeCompatibilityRules` | 生产另写铁矿/能晶判断 |
| 放置与施工 | 现有 3D session 和 evaluation | 生产绕过统一放置 |
| 城市倍率 | `CityOperationalRules` | 新增 1.25 常量 |
| 物流范围 | 城市模式、中心与 `BuildingRangeRules` | 复用 2D BFS 物流网络 |
| 城市资源 | `ResourceInventory` | UI 直接改字典 |
| 建筑缓存 | 每个 `GrayboxBuildingInstance3D` 的生产态 | 按建筑类型共享进度 |
| 背包 | 3D 会话背包模型 | 写入 schema 30 |

### 3.2 推荐类型

纯领域层：

- `GrayboxProductionDefinition3D`：稳定建筑 ID、种类、配方、周期、输入/输出容量；
- `GrayboxProductionCatalog3D`：首批三座建筑的唯一配置；
- `GrayboxBuildingCache3D`：限制资源与容量的缓存包装器；
- `GrayboxBuildingProductionState3D`：每实例进度、活动周期、暂停、原因和节点绑定；
- `GrayboxProductionSimulation3D`：事件式周期推进、物流轮询和停工原因；
- `GrayboxPlayerInventory3D`：12 格、99 堆叠和确定性装入；
- `GrayboxInventoryTransfer3D`：缓存与背包之间的原子事务；
- `GrayboxResourcePresentationCatalog3D`：资源显示名、图标地址、颜色与统一回退；
- `GrayboxResourceNodeIdentity3D`：节点稳定 ID 创建和解析。

Unity 接线层：

- `GrayboxProductionController3D`：从正式世界、城市、session 和规则时间构造 tick context；
- `GrayboxInventoryView3D`：背包、建筑缓存、拖拽和反馈；
- 现有 `GrayboxBuildingMenuView3D` 扩展完成建筑详情，不成为库存真值；
- 现有输入协调器增加 inventory modal，保持 Esc/system menu 优先级和点击防穿透；
- `GrayboxSceneAuthoring` 创建稳定对象、组件和引用，正式场景由 authoring 生成并冻结合同。

## 4. 确定性生产算法

简单按实例列表逐帧 tick 会使放置顺序和帧长改变产量，因此使用事件边界推进：

1. 过滤完成、玩家拥有、未撤离锁定、符合 `BuildingMobilityRules.CanOperate` 的实例；
2. 计算本帧规则时间，再乘 `CityOperationalRules.ProductionMultiplier`；
3. 在当前时间点泵送物流，并按稳定 ID/轮询游标分配可访问资源；
4. 对可启动建筑原子扣除一轮输入并标记活动周期；
5. 推进到最近一个周期完成边界；
6. 同一边界固定按采矿、冶炼、装配顺序结算一次，再重新泵送物流；
7. 重复直至消费完本帧规则时间；阻断建筑不积累无限待结算周期；
8. 对循环次数设置高但有限的安全上限，非法零周期配置在构造时拒绝。

必须证明 `Tick(12)` 与十二次 `Tick(1)` 的缓存、节点余量、完成周期和原因一致；打乱实例集合顺序也必须一致。

## 5. 资源占位表现与 AI 资产治理

资源图标统一位于项目质量目录覆盖的 3D UI 资源目录；世界节点占位表现继续读取 `WorldMapModel`，不得由 Renderer 反向决定资源类型。

图标集合：铁矿、合金、弹药、石材、生物质、能晶、水。世界节点集合：铁矿、能晶、石材、生物质、水。

视觉要求：

- 统一正交或轻微俯视角、透明背景、清晰外轮廓和工业废土配色；
- 64×64 UI 下仍可区分，不能依赖小字；
- 世界节点使用低成本占位几何/材质，保持现有批处理和对象复用约束；
- 缺图统一落到中性资源箱图标，不能出现空引用或粉色材质；
- AI 生成源和最终切图分离，Unity 最终图必须检查 alpha、尺寸、压缩和 mipmap 策略；
- 在开发参考文档记录模型/工具、完整提示词、生成日期、后期处理、源文件和最终 Unity 路径；AI 资产不代表人工美术验收。

## 6. UI 与真实输入合同

完成建筑选择需复用现有稳定 collider/实例 ID；施工中选择和撤离语义保持不变。详情至少显示：

- 建筑名、配方、基础周期、城市倍率后的有效周期；
- 输入/输出缓存数量和容量；
- 当前进度；
- 物流已连接/已脱离；
- 运行/五类停工原因；
- 手动暂停/恢复按钮。

真实输入优先级建议：系统菜单 > 拖拽中的背包 > 背包面板 > 撤离/建造模态 > 世界操作。`E` 不得在文本输入焦点或系统菜单打开时穿透。关闭背包时取消拖拽，不移动物品。

## 7. 性能、重建与失败安全

- 正常 tick 不使用 `FindObjectsOfType`、LINQ 或逐帧临时集合；
- 缓存只在实例创建时分配；只读快照和 UI 文本按 revision 更新；
- 世界节点枯竭只刷新受影响节点表现；
- authoring 连续运行两次必须字节稳定，场景不累积对象、材质或 EventSystem；
- 生产、物流和背包事务出现异常时不应部分扣除资源；
- 场景引用缺失时给出明确诊断，不回退到冻结 2D 控制器；
- 不修改地形源图、importer、Texture2DArray Builder 或数组，因此日常验证排除 `TerrainAssetDeep`。

## 8. 验证门

实施必须先 RED 后 GREEN，至少覆盖：

- 正式配置、稳定 ID、铁矿/能晶节点兼容与节点绑定；
- 每实例独立周期、城市倍率、分帧确定性和顺序确定性；
- 内部容量、原子消费、物流公平分配、脱离和重连；
- 仓库扩容但不扩距，容量降低不丢资源；
- 节点枯竭、输出已满、缺料、脱离物流、建筑暂停和全局暂停；
- 12×99 背包、堆叠、部分接收、双向拖拽无丢失无复制；
- 正式 3D 真实 `E`、鼠标选择和拖拽；
- 场景合同、重复 authoring、性能和稳定对象数量；
- 正式资源图标、回退和 AI 来源记录；
- schema 仍为 `30`，Persistence 无字段变化；
- 日常完整 EditMode、完整 PlayMode、无界面编译及要求的平台构建。

自动化、构建和截图不能替代用户对资源图标、布局、拖拽手感和生产可读性的人工验收。
