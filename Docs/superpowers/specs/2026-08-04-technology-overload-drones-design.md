# 科技过载与无人系统闭环设计

## 目标

完成正式路线图 F1 的“科技过载与无人机”里程碑，同时保持主 GDD 已经分别定义的岑烬角色技能与科技路线机制：

- 岑烬“强制过载”继续使用健康 `1.75×`、受伤 `1.35×` 的角色数值；
- 科技路线过载使用 `2×` 攻速、能量伤害 `+30%`、持续 `5` 秒、过热停火 `3` 秒、冷却 `30` 秒；
- “无人系统”研究通过自动维修机甲站部署侦查无人机，并复用现有维修脉冲作为自动维修机甲的玩法效果；
- 所有新增表现使用程序化占位符和稳定 `VisualSlot` ID，后续可替换为正式 2D 或 3D 资源。

## 文档冲突与最小推断

主 GDD 同时给出了两套不同数值的过载。角色章节的数值只描述岑烬，路线机制章节描述科技路线，因此不覆盖其中任何一套，而是让它们共享底层修正接口。

科技树没有独立“过载”节点。科技过载包含能量伤害加成，因此由已有 T3“能量武器”节点解锁；无人机由已有 T3“无人系统”节点解锁。此映射不新增第 44 个研究节点，不改变既有 43 节点树。

GDD 没有规定无人机制造配方、容量或手动命令。为避免发明新资源链，本里程碑把每座已完成且接入物流的自动维修机甲站作为一个无人系统部署槽。

## 科技过载规则

新增普通 C# `TechnologyOverloadModel`：

- 未解锁时不能激活；
- 激活后进入 `Boosting`，持续 `5` 秒；
- `Boosting` 时科技过载攻速倍率为 `2.0`；
- `Boosting` 时只有 `DamageType.Energy` 获得 `1.3` 伤害倍率；
- 增益结束立即进入 `Lockout`，持续 `3` 秒，炮塔攻速倍率为 `0`；
- 总冷却从激活时开始计算，共 `30` 秒；
- 冷却或过热时不能再次激活；
- 时间输入按非负值处理，跨阶段的大步长更新时间必须正确消耗剩余时间；
- 模型可以保存并恢复冷却、增益和过热剩余时间。

新增运行时 `FormalTechnologyRouteController`：

- 引用 `ResearchController` 和 `FormalLeaderController`；
- 只有完成 `core.research.energy-weapons` 后，玩家按 `T` 才能激活科技过载；
- 提供统一炮塔战斗修正接口和简短状态 UI；
- 没有正式特效时显示稳定 ID 为 `technology.status.overload` 的程序化环形占位符。

## 与岑烬过载的组合

炮塔不直接依赖某一个具体技能，改为读取统一的战斗修正源：

- 没有增益时攻速倍率 `1`；
- 只有岑烬增益时使用岑烬当前倍率；
- 只有科技增益时使用 `2`；
- 两个增益同时存在时取更大的攻速倍率，不相乘；
- 任一来源处于过热停火阶段时，最终攻速倍率为 `0`；
- 能量伤害 `+30%` 只来自科技过载的增益阶段；
- 物理、生物、真元和灵能伤害不获得科技过载伤害加成。

这样保留角色章节的救援差异，也满足路线章节的精确数值，不制造 `1.75×2` 的异常倍率。

## 无人系统规则

### 部署条件

每座满足以下条件的自动维修机甲站提供一个无人系统：

- 建造完成；
- 物流已连接；
- “无人系统”研究已经完成。

条件失效时对应无人机停用；条件恢复时重新启用。无人机数量由建筑状态派生，不单独消耗或保存。

### 侦查无人机

`PlaceholderScoutDrone` 负责运行时巡航：

- 围绕移动城市进行确定性圆周巡航；
- 多座机甲站使用不同相位，避免完全重叠；
- 每秒在当前位置揭示半径 `2` 的世界格；
- 城市移动时巡航中心随城市更新；
- 不参加战斗、不接受集结点命令，也不引入尚未定义的维护费；
- 稳定表现 ID 为 `technology.unit.scout-drone`。

迷雾状态已经由现有世界存档保存，因此无人机自身相位不写入存档；读档后重新从确定性相位开始不会丢失已侦查区域。

### 自动维修机甲

保留现有自动维修机甲站玩法：每 `6` 秒修复半径 `6` 内已完成建筑 `20` 点生命。新增一个围绕机甲站移动的占位表现，稳定 ID 为 `technology.unit.repair-mech`。该表现不承载生命、修复数值或存档状态。

## 运行时接线

- `PlaceholderBuildingController` 将统一炮塔战斗修正源传给所有新建和已恢复的炮塔；
- `PlaceholderTurret` 在计算射击时间时读取攻速倍率，在结算能量伤害时读取能量倍率；
- `PlaceholderAutomatedRepairBay` 负责维修机甲占位表现，并把侦查无人机委托给科技路线控制器管理；
- `FormalProjectSetup` 在生成正式场景时创建科技路线控制器并连接研究、世界、城市、建筑、领袖和存档；
- 现有正式场景同步加入相同组件和序列化引用。

## 存档

存档升级为 schema `26`，新增：

- 科技过载冷却剩余时间；
- 科技过载增益剩余时间；
- 科技过载过热剩余时间。

兼容规则：

- schema `26` 恢复科技过载状态；
- schema `25` 及更旧存档默认科技过载就绪；
- 未完成“能量武器”的存档即使包含异常过载计时，也恢复为就绪；
- 无人机从研究和机甲站状态重新派生，不增加快照；
- 世界迷雾继续使用已有 `worldRevealed` 数据。

## 测试与验收

1. EditMode 测试覆盖过载阶段、精确倍率、能量伤害限定、组合优先级、未解锁拒绝和状态恢复。
2. EditMode 测试覆盖无人系统部署计数、失去物流时停用和确定性巡航位置。
3. PlayMode 测试证明科技过载让激光塔获得 `2×` 射速和 `1.3×` 能量伤害，过热阶段停火，物理塔不获得伤害倍率。
4. PlayMode 测试证明无人系统研究与维修站共同生成稳定占位槽，并能揭开远离城市的迷雾。
5. 存档测试证明 schema `26` 往返过载计时，schema `25` 默认为就绪。
6. 运行全部 EditMode、PlayMode、无界面编译和 Windows 64 位构建。
7. 真实 Windows 10/11 独立程序冒烟继续标记为待补；通过前不得作为候选发布版。

## 非目标

- 不增加无人机制造资源、维护费、生命、武器或手动指挥。
- 不实现多城市无人机运输。
- 不把自动维修机甲改造成可选择的战斗单位。
- 不让岑烬与科技过载的攻速倍率相乘。
- 不实现“过载无过热”命轨破格；等待命轨对应里程碑。
- 不导入正式美术、模型、动画或音频。
