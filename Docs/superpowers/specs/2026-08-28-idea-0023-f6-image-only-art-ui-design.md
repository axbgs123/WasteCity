# IDEA-0023 F6 贴图替代建模与三面板视觉设计

## 目标与边界

在不改变 schema `34`、`64×48` v2 地图、玩法数值或输入规则的前提下，用正式透明贴图替换 F3–F5A 最明显的程序化占位，并统一 `M/N/P` 三面板的视觉层。需要建模的对象本轮只做面向镜头的 Sprite/公告板；不实现模型、动画、复杂 Shader、音频或新玩法。

## 资产清单

- 单位：战斗傀儡、培育巨兽、灵能机甲、半机械巨兽。
- 地点与运输：次城、前哨、运输队。
- 人物：林溪、韩骨；岑烬复用既有正式图。
- UI：军队、世界、政务三套同族面板部件及守卫、跟随、远征、撤退、运输、通信、忠诚、救援等必要状态徽记。

每项资产先使用正式目录中的名称、来源和用途形成生成简介。图像不含文字、水印、数值或玩法状态，不通过额外透明留白制造偏移。

## 视觉规则

- 单位与地点：风格化低多边形、俯视游戏用抬高 3/4 视角、低饱和工业废土基底、路线色作有限识别强调、强轮廓、适合缩小。
- 人物：非写实精致赛璐璐、遮脸或弱化脸部细节、与岑烬同世界观但通过服装轮廓和路线色区分。
- UI：工业指挥终端、枪灰与旧铜主体、青蓝信息色、琥珀交互色、暗红危险色；装饰不得压过实时文字。
- 输出：透明 PNG；单位/地点/人物使用方形画布，UI 部件按实际消费者比例；运行时始终保持宽高比。

## 所有权

- 领域稳定 ID 继续由 Army、WorldLayer、Transport 和 Character 目录拥有。
- 新视觉目录只负责“稳定视觉 ID → Sprite + 展示参数”；现有枚举末尾追加 Unit 类，单位进入独立受控目录与 Units Atlas，人物、世界标记和 UI 继续沿用既有分类。
- 世界表现只为已有权威世界坐标的小队、地点和运输读取视觉目录生成 SpriteRenderer/公告板，目录缺失时回退现有程序化标记；角色没有独立坐标时只进入政务头像区。
- 三面板读取同一 UI 视觉目录，所有文字、数值、按钮行为和模态优先级仍由现有 View/Controller/Input System 负责。
- 图片、目录和显示对象均不进入存档。

## 测试策略

先写失败测试冻结资产数、稳定 ID、Alpha、导入设置、Atlas/目录映射、世界公告板的统一锚点与比例配置、缺图回退，以及 M/N/P 面板真实输入下的图像绑定和输入阻断。随后完成最小实现，再运行聚焦、日常完整 EditMode、完整 PlayMode、质量门和三项现役构建。

## 外部参考边界

只借鉴 Widelands 的小尺寸图标层级、OpenRA 的单位表现/命令状态分离和 Wesnoth 的图像与运行时偏移分离；不复制任何代码、美术、名称、数值或界面布局，不增加第三方依赖。
