# IDEA-0021 文明 Lv.2、六桥节点、全建筑贴图与科技树 UI 设计

## 1. 范围与真值

本规格实现 `IDEA-0021`。保持 `64×48` v2 地图、seed `8128`、24 个资源节点与 schema `33`。研究只读 `ResearchCatalog`，建筑只读 `BuildingCatalog`，生产只读 `ResourceRecipeCatalog`，战斗只读 Defense 目录，UI 只做投影和发布命令。

## 2. 文明 Lv.2 自然升级

- `core.research.alloy-armor`：保留 24 合金 + 8 石料、60 秒和精密装配前置。文明 Lv.1 显示“需要文明 Lv.2”；Lv.2 按正常前置/材料/研究站规则开放。完成后解锁机枪塔原位升级，并使已完成玩家建筑最大耐久×1.3；研究完成时保留已承受的伤害量。
- `core.research.sword-riding`：保留 24 灵铁 + 8 飞剑、60 秒和剑阵初解前置。Lv.2 后开放，完成后解锁剑阵台原位升级并使剑阵台/御剑台射程×1.3。
- 只对这两个稳定 ID 建立“文明开放投影”，其余 `PreviewOnly` 不开放。研究运行时、Operations UI、Latest 定位、存档恢复和 Validator 复用同一判定。
- 重机枪塔与剑阵台/御剑台进入正式战斗白名单，本地耗材容量统一配置为 30。同 stable instance 升级时重建战斗定义，保留并夹紧耗材、暂停和站点状态。

## 3. F2 六桥节点

六节点保留现有 ID、双前置、成本和 90 秒时长，从 `PreviewOnly` 改为 `Researchable`。

| 节点 | 本轮真实效果 |
|---|---|
| 灵能机甲 | 解锁 3×2 灵能机甲厂；2 机械组件 + 1 灵能增幅器 + 1 能量电池，18 秒产 2 控制芯片，作为 F3 机甲编队的前驱产线 |
| 高周波飞剑 | 解锁 2×2 高周波飞剑铸造台；2 灵铁 + 1 超导线圈，10 秒产 3 飞剑，直接补给剑类防御塔 |
| 生物机库 | 解锁 3×2 生物机库；2 骨钢 + 1 机械组件 + 1 活性生物质，14 秒产 3 生物武器，作为 F3 半机械巨兽的前驱产线 |
| 灵植培育 | 解锁 2×2 灵植园；已有灵植精华配方新增该建筑为允许生产者，旧存档中培育室选择不失效 |
| 精神脉冲武器 | 解锁 1×1 EMP 塔；消耗能量电池接入正式 Defense。EMP 命中标记为 Mechanical 的敌人时当帧抑制其移动，持续攻击形成持续瘫痪，不创建需要新存档字段的脱战计时状态 |
| 血肉灵丹 | 开放既有炼丹房三倍产出配方；使用时城市/建筑治疗量×3，20% 突变风险在治疗后对城市造成 150 点反噬伤害。风险采用可注入样本并立即结算，无新持久化状态 |

本轮不产生可下令的机甲/巨兽实例；实际小队、编队与远征属于 F3，UI 必须如实标注“前驱产线，单位部署待 F3”。

## 4. 建筑与美术

- 建筑目录从 30 扩为 35；28 个旧建造项 + 5 个新建造项进入 BuildMenu，重机枪塔和御剑台继续只能升级获得。
- 现有 30 座的 1024 透明母版和 256 交付图继续作为已生成真值，不无意义重绘；本轮为 5 座新建筑分别生成 1024 透明母版，派生 256 交付图。
- 五座新建筑的提示词从本规格的功能与简介生成；统一采用倾斜正交俯视、风格化中低模感废土工业建筑、路线色作局部能量强调、无文字、无地面、无背景、边缘清晰、10% 透明安全区。
- 全 35 座必须进入建筑清单、`BuildingIconCatalog3D`、统一视觉目录和 Buildings SpriteAtlas，并被建造卡/详情/世界贴图投影消费。失败时使用现有路线色占位回退。
- Editor manifest 保留 35 座建筑的来源、用途、解锁、背景简介和生成关键词，作为贴图制作与审核记录；运行时建筑详情继续由 BuildingDefinition、生产和 Defense 正式规则生成。本轮不新增一套重复的 runtime lore 目录，View 也不直接读取 Docs JSON。

## 5. 科技树 UI

以 `Docs/Art/IDEA-0021/research-tree-ui-concept-v1.png` 为视觉基准，不把整图作为背景。节点保持 180×112 和现有点击/搜索/筛选真值。连线投影新增粗主干、细分支、共享 junction、向上箭头和金色双路线虚线；桥线不穿节点，投影对同一目录字节稳定。背景 `#090D0F`，面板 `#0F171D`，通用/科技/修仙/生物/灵能/桥分别为 `#B8C2C7/#52B3E0/#61DB9E/#D16661/#B37AEB/#D5B45B`。

## 6. 验收

每个子系统 RED→GREEN。UI PlayMode 必须通过真实 Input System。日常 EditMode 不运行 `TerrainAssetDeep`，因为本轮不改地形源、导入规则、Builder 或 Texture2DArray。最终运行完整 EditMode/PlayMode、质量门、三项现役构建、文档生成/校验和 `RecordVerification`；用户视觉与真实 Windows 结论仍由实际验收给出。
