# IDEA-0018 文明式地图视觉与正式 3D UI 比例统一设计

状态：已批准，开发中
需求：`IDEA-0018`
Unity：`2022.3.62f1`
存档：保持 schema `32`

## 1. 目标

本阶段解决两个直接影响试玩观感的问题：

1. 当前地表偏写实、高频、综合色调接近，远景难以区分地貌且重复明显；
2. 三个 Canvas 使用不同缩放规则，常驻 HUD、建造栏、大型面板和开发修改器的视觉重量不一致。

完成后的地图应在远、中、近三种观察距离都可读；完成后的 UI 应在常见桌面分辨率和窗口化尺寸下保持统一比例、可读字号与稳定交互。

## 2. 参考原则与版权边界

只采用通用设计原则：

- Firaxis《The Art of Civilization VI》：用颜色、形状和轮廓保证远距离识别，让地图在不同观察距离均可读；
- Unity 2022.3 官方 CanvasScaler、Anchor 和 Auto Layout：统一参考分辨率、边缘锚定和最小/推荐/弹性尺寸；
- Archon Engine：玩法模拟与 GPU 地图表现保持单向分层；
- Daggerfall Unity：Texture2DArray 与稳定世界采样可减少材质切换并支持确定性变化；
- uLayout：借鉴 min/max/grow/wrap 的布局语义，但不引入依赖。

不复制任何《文明》贴图、图标、字体、界面布局、品牌或具体轮廓；不复制 GitHub 项目代码和美术，不下载或引入第三方包。

## 3. 不变真值

以下内容逐字段保持：

- 逻辑地图 `64×48`、seed `8128`、旧 `32×24` 内容偏移 `(16,12)`；
- 3072 格 Terrain、Traversal、ResourceId、ResourceAmount；
- 资源节点稳定 ID、类型、储量和世界坐标；
- 城市出生、建筑格位、通行、部署、物流、放置和采矿规则；
- `core.world.formal-3d.v1.64x48` world signature；
- schema `32` 及 schema `1–31` 兼容；
- Ruins/Cliff 14 Prefab、稳定 GUID/localFileID、确定性布局、两类合批、13 共享材质和分类原子回退；
- 唯一 EventSystem、正式 Input System 与现有模态优先级。

表现层只读取这些真值，不反向修改。

## 4. 地图视觉

### 4.1 七类颜色与细节层级

| 地貌 | 远景主色与明度 | 中近景语义 |
|---|---|---|
| Wasteland | 暖赭黄、中高明度 | 风蚀沙土、稀疏裂纹，不铺满碎石 |
| Rocky | 冷灰褐、中明度 | 大块岩板、受控边缘阴影 |
| Wetland | 灰橄榄绿、中低明度 | 湿土、水膜和稀疏枯枝 |
| Crystal | 青灰/冷青、中高局部亮度 | 稀疏晶脉和冷色反差，不与水混同 |
| Ruins | 中性混凝土灰、局部锈红 | 断裂人造面、尘土与标线残留 |
| DeepWater | 蓝黑、低明度 | 岸线亮带、双法线缓动和少量高光 |
| Cliff | 深灰褐、低明度 | 层理与断口，和普通 Rocky 保持明显高差感 |

每套源图仍使用稳定路径和现有通道合同。BaseColor 负责大色块和受控材质；Normal/Height 降低高频幅度；Mask 保持材质用途清楚。默认远景不得依赖微小法线才看得出类别。

### 4.2 现有管线演进

保留：

```text
WorldMapModel
  → FirstArtTerrainControlMapGenerator3D
  → Control A/B
  → 4 组 Texture2DArray
  → WasteCityFirstPassTerrain.shader
  → FirstArtTerrainRenderer3D（单 Renderer）
```

Shader/Profile 增加数据驱动的表现参数：

- 世界空间低频宏观色区；
- 每层受控色阶变化；
- 特殊地貌边缘/岸线强调；
- 世界坐标确定性 UV 旋转/镜像或等价去重复策略；
- 水面继续使用两组非平行法线动画。

首轮不改控制图算法、top-3 混合和 BlendWidth；视觉证据确实不足时才另写失败测试调整。禁止相机相关 Shader 真值、顶点位移、逐格 Renderer 和运行时材质实例增长。

### 4.3 镜头与资源标记

现役镜头补齐滚轮缩放。缩放状态由镜头控制器拥有，使用配置化的最小/默认/最大俯视距离与滚轮灵敏度；模态 UI、滚动列表或科技树消费滚轮时不得穿透到世界镜头。

资源标记只按镜头尺度切换表现：

- Near：图标 + 中文名 + 剩余储量；
- Mid：图标 + 储量；
- Far：图标，必要时做稳定重叠抑制；
- Mining Guidance：覆盖常态 LOD，按统一放置评估显示合法性、名称、储量和锚点。

LOD 不改变节点 GameObject 身份、稳定 ID、剩余量或采矿合法性；重复切换不得新增对象、材质或监听器。

## 5. UI 比例系统

### 5.1 统一 Canvas

Building、ProductionObservability、SystemMenu 三个 Canvas 使用同一配置：

- `ScaleWithScreenSize`；
- 参考分辨率 `1920×1080`；
- `ScreenMatchMode.Expand`；
- `referencePixelsPerUnit = 100`；
- 排序仍为 Building `0`、Operations `50`、SystemMenu `100`；
- 唯一 EventSystem 不变。

选择 `Expand` 是为了在 16:9、16:10、超宽和常见窗口化尺寸下优先保证安全区内容不裁切。最终以固定分辨率证据校准，不能仅凭公式宣称可用。

### 5.2 Layout Profile 与 Policy

新增 `FormalUiLayoutProfile3D`，只保存：

- 参考分辨率、Canvas 模式、排序层；
- 桌面安全边距 `24`、紧凑安全边距 `16`；
- 间距 token `4/8/12/16/24/32`；
- 字号 token：说明 `14`、正文 `16`、强调 `18`、小标题 `20`、大标题 `28`；
- 普通按钮最小高度 `36`、主要按钮 `44`；
- 各面板最大占屏比例与最小可用尺寸；
- 镜头缩放和资源标记 LOD 表现阈值可以放在独立地图表现 Profile，不能混入玩法配置。

新增纯 C# `FormalUiLayoutPolicy3D`，输入参考画布矩形，输出安全矩形、常驻槽位和面板布局。它不能读取领域模型或操作 Transform。

### 5.3 常驻槽位

```text
┌────────────────────────────────────────────────────────────┐
│ [危险/核心]        [资源状态栏，可横向滚动]     [速度/菜单] │
│                                                            │
│                       地图主视野                            │
│                                              [选择详情抽屉] │
│                                                            │
│                   [放置/缺料固定反馈]                       │
│                     [建造快捷栏]                            │
└────────────────────────────────────────────────────────────┘
```

规则：

- 资源栏不覆盖左上危险 HUD 和右上速度区；
- 建造栏保持现有位置，缺料/放置反馈固定在其正上方；
- 右侧详情使用安全区抽屉，不压住顶部速度与底部建造；
- 开发修改器使用更高的正式模态排序层，不能被资源或防御 HUD 覆盖；
- 系统菜单继续覆盖结算以下界面。

### 5.4 主模态与长内容

- 资源账本、背包/合成、科技树、撤离和系统菜单：限制在安全区的 `88%–92%`，内部滚动；
- 科技树保留节点画布拖动/缩放，外框响应式；
- 结算统计放入 ScrollRect，底部动作固定；
- 开发修改器变为右侧拉伸抽屉，宽度有上下限，内容滚动；禁止把整个面板缩到 `0.25`；
- 正文不低于正式说明字号，内部 stable ID 仅在必要处使用较弱层级，不抢占主信息。

## 6. 测试与证据

### 6.1 先失败的测试

1. 世界冻结：3072 格、节点、坐标、world signature、schema 保持；
2. 地形资产：七层唯一、色相/明度远景分离、高频密度上限、边界无缝、DeepWater 蓝黑和动态；
3. Shader/Profile：宏观变化确定性、参数来自正式配置、无相机依赖、无顶点位移、单 Renderer；
4. UI Policy：`1280×720`、`1366×768`、`1600×900`、`1920×1080`、`2560×1440`、`3440×1440`、`3840×2160` 的安全区与槽位不重叠；
5. 场景合同：三个 Canvas 完全一致、排序与唯一 EventSystem 不变；
6. 真实输入：滚轮镜头、资源/科技滚动、`B/E/T/Esc/0/Space`、Pointer 点击与模态不穿透；
7. 稳定性：资源标记 LOD、面板开关、分辨率切换和 authoring 重建不增加对象/监听器/材质实例。

### 6.2 固定视觉证据

- 默认 16:9 总览；
- 四基础层交汇；
- DeepWater 岸线；
- Ruins/Cliff 接缝与分类回退；
- 资源标记 Near/Mid/Far；
- 建造范围、蓝图和缺料反馈；
- 常驻资源/危险/速度/建造 HUD；
- 资源账本、背包/合成、科技树、结算、系统菜单和修改器；
- `1280×720` 紧凑窗口与 `3440×1440` 超宽窗口。

动态水和滚轮缩放需要运行时视频或等价连续帧证据；静态截图不冒充动态验证。
