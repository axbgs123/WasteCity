## 2. 本阶段目标

在默认正式 3D 主循环中建立机枪塔之前的最小生产闭环，并让玩家能够观察、理解和干预资源流：

```text
资源节点 → 采矿站内部输出 → 城市库存
城市库存 → 冶炼厂内部输入 → 内部输出 → 城市库存
城市库存 → 装配厂内部输入 → 内部输出 → 城市库存
```

同时提供：

1. 城市库存与 30 格个人背包；
2. 自动物流与近距离人工原子转移；
3. 背包内两条应急合成配方和 FIFO 队列；
4. 六节点首版科技树，其中仅两个推进节点可在本阶段启动；
5. 文明式常驻资源栏、E 库存/合成面板、T 科技树和建筑生产详情；
6. 生产、物流、库存、研究和合成的确定性运行时与可执行验证。

本阶段不进入敌人、炮塔、弹丸或正式战斗。机枪塔的耗弹数值只作为后续供应关系的设计基线，不接战斗运行时。

## 4. 生产配置与内部缓存

### 4.1 首批生产数值

机器与应急合成都进入同一个正式资源配方目录；机器生产定义再用稳定建筑 ID 映射配方 ID 与内部缓存。运行时、建筑详情、HUD、测试和生成文档只读取这些正式配置，不复制常量。

| 建筑 | 稳定机器配方 ID | 输入 | 周期输出 | 内部缓存 |
|---|---|---|---|---|
| 采矿站 | `core.production.extract-node-resource` | 绑定资源节点 | 每 3 秒采集 1 个节点对应资源 | 输出 20 |
| 冶炼厂 | `core.production.smelt-alloy` | 2 铁矿 | 每 6 秒 1 合金 | 输入 20，输出 10 |
| 装配厂 | `core.production.assemble-ammunition` | 2 合金 | 每 6 秒 2 弹药 | 输入 20，输出 30 |

这三个机器配方与 `core.crafting.field-alloy`、`core.crafting.field-ammunition` 共用目录合同，但稳定 ID、用途和数值独立；机器配方不能进入玩家 FIFO，应急配方不能被生产建筑执行。

后续机枪塔基线为持续开火时每 3 秒消耗 1 弹药；本阶段只用它验算稳定供应关系，不创建炮塔消费端。

稳定供应关系保持：

```text
2 采矿站 → 2 冶炼厂 → 1 装配厂 → 1 座持续射击机枪塔
```

### 4.2 资源节点绑定

- 采矿站必须绑定其正式放置评估已经确认兼容、且被 footprint 覆盖的资源节点；不得在生产系统重新复制放置合法性或兼容性判断。
- 绑定铁节点时产出铁；绑定能晶节点时产出能晶。
- `WorldMapModel` 是节点资源类型和剩余储量的唯一真值。采矿周期完成时才通过 `WorldMapModel.Harvest` 原子扣除真实储量。
- 节点不足 1 单位时不产生输出，状态显示“矿脉已枯竭”。
- 节点耗尽后，节点表现层必须根据模型状态刷新；视觉对象不得拥有或反写储量。
- 首批消费闭环只处理铁 → 合金 → 弹药；能晶可采集、入库和转移，但本阶段没有新的能晶消费配方。

### 4.3 生产推进

- 每个已完成建筑实例拥有独立进度、内部输入、内部输出、节点绑定、玩家暂停标记和状态快照；不得按建筑类型聚合成一条共享进度。
- 只有已完成、归玩家所有、未处于撤离锁定、且满足 `BuildingMobilityRules.CanOperate` 的建筑可推进生产。
- 正式配置的 `3/6/6` 秒是 3D 首版最终有效周期，不调用冻结 2D 的 `CityOperationalRules.ProductionMultiplier`，也不叠加其 Fortress `1.25` 倍率；城市形态在本轮只通过既有运行资格与物流连接影响生产。
- 生产只消费统一规则时间。全局暂停时不推进；打开 E、T、建造目录或建筑详情本身不暂停世界。
- 玩家可以在建筑详情中单独暂停/恢复生产。暂停保留进度和缓存。
- 新周期只有在当前内部输出缓存能够容纳完整产出时才开始，避免明知满仓仍预占输入或节点时间。
- 冶炼厂和装配厂开始一个新周期时，从内部输入缓存原子取得完整输入批次并由活动周期持有；输入不足时不开始，也不部分扣除。该周期随后脱网时，已经取得的批次仍可完成。
- 冶炼厂和装配厂在周期完成时才把完整产物原子写入内部输出缓存。若完成边界没有完整输出空间，进度保持在 100%，输入批次继续由活动周期持有，直到可完整写入；不得丢失、截断或重复产物。
- 采矿站没有输入预留。它只在周期完成时把 `WorldMapModel.Harvest` 扣减与内部输出写入作为同一次原子提交；任一步不能完成时，节点和缓存都不发生部分变化。
- 缺少输入、输出已满、矿脉枯竭或运行条件不满足时不虚增可追赶的进度债务。恢复条件后从保留进度继续，不瞬间补做停工期间的周期。

### 4.4 可观察状态

不要把联网状态与生产阻塞压成一个互斥枚举。正式快照至少分为：

- 生命周期：施工中、已完成、遗弃遗迹；
- 运行资格：可运行或由现有移动/展开规则禁止；
- 物流：已联网或脱离物流；
- 活动：运行、玩家暂停、全局暂停、阻塞；
- 原因集合：缺少输入、输出已满、不在物流范围、矿脉已枯竭、玩家暂停运行，以及现有运行资格原因。

“脱离物流”可以是警告而不是立即停工：建筑保留内部缓存，仍可在本地条件允许时运行。矿站脱网后继续采集，直到输出缓存满或节点枯竭；冶炼厂和装配厂脱网后继续消耗已有输入，直到缺料或输出满。UI 必须同时显示“脱离物流”和实际活动/阻塞原因，不能把脱网运行误报为完全停工。

建筑详情同时保留完整原因集合和一个确定的首要停工原因。首要原因优先级为：玩家暂停运行 → 矿脉已枯竭 → 输出已满 → 不在物流范围 → 缺少输入。“不在物流范围”只有在当前缺少的输入本可从城市库存取得、但连接断开时才取代“缺少输入”；单纯脱网且仍在使用内部缓存运行时只显示物流警告。全局战术/系统暂停冻结规则时间，但不覆盖建筑自己的首要停工原因。

## 5. 城市库存、仓库与容量降低

### 5.1 城市库存

- 城市库存继续使用 `ResourceInventory` 的“每种资源独立容量”语义。
- 正式基础容量为每种资源 150，不采用现有 3D 开发夹具的每资源 5000 作为正式值。
- 新正式 3D 会话的初始城市库存严格采用 GDD A6.1：铁 20、合金 20、弹药 30、生物质 10，其余 11 种正式资源为 0。现有建造开发夹具的 30 铁、10 能晶、30 石料、20 生物质、20 水、30 合金不是正式开局数值。
- 每座已完成、归玩家所有且未处于撤离锁定的仓库，为每种城市资源增加 150 容量；单纯脱离自动物流不取消该容量效果。
- 仓库不增加物流半径。

### 5.2 容量降低与超额库存

仓库被废弃、移除、进入撤离锁定或失去玩家所有权而造成容量降低时：

- 已有资源不得裁切、丢弃或转换；
- 允许当前数量暂时高于新容量；
- 对应资源禁止继续自动或人工入库，直到数量重新不高于容量；
- 已有超额资源仍可正常消费或转出；
- UI 显示 `当前数量/容量`、超额量和“容量不足，禁止继续入库”；
- 容量恢复后自动解除入库阻塞，不补发或重算历史资源。

因此不得直接沿用 `ResourceInventory.AddCapacity` 当前在降容时裁切数量的行为。实现应扩展或包裹库存容量语义，并用失败测试保护零丢失。

## 6. 个人背包

### 6.1 栈规则

- 玩家拥有一个本阶段会话级个人背包，界面固定为 `10×3`，共 30 格。
- 每格只存一种资源，单格上限 100。
- 同一种资源可以占用多个格。
- 入包时按稳定格索引从小到大，先填充已有同资源非满栈，再使用空格。
- 移出时同样按稳定格索引从小到大扣除。
- 背包支持第 3 节定义的全部 15 种资源。
- 格索引、资源 ID 和数量属于领域状态；图标、文本和拖动对象只是表现。

### 6.2 原子转移结果

所有人工转移先计算可移动量，再把“源端精确扣除”和“目标端精确增加”作为一个事务提交。

- 目标容量不足时允许部分接收；一次部分接收仍是一个原子事务。
- 返回值至少包含请求量、实际移动量、剩余量和明确原因。
- 源端不得扣除超过目标实际接收的数量。
- 任一步验证失败或提交异常时必须完整回滚源、目标和相关 revision。
- UI 必须显示未移动的剩余量及原因，不得把部分成功显示成全部成功。
- 自动物流和合成预留不能绕过相同的容量/原子性底层边界。

### 6.3 人工转移交互范围

交互半径是正式配置值：平面距离不超过 2 个世界网格单位。UI 不得硬编码 `2`。

建筑人工转移：

- 目标必须是已完成、归玩家所有、未处于撤离锁定的建筑；
- 计算当前直接控制目标（城市或已招募领袖）到建筑 footprint 边缘的最短平面距离；
- 距离 ≤ 2 格时允许背包与建筑内部缓存之间人工转移；
- 不要求 `Fortress`，也不要求自动物流连接，因此玩家可近距离维护脱网建筑；
- 距离、所有权、完成状态和撤离锁定必须在提交时重新验证，不能只依赖打开面板时的旧判定。

城市库存与背包转移：

- 当前直接控制城市时，始终可访问本城库存；
- 当前直接控制已招募领袖时，领袖到城市核心 footprint 边缘的平面距离必须 ≤ 2 格；
- 超出范围时保留面板信息但禁用提交，并显示实际原因。

## 7. 自动物流

### 7.1 联网判定

- 内城建筑自动联网。
- 地面建筑只有在城市处于稳定 `Fortress`，且建筑 footprint 的全部格都位于 `BuildingRangeRules` 提供的正式范围内时联网。
- 建筑不要求相邻。
- 建筑不充当中继，不能链式延伸物流。
- 仓库不扩大物流距离。
- 不复用旧 `LogisticsNetworkModel` 的任意建筑链式中继语义。
- 联网判定必须消费现有城市位置、建筑 placement 和 `BuildingRangeRules`；生产系统、UI 和测试不得复制切比雪夫距离公式。

### 7.2 自动搬运顺序

自动物流只在联网时运行，并以稳定建筑实例 ID 的顺序处理。每个物流步按以下固定顺序：

1. 尝试把建筑内部输出移入城市库存；
2. 尝试从城市库存补充建筑内部输入，最多补到内部输入容量；
3. 生产系统使用物流处理后的缓存推进当前规则时间；

本步新产生的输出保留在内部输出缓存，等待下一物流步移出。这样内部缓存始终可观察，且同一输入状态和时间序列得到同一结果。

自动搬运允许部分移动，但每次部分移动必须遵守第 6.2 节的原子结果。城市超容量或内部缓存已满时，未移动资源保留在来源端。

## 8. 背包内应急合成

### 8.1 面板和资源所有权

E 打开同一个非模态“库存”面板，包含“资源”和“合成”两个页签。合成只使用个人背包中的资源，不自动访问城市库存或建筑缓存。需要城市资源时，玩家先通过正式转移交互把资源移入背包。

背包合成是应急补缺，不替代自动生产：耗材比建筑生产更高、周期更长，且不自动把产物用于下一配方。

### 8.2 唯一两条首版配方

| 稳定配方 ID | 解锁 | 输入 | 输出 | 单次时间 |
|---|---|---|---|---|
| `core.crafting.field-alloy` | 基础冶金完成 | 4 铁 | 1 合金 | 12 秒 |
| `core.crafting.field-ammunition` | 弹药装配完成 | 4 合金 | 2 弹药 | 12 秒 |

配方 ID、资源、数量、周期和解锁必须来自正式合成配置，不得写进按钮回调或文案。

### 8.3 FIFO 队列

- 队列按合成“次数”计数，最多 20 次；不是最多 20 个可无限叠加的队列行。
- 左键配方加入 1 次；右键请求完整加入 5 次，无法完整承担时整体拒绝；`Shift + 左键` 加入当前资源和队列余量允许的最大次数。
- 入队时从背包原子预留全部所需输入。任一输入不足或队列余量不足时，不产生部分未说明的请求；只有 `Shift + 左键` 会把请求显式缩减为计算后的最大成功次数。
- 只推进队首，严格 FIFO；没有并行合成。
- 队首完成时把完整输出原子写入背包。背包无足够空间时，队首保持 100% 进度并显示“输出已满”，不丢失输入或产物，也不推进后续项。
- 取消未完成或输出阻塞的次数返还 100% 已预留输入。若背包没有足够空间容纳完整返还，则拒绝取消并显示原因；不得部分返还或丢弃。
- 不自动把 `core.crafting.field-alloy` 的输出交给后续 `core.crafting.field-ammunition`，也不自动补充、循环或链式排队。
- 关闭 E 面板后队列继续推进。
- 全局战术暂停、系统菜单暂停或其他统一暂停原因存在时，队列冻结；恢复后从原进度继续。
- 单独暂停建筑不影响背包合成队列。

## 9. 六节点首版科技树

T 打开正式 3D 科技树。科技树严格采用 GDD A16.4 的六个节点、顺序主链与末端分支，不显示当前大型路线研究目录来冒充首版科技树。

| 顺序 | 稳定节点 ID | 科技 | 前置 | 成本 | 时间 | 效果/本阶段状态 |
|---:|---|---|---|---|---|---|
| 0 | `core.research.scrap-processing` | 废料加工 | 初始 | 无 | 已解锁 | 初始完成；解锁采矿站、研究站、住房、仓库、城墙 |
| 1 | `core.research.automated-machinery` | 基础冶金 | 废料加工 | 铁 10 | 20 秒 | 本阶段可研究；解锁冶炼厂与 `core.crafting.field-alloy` |
| 2 | `core.research.precision-assembly` | 弹药装配 | 基础冶金 | 合金 10 | 30 秒 | 本阶段可研究；解锁装配厂与 `core.crafting.field-ammunition` |
| 3 | `core.research.automated-defense` | 自动防御 | 弹药装配 | 合金 12 + 生物质 10 | 35 秒 | 只预览且锁定；不激活机枪塔效果 |
| 4 | `core.research.reinforced-structures` | 加固结构 | 自动防御 | 合金 20 + 生物质 10 | 45 秒 | 只预览且锁定；不激活生命加成 |
| 5 | `core.research.legacy-analysis` | 遗产解析 | 自动防御 | 合金 30 + 生物质 20 | 60 秒 | 只预览且锁定；不激活升阶效果 |

其中 `core.research.automated-machinery`、`core.research.precision-assembly`、`core.research.automated-defense`、`core.research.legacy-analysis` 复用准确基线既有 ID；`core.research.scrap-processing` 与 `core.research.reinforced-structures` 是本轮批准新增、仅表达六节点 3D profile 语义的稳定 ID。禁止为已有四项另建重复或平行 ID。

“仅前两项可研究”指废料加工之后的前两个推进节点：基础冶金和弹药装配。后三个推进节点必须显示正式名称、前置、成本、时间和预览效果，同时显示“本阶段未开放”，任何输入或开发外正常流程都不能启动它们。

研究运行规则：

- 同时只有一个活动研究，不建立多项研究队列。
- 开始研究时原子扣除完整成本；多资源成本必须全有或全不扣。
- 取消研究返还 80%，进度不保留；若完整退款无法原子写回城市库存则拒绝取消，不得部分退款、超容写入或丢失资源。
- 开始和推进研究都需要至少一座已完成、归玩家、未撤离锁定的研究站；失去最后一座合格研究站时暂停但不取消、不退款，恢复后从原进度继续。
- 城市稳定 `Fortress` 时按 100% 推进；Mobile、Deploying 和 Packing 时按 50% 连续推进；该 `100%/50%` 只属于新 3D 运行时，冻结 2D 旧行为保持原样回归。
- 全局暂停时不推进；T 面板本身不暂停世界。
- 完成研究时更新正式研究状态，并让建筑目录、合成目录和相关 UI revision 在同一规则提交后可见。
- 本阶段不触发科技完成关注度，因为关注度运行时不在本轮范围；UI 可标注该后续效果，不得声称已生效。

准确基线 `BuildingCatalog` 的冶炼厂与研究站施工成本和 GDD A16.2 不一致。本里程碑不修改这些既有施工成本，也不借科技接线静默改变冻结 2D 放置体验；该差异保留为独立变更控制项。

## 10. 正式 3D UI 与输入

### 10.1 常驻资源栏

- 屏幕顶部提供文明式常驻资源栏：铁矿、能晶、石料、生物质和水五种基础资源常驻；合金与弹药在首次发现或对应科技解锁后加入。其余路线资源不在未发现时提前占用常驻栏。
- 每项读取城市库存正式账本快照，显示数量、有效容量、近期净流速和超额/入库阻塞状态；不得维护第二份资源真值。
- 悬停显示近期收入来源、支出去向、容量来源，以及按稳定净流速估算的耗尽或装满时间；趋势不足时显示“暂不可估算”，不得伪造时间。
- 点击可交互的资源项打开只读完整资源账本，按正式顺序覆盖 15 种资源。该明确命中区与非交互背景分离；账本仍只读取同一真值。
- 资源栏是被动信息层，文本和背景不接收 raycast，不得遮挡世界点击、目的地或镜头拖动。
- 资源变更或容量 revision 改变时更新；不逐帧重建全部文本和布局。

### 10.2 E 库存/合成面板

- E 从空闲状态打开/关闭同一“库存”面板。
- 资源页显示 30 个稳定格位、全部城市资源、可访问目标和转移结果。
- 左键负责拿起、放置、同类合并或异类交换；右键负责拆分一半和逐个放置；`Shift + 左键` 在当前有访问资格的背包与城市/建筑库存之间快速转移。所有手势都提交同一原子转移命令，不允许视图直接改数量。
- 合成页显示两条配方、解锁原因、可排次数、FIFO 队列、活动进度和阻塞原因。
- 面板打开不暂停世界；合成队列继续运行。
- E 与 T、B 完整建筑目录互斥。打开一个主面板时关闭另一个，避免重叠焦点和输入所有权。

### 10.3 T 科技树

- T 打开/关闭六节点科技树。
- 显示已完成、可研究、前置不足、资源不足、缺少研究站、当前研究中和“本阶段未开放”。
- 点击节点只选择；明确的研究按钮才提交开始操作，避免误点扣款。
- 当前研究显示剩余时间、模式倍率和暂停原因。
- T 面板打开不暂停世界。

### 10.4 建筑生产详情

- 退出放置预览后，真实世界左键可选择已完成建筑；放置预览中的左键仍只属于放置确认。
- 施工中建筑继续由既有施工取消控制器拥有；不要把完成建筑详情塞入施工取消控制器。
- 详情读取不可变建筑运行快照，显示配方、输入缓存、输出缓存、进度、节点剩余量、物流、活动状态和全部原因。
- 提供玩家暂停/恢复和满足交互范围时的人工转移；UI 不自行计算范围、配方或物流。

### 10.5 焦点、Esc 和防穿透

正式输入继续经过 `GrayboxInputRouter` → `GrayboxUsabilityInputCoordinator3D`。新增面板不得各自轮询键盘。

优先级固定为：

1. 已打开系统菜单及其子页；
2. 当前 UGUI 可编辑/键盘控件；
3. 施工取消确认和疏散处理等既有模态流程；
4. E、T 和建筑详情；
5. 建筑目录/放置的既有取消链；
6. 空闲 Esc 打开系统菜单。

焦点控件获得输入时，文字、导航、提交和首次 Esc 由 UI 消费；首次 Esc 只失焦，下一次 Esc 关闭当前非模态面板，再次空闲 Esc 才打开系统菜单。系统菜单打开时，E/T/生产详情/合成操作全部失效。

所有面板内点击、拖动和释放都必须由活动 `GraphicRaycaster` 捕获，禁止穿透为放置、领袖移动、城市目的地或镜头拖动。常驻资源栏保持非 raycast。隐藏或销毁面板后必须在下一输入帧释放焦点与指针所有权。

### `WasteCity.Game`

- 六节点首版科技配置与研究运行模型；

### `WasteCity.Graybox3D.Building`

拥有正式 3D 会话适配：

- 以稳定建筑实例 ID 关联生产运行状态；

Editor authoring 只负责生成/验证场景序列化引用。不得通过 `FindObjectOfType`、名称查找或临时运行时创建来掩盖正式场景缺少引用。

## 12. 确定性、修订与性能

- 资源、配方、科技、建筑实例、队列项和背包格都使用稳定 ID 或稳定索引。
- 建筑物流与生产按稳定实例 ID 排序；背包按格索引；合成严格 FIFO；不得依赖 Dictionary、HashSet、场景遍历或碰撞返回顺序。
- 同一初始快照、同一命令序列和同一规则时间序列必须产生相同结果。
- 阻塞期间不累积无限补算债务；大 delta 的周期提交必须有确定边界且不能形成无上限单帧循环。
- 领域状态变更后统一增加相应 revision。UI 按 revision 或事件刷新结构，不能每帧重建配方、科技、格位或建筑列表。
- 活动进度条可更新数值；倒计时文本只在显示精度变化时格式化。
- 关闭面板、打开静止面板和稳定运行队列/生产三种状态都必须进行连续 300 帧或调用的分配探针；正式适配器目标为 `0 B GC Alloc`。
- UI 行、资源格和科技节点使用固定创建或复用，不在运行 Tick 中反复创建/销毁 GameObject。
- 生产与物流工作量必须随相关建筑数量线性增长；不得每个建筑每帧全图扫描资源节点或所有建筑。

## 13. TDD 与实施顺序

每一步先提交能失败的测试，再做最小实现。推荐顺序：

1. 15 资源目录、生产配置和科技/合成配置合同；
2. 城市超额容量和 30×100 背包纯规则；
3. 原子转移、部分接收、回滚和 2 格交互规则；
4. 每建筑内部缓存、周期、暂停和原因快照；
5. 节点绑定、真实 Harvest 和枯竭；
6. 不链式的正式物流连接与稳定自动搬运；
7. 两条应急配方和 20 次 FIFO 队列；
8. 六节点科技、单活动研究、100%/50% 推进；
9. 正式 3D 资源栏和建筑详情；
10. E 库存/合成、T 科技树和统一输入协调；
11. 场景 authoring、质量目录、复用目录和生成文档；
12. 聚焦测试、全量测试、构建和独立审查。

实现文件名可在计划中细化，但不得创建平行库存、平行建筑目录、平行物流范围或第二套资源节点兼容规则。

## 14. 必测合同

### EditMode 纯规则

- 三类建筑的精确配方、周期和缓存；铁/能晶节点对应输出；
- 每建筑独立进度，暂停、缺料、输出满、脱网运行和恢复无追赶；
- 节点最后一单位、耗尽和无重复 Harvest；
- 内城联网、地面 footprint 全格范围、非 Fortress 断网、不相邻、不链式、仓库不扩范围；
- 城市基础 150、每有效仓库 +150、降容保留超额、禁止继续入库和恢复；
- 背包 30 格、单格 100、多栈、稳定合并/扣除和容量边界；
- 城市、建筑、背包之间完整/部分转移和异常全回滚；
- 城市/领袖到 footprint 边缘的精确 2 格边界，以及提交时重验；
- 两配方精确值、研究门槛、左 1/右 5/Shift 最大、20 次总上限、FIFO、原子预留、输出阻塞、取消空间不足拒绝和无自动链式；
- 六节点精确拓扑（顺序主链与末端分支），仅基础冶金/弹药装配可启动，后三项不能绕过；
- 研究多资源原子扣款、取消 80% 与退款容量拒绝、单活动、启动/推进研究站门槛、研究站失效暂停恢复、Fortress 100%、其他模式 50%、统一暂停冻结；
- 快照、排序、revision、重建稳定性和 300 次分配探针。

### PlayMode 真实主循环

- 使用真实 Input System 按 E/T、输入焦点、Esc 分层关闭和系统菜单；
- 使用真实 `InputSystemUIInputModule` 点击页签、配方、队列、研究、转移和建筑暂停按钮；禁止直接调用内部回调冒充玩家输入；
- UI 按下、拖动、释放不穿透到世界；常驻资源栏不阻挡世界；
- 退出预览后真实点击完成建筑显示实例生产详情；预览中左键语义不变；
- E 关闭后合成继续；E/T 打开时世界继续；统一暂停时生产、合成、研究、施工停止而 UI 可读；系统菜单保持模态；
- 真实建造 2 矿站、2 冶炼厂、1 装配厂并观察铁 → 合金 → 弹药；不以直接注入最终资源代替闭环；
- 移动/收起导致地面建筑脱网，缓存保留并按批准规则继续或阻塞；重新展开联网后自动恢复搬运；
- 城市和领袖 2 格边界的人工转移；
- 场景重载后的正式序列化引用、唯一监听器和明确的会话级无存档策略。

### 回归与交付门

- 聚焦 EditMode 与聚焦 PlayMode；
- 普通日常完整 EditMode，明确不运行 `TerrainAssetDeep`；
- 完整 PlayMode；
- 官方文档生成、项目质量验证和 `RecordVerification`；
- Windows Release 3D、Development 3D、Legacy 2D 和 macOS universal 正式入口；
- 静态审查、运行时验证、性能探针和构建日志；
- 真实 Windows 10/11 视觉、GPU、显存与内存仍需独立人工/机器验收，不能由 macOS 或 Editor 结果替代；
- 用户人工试玩结论只能由用户确认。

只有实际运行并核对证据后才能把“已实现待验证”提升为“已验证”。

## 15. schema 30 与冻结 2D

- 正式存档 schema 保持 `30`。
- 本阶段的 3D 建筑内部缓存、个人背包、合成队列和六节点科技适配均为当前会话状态，不写入正式存档。
- 不在旧字段中偷塞新数据，不修改 codec 兼容边界，不宣称支持迁移或恢复。
- 若未来要求保存这些状态，必须单独提出 schema 变更、兼容和迁移设计并取得用户批准。
- `FormalPrototype` 和其 2D 控制器只做回归保护；不接 E/T、新生产、背包、合成、科技或物流 UI。
- 不修改或复用 `PlaceholderBuildingController` 作为 3D 运行时。
- 现有 2D `TechnologyProductionController`、`ResearchController` 和 `LogisticsNetworkModel` 的聚合生产、旧研究推进和链式物流不是本阶段 3D 规格。

## 16. 明确排除项

本阶段不制作：

- 电力系统；
- 传送带；
- 具体工人或运输单位；
- 相邻八格共享；
- 建筑中继和跨城市运输；
- 新资源、装备、物品品质或重量系统；
- 两条批准配方之外的手工合成；
- 自动合成链、循环配方或自动补货；
- 多项研究队列、后三节点的实际效果或六节点之外的正式科技树；
- 敌人、炮塔、弹丸和战斗；
- 正式存档、schema 变更或迁移；
- 冻结 2D 新功能接线；
- 正式 UI 美术、音效或超出清楚可替换占位表现的资产；
- 跨城市、前哨完整自治、实体运输或高阶物流请求；
- 正式发布、Release、PR 合并或自动部署。

## 17. 完成定义

本设计的实现只有同时满足以下条件才可报告“实现完成”：

1. 精确规则全部由正式配置和单一领域真值驱动；
2. 不复制放置、资源节点兼容、物流范围或建筑运行资格；
3. 正式 3D 真实输入完成 E/T/建筑详情和完整生产观察；
4. 资源转移、生产、合成、研究和容量变化均原子且无资源丢失；
5. schema 仍为 30，冻结 2D 无新功能改动；
6. 新生产文件进入项目质量目录和可复用目录；
7. 失败测试先于最小实现，聚焦、全量、文档、构建和性能证据全部新鲜；
8. 未完成的 Ruins/Cliff 人工复验、真实 Windows 验收和用户试玩仍被如实标记为未完成。

在此之前，正确状态只能是“设计已批准，尚未实现/验证”或“已实现待验证”。
