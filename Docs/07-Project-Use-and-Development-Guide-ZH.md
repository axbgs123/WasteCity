# 废土移动城市使用与开发入门

## 这份说明适合谁看

适合第一次打开这个项目的试玩者、非程序背景的协作者，以及刚加入项目的新开发者。先约定五个词：EditMode（不启动游戏画面、在编辑器里检查规则和资料的测试）、PlayMode（启动游戏流程、检查实际互动的测试）、组件（挂在场景物体上的一小块功能）、程序集（把相关代码一起编译成可用单元的集合）和稳定 ID（不随改名或资源替换而变化的固定编号）。不熟悉这些词也可以继续阅读；本页先讲该怎么用，技术细节放在后面的链接里。

## 游戏目前能做什么

当前默认入口是一座可移动的三维灰盒城市：可以进入三维场景，观察城市、地形、相机和建造相关交互。已实现的规则、资源、路线和视觉接入会继续由自动检查保护；能否作为面向玩家的完整体验，仍要以实际试玩为准。

## 明确尚未完成的内容

“移动→展开→建造→生产→防御→撤离”的完整正式循环尚未完成。`IDEA-0011` 已获批准并进入开发中状态，目标只在默认 3D 场景补充铁矿→合金→弹药生产、建筑内部缓存、城市物流观察、资源占位表现，以及按 `E` 打开的玩家背包和缓存双向拖拽；这些目标目前仍在设计和实施阶段，尚不可在游戏中使用。研究界面、队列、完整敌人与防御、正式撤离、正式存档适配，以及完整首版美术接入也仍属于后续工作。不要把目录里出现的模型、计划项或旧测试误解为这些内容已经可供玩家使用。

## 怎样打开默认 3D 游戏

1. 用 Unity Hub 打开工程根目录，并确认编辑器版本为 `2022.3.62f1`。
2. 在 Project 窗口打开 `Assets/_Game/Scenes/GrayboxPrototype3D.unity`；这是默认 3D 场景，也是默认编辑和正式构建入口。
3. 按 Play 开始试玩；若 Console 有持续报错，先记下报错和操作步骤，不要直接改场景。
4. 想知道场景、脚本、界面所有者或美术接入点，请查看自动更新的[项目清单](Generated/Project-Inventory-ZH.md)。

## 两个场景的区别

默认 3D 场景是 `GrayboxPrototype3D.unity`，用于当前开发、试玩和默认构建。冻结 2D 场景是 `FormalPrototype.unity`，它保留旧版二维规则的回归基线，用来确认旧内容没有被意外破坏。冻结 2D 场景不是新功能模板；新功能从默认 3D 场景及其现有规则开始，并在需要时保留 2D 回归检查。

## 主要按键和界面

以场景实际显示的提示为准：相机可拖动，`Home` 可回到指定视角；建造、选择和城市展开相关操作由当前三维界面处理。`IDEA-0011` 的目标操作是按 `E` 打开或关闭 12 格玩家背包，并在选中建筑的缓存与背包之间双向拖拽；在正式 3D 场景、真实输入测试和本文状态共同证明接入前，`E` 仍只是已批准目标，不应当作当前可用按键。开发修改器只会在开发版本出现，不能把它当作正式玩家功能，也不能据此判断平衡或发布体验。界面与输入的准确归属可在[项目清单](Generated/Project-Inventory-ZH.md)中查找。

## 开发修改器只在开发版本出现

开发修改器用于开发时快速检查建造和场景状态。它出现时，请把它看作测试辅助；正式构建是否提供、提供什么功能，都必须另行确认。发现它遮挡操作、抢走输入或与普通界面冲突时，按本页的排查步骤记录问题。

## 想修改某个功能先看哪里

先读[用户反馈与变更控制](06-User-Feedback-and-Change-Control-ZH.md)，确认该事项是否已经批准、属于修复还是新构思。然后到[项目清单](Generated/Project-Inventory-ZH.md)找相关场景、组件、程序集和文件，到[测试清单](Generated/Test-Inventory-ZH.md)找相应检查。需要复用已有内容时，再读[可复用项目目录](09-Reusable-Project-Catalog-ZH.md)，尤其要遵守“仅限场景”“冻结回归”和“禁止用于新功能”的边界。

## 新电脑交接最短路径

安装 Git、Git LFS、Unity Hub、Unity `2022.3.62f1` 及 Windows Build Support；克隆 Private 仓库后运行 `git lfs pull`，再用 Unity Hub 打开工程根目录。等待 Unity 恢复依赖后，打开默认 3D 场景，查看 Console，并先执行相应的自动检查。不要复制其他电脑的 `Library`、`Temp`、`Logs`、`Builds`、`TestResults` 或 `UserSettings`。

## 出问题时先做什么

先停止继续叠加操作，记录版本或提交、场景、复现步骤、期望和实际结果；截图或录屏比“看起来不对”更有用。接着查看[测试与 Bug 定位指南](08-Testing-and-Bug-Location-Guide-ZH.md)。自动报告只是排查起点，它告诉我们先从哪里看，不能替代复现、阅读上下文和人工确认。
