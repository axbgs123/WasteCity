# 废土移动城市使用与开发入门

## 这份说明适合谁看

适合第一次打开这个项目的试玩者、非程序背景的协作者，以及刚加入项目的新开发者。先约定五个词：EditMode（不启动游戏画面、在编辑器里检查规则和资料的测试）、PlayMode（启动游戏流程、检查实际互动的测试）、组件（挂在场景物体上的一小块功能）、程序集（把相关代码一起编译成可用单元的集合）和稳定 ID（不随改名或资源替换而变化的固定编号）。不熟悉这些词也可以继续阅读；本页先讲该怎么用，技术细节放在后面的链接里。

## 游戏目前能做什么

当前默认入口是一座可移动的三维灰盒城市：可以进入三维场景，观察城市、地形、相机和建造相关交互。`IDEA-0011` 至 `IDEA-0013` 已接入基础生产物流、背包与应急合成、首版研究、资源状态栏和首个防御闭环；`IDEA-0014` 又接入正式展开、收起和战斗撤离，`IDEA-0015` 接入正式 3D 单槽存档。`IDEA-0016` 已实现 31 种资源、30 条配方、43 节点自下向上科技树、完整资源账本、中文修改器和六类 114 项透明二维图。`IDEA-0017` 当前为“已实现待验证”：正式 3D 已扩展为三塔、三敌、单城市十波、建筑受击、统一暂停/倍速、唯一胜负结算、完整会话统计、内部最近波前重试和 schema `32`。`IDEA-0019` 又把正式世界更新为覆盖整张 `64×48` 地图的 v2 固定宏区布局，使用 24 个固定资源节点、统一建筑表现比例和会确定性避让的矿点标签。日常完整 EditMode、完整 PlayMode、项目质量门、三项现役构建和官方文档生成/校验已经通过；人工试玩和真实 Windows 复验仍须按实际结果收口。

## 明确尚未完成的内容

“移动→展开→建造→生产→防御→撤离”的完整正式循环已经完成实现、完整自动化、项目质量门和退役前构建，当前状态为“已实现待验证”；仍须由用户试玩，并在真实 Windows 机器复验视觉、GPU、显存和内存。`IDEA-0015` 的正式 3D 单槽存档历史基线及 Task 14 退役后的完整自动化、质量门和三项现役构建均已通过。`IDEA-0016` 的资源、科技和二维视觉也已实现待验证。`IDEA-0017` 的十波战役、schema `32`、统计与结算已完成生产实现；本阶段完整 EditMode 2481 项、完整 PlayMode 87 项、项目质量门、Windows Release 3D、Windows Development 3D、macOS universal 3D 和官方文档生成/校验均已通过。结算排版、可读性、真实游戏节奏、重试体验和真实 Windows 表现仍待用户验证。前哨、迷雾、其余敌人与炮塔，以及新增三维模型、动画、VFX 与 SFX 仍属于后续工作。不要把灰盒废墟称为前哨，也不要把任何自动化或构建描述成人工验收已经完成。

## 怎样打开默认 3D 游戏

1. 用 Unity Hub 打开工程根目录，并确认编辑器版本为 `2022.3.62f1`。
2. 在 Project 窗口打开 `Assets/_Game/Scenes/GrayboxPrototype3D.unity`；这是默认 3D 场景，也是默认编辑和正式构建入口。
3. 按 Play 开始试玩；若 Console 有持续报错，先记下报错和操作步骤，不要直接改场景。
4. 想知道场景、脚本、界面所有者或美术接入点，请查看自动更新的[项目清单](Generated/Project-Inventory-ZH.md)。

## 当前 3D 场景与历史 2D 入口

默认且唯一启用的游戏场景是 `GrayboxPrototype3D.unity`，用于当前开发、试玩和正式构建。Task 14 已退役历史 2D `FormalPrototype.unity`、47 个只服务该运行时的脚本（共 51 个 `MonoBehaviour` 类型）和 legacy 2D build；当前正式构建只有 Windows Release 3D、Windows Development 3D 和 macOS universal 3D 三类。退役后的聚焦和完整自动化、项目质量门、三项构建、官方文档生成/校验和正式验证记录均已通过。退役只移除旧场景运行入口，不删除共享纯规则、稳定 ID、schema `1–30` decoder、迁移、固定回归样本或旧档中文识别。

## 主要按键和界面

以场景实际显示的提示为准：相机可拖动，`Home` 可回到指定视角；建造、选择和城市展开相关操作由当前三维界面处理。`F` 用于展开、收起或取消正在进行的转换；已展开且存在外城资产时，`F` 会先打开撤离清单。`E` 打开背包、全部 30 条配方的只读目录与两条可手工排队的应急合成；高级路线配方只能由对应机器执行。`T` 打开 43 节点正式科技树；科技树支持空白左拖、中键拖动、指针中心滚轮缩放、搜索、路线/状态筛选、`Home` 显示全树和进行中科技定位，打开时依据正式目录定位最新可推进范围。搜索框有文本焦点时第一次 `Esc` 只释放焦点，第二次才关闭；科技树打开期间其他世界和建造输入不得穿透。顶部横向资源栏常驻五种基础资源，完整账本按正式发现投影显示已拥有或由研究/配方揭示的材料，并提供路线与层级筛选；断开物流的仓库内容仍属于玩家资产和发现事实，但不计入当前联网可用数量。生产详情显示当前可选配方、全部输入/输出通道、进度、物流连接、节点剩余量和停工原因，并允许在安全边界内切换配方、暂停/恢复和按通道转移资源。可见但尚未满足条件的建筑点击原因，以及城市形态、范围、占用、地形、障碍、矿点和材料等蓝图放置失败，都固定显示在位置不变的建造栏正上方；提示不会形成世界点击死区。撤离清单与处理页不会自动暂停世界，仍允许 `Space` 战术暂停；容量不足时可按 `E` 把城市物资移入背包，返回原批次后重新检查容量。系统菜单优先于撤离界面，撤离界面优先于其他面板、建造和世界操作；若出现点击穿透或快捷键同时触发多个系统，应按 Bug 记录。开发修改器只会在开发版本出现，不能把它当作正式玩家功能，也不能据此判断平衡或发布体验。界面与输入的准确归属可在[项目清单](Generated/Project-Inventory-ZH.md)中查找。

## IDEA-0014 六段流程与真实输入边界

当前自动流程 `GrayboxFormalEvacuationVerticalSliceTests` 使用正式场景、虚拟键盘/鼠标和真实 Input System UI 主循环依次检查六段：1）驾驶城市到合法位置并按 `F` 展开；2）按 `B` 建成研究站并按 `T` 完成基础冶金、弹药装配和自动防御；3）用建造界面建立两座采矿站、两座冶炼厂、一座装配厂和一座机枪塔；4）等待真实采矿、加工、产弹、补弹、索敌和射击；5）敌人存活时按 `F` 打开撤离清单，通过真实按钮分配并确认外城资产；6）等待处理和收起完成，回到 Mobile 后再次驾驶。修复 `BUG-0007` 后，该流程必须保持正式人口 `100`，不得调用开发人口修改；夹具仍只可提供获批的确定性资源和规则时间加速。该测试没有直接完成研究、创建建筑、注入产物或弹药、杀敌、切换城市模式或调用撤离提交，因此能证明正式输入链已经接通；它仍不能代替玩家对手感、文案、遮挡和视觉反馈的试玩确认。

## 正式开局的已知生产边界

正式 3D 会话按 GDD 的自然开局资源初始化，人口为 `100`、容量为 `150`。首轮研究站人口门槛为 `0`，自然开局只要成本、格位和城市规则满足即可施工；开发人口修改器不是解锁研究站的正式玩法。开局石料为 `0`，而现有建筑目录中的冶炼厂施工仍需要 `6` 石料。`IDEA-0019` 的 seed `8128` 正式 v2 世界固定提供 8 个铁矿、4 个石料、4 个能晶、4 个水和 4 个生物质节点；铁矿、石料和能晶节点继续经过统一采矿站兼容检查，因此自然开局有正式石料获取路径。建筑施工成本与 GDD A16.2 仍有既存差异，未经独立变更控制不得静默改数值；开发修改器也不能当作正式玩家解决方案。

背包、合成队列、3D 生产实例、43 节点正式研究进度、十波防御、建筑生命、完整会话统计与已确认撤离批次现已进入 schema `32` 正式 3D 存档。schema `31` 仍可迁移，无法追溯的旧局统计会明确标为“迁移前统计不完整”；schema `1–30` 继续保持旧 2D 身份。Deploying、Packing、活动战斗、已经确认的撤离处理中和容量阻塞撤离已有历史真实输入往返覆盖；未确认的菜单、选择、悬停、建造预览、结算面板和表现对象不保存，重开后由权威玩法状态重建。自动化与构建证据仍不是用户试玩或真实 Windows 10 和 Windows 11 的验收结论。

## IDEA-0015 正式存档的用户边界

进入默认 3D 场景后先在启动页选择“开始新进度”或“继续”。只有存在通过解码与语义校验的当前 schema `32` 主档、有效备份或可受控迁移的 schema `31` 3D 档时，“继续”才可用；开始新进度若会覆盖已有内容，必须先经过确认。游戏中从系统菜单选择“保存并退出”会写入同一个正式玩家槽位。直接关闭进程不能替代这个命令；若界面持续显示“自动存档失败，当前进度尚未保存”，应先保留现场并按存档 Bug 流程排查。

自动检查点在新进度就绪、首次展开、首座机枪塔建成、教学战斗开始、撤离批次确认、撤离工作提交和收起完成时触发，不按每帧或短周期反复写盘。正式主档为 `formal-world.json`；实现会先写同目录临时文件，刷新并复读验证，再更新 `.bak` 备份并原子替换主档。主档损坏而备份有效时会提示“主存档损坏，已恢复备份”；版本过新、旧 2D 档、读写失败或没有有效存档也会显示对应中文原因。

schema `1–30` 的文件属于旧 2D payload，会继续按原语义读取，绝不会被 3D 入口静默解释成新世界。3D 启动页发现旧 2D 存档时会明确说明其类型，“继续”不会把它载入 3D；玩家确认开始新的 3D 进度时，旧档先按原身份归档，不被伪装成 schema `31` 或 `32`。Task 14 已退役 `FormalPrototype`、专属控制器和 legacy build，但没有删除共享玩法规则、schema `1–30` decoder、迁移和测试样本。场景入口退役不等于旧档身份消失。

## IDEA-0017 十波结算与最近波前重试

任一正式防御塔完成后会触发单城市十波战役。战斗界面提供暂停、`1×` 和 `2×`；系统菜单与结算模态优先阻断建造和世界输入。第十波全部清除后只显示“防御战役完成”，这不是整个游戏通关，按钮只允许继续当前地图的沙盒；核心归零后显示“城市核心失守”，按钮只允许“读取最近波前”或“返回标题”。操作执行中不会重复提交；失败时面板保留并显示中文原因。

结算列出规则时间、完成波次、敌人击杀、塔伤害/击杀、耗材支出、建筑损失、核心生命、生产批次与效率、坚守/机动、迁移部分统计和修改器使用标记。没有符合运行资格的生产时间时，效率显示“无可用数据”，不显示伪造的 `0%`。开发修改器成功改变资源、科技、人口、城市形态、施工速度或施工完成状态后，本局会标记“使用过开发修改器”；只打开、搜索、查询、失败或没有实际变化不会标记。

失败重试读取独立内部的最近波前档。它不是第二个玩家可选存档槽，也不会覆盖 `formal-world.json`；只保存完整通过 schema `32` 身份、codec 与语义校验的 Formal3D envelope，新波前替换旧波前，写入失败保留旧有效档。玩家看到重试失败时应记录中文提示，不要手动复制或改写内部文件。该功能已通过相关聚焦自动化，但仍待用户试玩结算可读性、输入阻断、继续沙盒、失败重试和返回标题，并在真实 Windows 10 和 Windows 11 复验。

## 开发修改器只在开发版本出现

开发修改器用于开发时快速检查建造和场景状态，在 Unity Editor 或 Development Build 中按键盘上方数字键 `0` 开关；`F10` 不再触发修改器。资源和科技页都显示正式游戏中文名，并同时提供列表浏览与输入搜索；资源可按指定数量加入正式库存边界，科技可解锁单项、路线或全部内容，结果以中文反馈。`0` 在搜索框、数值输入框等文字控件聚焦时仍作为普通字符输入；建造栏第 10 格保留鼠标点击入口，不再占用 `0` 快捷键。修改器只用于测试，Release 无入口、无界面、无行为；发现它遮挡操作、抢走输入或与普通界面冲突时，按本页的排查步骤记录问题。

## 想修改某个功能先看哪里

先读[用户反馈与变更控制](06-User-Feedback-and-Change-Control-ZH.md)，确认该事项是否已经批准、属于修复还是新构思。然后到[项目清单](Generated/Project-Inventory-ZH.md)找相关场景、组件、程序集和文件，到[测试清单](Generated/Test-Inventory-ZH.md)找相应检查。需要复用已有内容时，再读[可复用项目目录](09-Reusable-Project-Catalog-ZH.md)，尤其要遵守“仅限场景”“冻结回归”和“禁止用于新功能”的边界。

## 新电脑交接最短路径

安装 Git、Git LFS、Unity Hub、Unity `2022.3.62f1` 及 Windows Build Support；克隆 Private 仓库后运行 `git lfs pull`，再用 Unity Hub 打开工程根目录。等待 Unity 恢复依赖后，打开默认 3D 场景，查看 Console，并先执行相应的自动检查。不要复制其他电脑的 `Library`、`Temp`、`Logs`、`Builds`、`TestResults` 或 `UserSettings`。

## 出问题时先做什么

先停止继续叠加操作，记录版本或提交、场景、复现步骤、期望和实际结果；截图或录屏比“看起来不对”更有用。接着查看[测试与 Bug 定位指南](08-Testing-and-Bug-Location-Guide-ZH.md)。自动报告只是排查起点，它告诉我们先从哪里看，不能替代复现、阅读上下文和人工确认。
