# 废土移动城市使用与开发入门

## 这份说明适合谁看

适合第一次打开这个项目的试玩者、非程序背景的协作者，以及刚加入项目的新开发者。先约定五个词：EditMode（不启动游戏画面、在编辑器里检查规则和资料的测试）、PlayMode（启动游戏流程、检查实际互动的测试）、组件（挂在场景物体上的一小块功能）、程序集（把相关代码一起编译成可用单元的集合）和稳定 ID（不随改名或资源替换而变化的固定编号）。不熟悉这些词也可以继续阅读；本页先讲该怎么用，技术细节放在后面的链接里。

## 游戏目前能做什么

当前默认入口是一座可移动的三维灰盒城市：可以进入三维场景，观察城市、地形、相机和建造相关交互。`IDEA-0011` 至 `IDEA-0013` 已接入采矿、冶炼和装配生产、建筑内部缓存与城市物流、30 格背包、两条应急合成配方、六节点首版科技树、顶部资源状态栏，以及一座机枪塔、一种啃噬者和一轮教学波组成的首个防御闭环。已实现待验证的 `IDEA-0014` 又接入正式 5 秒展开、8 秒收起、转换取消、战斗撤离、外城资产原子处理、撤离清单和处理队列，并用同一正式 3D 输入闭合恢复移动。本轮完整回归、项目质量门和四个正式构建已经通过；用户试玩和真实 Windows 复验仍未完成，不能写成已经人工验收。

## 明确尚未完成的内容

“移动→展开→建造→生产→防御→撤离”的完整正式循环已经完成实现、完整自动化、项目质量门和四个正式构建，当前状态为“已实现待验证”；仍须由用户试玩，并在真实 Windows 机器复验视觉、GPU、显存和内存。正式 3D 存档适配、前哨、迷雾、其余敌人与炮塔，以及完整首版美术仍属于后续工作。不要把灰盒废墟称为前哨，也不要把自动化通过描述成用户试玩完成。

## 怎样打开默认 3D 游戏

1. 用 Unity Hub 打开工程根目录，并确认编辑器版本为 `2022.3.62f1`。
2. 在 Project 窗口打开 `Assets/_Game/Scenes/GrayboxPrototype3D.unity`；这是默认 3D 场景，也是默认编辑和正式构建入口。
3. 按 Play 开始试玩；若 Console 有持续报错，先记下报错和操作步骤，不要直接改场景。
4. 想知道场景、脚本、界面所有者或美术接入点，请查看自动更新的[项目清单](Generated/Project-Inventory-ZH.md)。

## 两个场景的区别

默认 3D 场景是 `GrayboxPrototype3D.unity`，用于当前开发、试玩和默认构建。冻结 2D 场景是 `FormalPrototype.unity`，它保留旧版二维规则的回归基线，用来确认旧内容没有被意外破坏。冻结 2D 场景不是新功能模板；新功能从默认 3D 场景及其现有规则开始，并在需要时保留 2D 回归检查。

## 主要按键和界面

以场景实际显示的提示为准：相机可拖动，`Home` 可回到指定视角；建造、选择和城市展开相关操作由当前三维界面处理。`F` 用于展开、收起或取消正在进行的转换；已展开且存在外城资产时，`F` 会先打开撤离清单。`E` 打开背包与应急合成，`T` 打开六节点科技树；顶部资源栏显示城市库存、容量和近期净变化，点击资源可查看 15 种正式资源账本。生产详情显示配方、内部输入/输出、进度、物流连接、节点剩余量和停工原因，并允许对单座建筑暂停/恢复。可见但尚未满足条件的建筑点击原因，以及城市形态、范围、占用、地形、障碍、矿点和材料等蓝图放置失败，都固定显示在位置不变的建造栏正上方；提示不会形成世界点击死区。撤离清单与处理页不会自动暂停世界，仍允许 `Space` 战术暂停；容量不足时可按 `E` 把城市物资移入背包，返回原批次后重新检查容量。系统菜单优先于撤离界面，撤离界面优先于其他面板、建造和世界操作；若出现点击穿透或快捷键同时触发多个系统，应按 Bug 记录。开发修改器只会在开发版本出现，不能把它当作正式玩家功能，也不能据此判断平衡或发布体验。界面与输入的准确归属可在[项目清单](Generated/Project-Inventory-ZH.md)中查找。

## IDEA-0014 六段流程与真实输入边界

当前自动流程 `GrayboxFormalEvacuationVerticalSliceTests` 使用正式场景、虚拟键盘/鼠标和真实 Input System UI 主循环依次检查六段：1）驾驶城市到合法位置并按 `F` 展开；2）按 `B` 建成研究站并按 `T` 完成基础冶金、弹药装配和自动防御；3）用建造界面建立两座采矿站、两座冶炼厂、一座装配厂和一座机枪塔；4）等待真实采矿、加工、产弹、补弹、索敌和射击；5）敌人存活时按 `F` 打开撤离清单，通过真实按钮分配并确认外城资产；6）等待处理和收起完成，回到 Mobile 后再次驾驶。修复 `BUG-0007` 后，该流程必须保持正式人口 `100`，不得调用开发人口修改；夹具仍只可提供获批的确定性资源和规则时间加速。该测试没有直接完成研究、创建建筑、注入产物或弹药、杀敌、切换城市模式或调用撤离提交，因此能证明正式输入链已经接通；它仍不能代替玩家对手感、文案、遮挡和视觉反馈的试玩确认。

## 正式开局的已知生产边界

正式 3D 会话按 GDD 的自然开局资源初始化，人口为 `100`、容量为 `150`。首轮研究站人口门槛为 `0`，自然开局只要成本、格位和城市规则满足即可施工；开发人口修改器不是解锁研究站的正式玩法。开局石料为 `0`，而现有建筑目录中的冶炼厂施工仍需要 `6` 石料。`IDEA-0012` 已在 seed `8128` 原始内容区加入可到达的石料节点，并允许采矿站按同一资源节点真值采集石料，因此自然开局现在有正式石料获取路径。建筑施工成本与 GDD A16.2 仍有既存差异，未经独立变更控制不得静默改数值；开发修改器也不能当作正式玩家解决方案。

背包、合成队列、3D 生产实例、六节点研究进度以及正式撤离批次目前都是会话状态，退出后不会写入正式存档；schema 仍为 `30`。冻结 2D `FormalPrototype` 不接入这些新界面或撤离功能，只用于回归；但它复用共享稳定 `BuildingCatalog`，所以首轮研究站人口门槛 `0` 的解锁配置会同步修正并由 2D 回归保护。

## 开发修改器只在开发版本出现

开发修改器用于开发时快速检查建造和场景状态，在 Unity Editor 或 Development Build 中按键盘上方数字键 `0` 开关；`F10` 不再触发修改器。`0` 在搜索框、数值输入框等文字控件聚焦时仍作为普通字符输入；建造栏第 10 格保留鼠标点击入口，不再占用 `0` 快捷键。修改器出现时，请把它看作测试辅助；正式构建是否提供、提供什么功能，都必须另行确认。发现它遮挡操作、抢走输入或与普通界面冲突时，按本页的排查步骤记录问题。

## 想修改某个功能先看哪里

先读[用户反馈与变更控制](06-User-Feedback-and-Change-Control-ZH.md)，确认该事项是否已经批准、属于修复还是新构思。然后到[项目清单](Generated/Project-Inventory-ZH.md)找相关场景、组件、程序集和文件，到[测试清单](Generated/Test-Inventory-ZH.md)找相应检查。需要复用已有内容时，再读[可复用项目目录](09-Reusable-Project-Catalog-ZH.md)，尤其要遵守“仅限场景”“冻结回归”和“禁止用于新功能”的边界。

## 新电脑交接最短路径

安装 Git、Git LFS、Unity Hub、Unity `2022.3.62f1` 及 Windows Build Support；克隆 Private 仓库后运行 `git lfs pull`，再用 Unity Hub 打开工程根目录。等待 Unity 恢复依赖后，打开默认 3D 场景，查看 Console，并先执行相应的自动检查。不要复制其他电脑的 `Library`、`Temp`、`Logs`、`Builds`、`TestResults` 或 `UserSettings`。

## 出问题时先做什么

先停止继续叠加操作，记录版本或提交、场景、复现步骤、期望和实际结果；截图或录屏比“看起来不对”更有用。接着查看[测试与 Bug 定位指南](08-Testing-and-Bug-Location-Guide-ZH.md)。自动报告只是排查起点，它告诉我们先从哪里看，不能替代复现、阅读上下文和人工确认。
