# 废土移动城市使用与开发入门

## 这份说明适合谁看

适合第一次打开这个项目的试玩者、非程序背景的协作者，以及刚加入项目的新开发者。先约定五个词：EditMode（不启动游戏画面、在编辑器里检查规则和资料的测试）、PlayMode（启动游戏流程、检查实际互动的测试）、组件（挂在场景物体上的一小块功能）、程序集（把相关代码一起编译成可用单元的集合）和稳定 ID（不随改名或资源替换而变化的固定编号）。不熟悉这些词也可以继续阅读；本页先讲该怎么用，技术细节放在后面的链接里。

## 游戏目前能做什么

当前默认入口是一座可移动的三维灰盒城市。`IDEA-0011` 至 `IDEA-0017` 已接入生产物流、背包与合成、研究、撤离、正式存档和十波防御；`IDEA-0019` 使用覆盖整张 `64×48` 地图的 v2 宏区与 24 个固定资源节点。`IDEA-0020` 把正式基线推进到 44 节点研究、关注度、命轨、压力与文明 `1→2`；`IDEA-0022` 进一步使用 schema `34` 保存单小队远征、两城/前哨/运输和角色外交继承。`IDEA-0023` 至 `IDEA-0025` 把单位、角色、世界标记、科技树、建筑公告板和透明图主体比例接入统一表现目录。`IDEA-0027` 再把 44 个科技全部接入自然研究路径，并用 schema `35` 保存过载、剑意、感染、共鸣、护盾、精神操控、临时基因特质和一次性奖励账本。可替换二维表现不代表正式 3D 建模已经完成；人工试玩和真实 Windows 复验仍待实际结果收口。

## 明确尚未完成的内容

“移动→展开→建造→生产→防御→撤离”的历史核心循环及 `IDEA-0017` 十波战役已经完成当时的完整自动化和三项构建。结算与升阶排版、军队/多城/政务信息密度、公告板比例、科技树信息密度、真实节奏和真实 Windows 表现仍待用户验证。`IDEA-0023` 与 `IDEA-0024` 的透明图只替换程序化或界面占位；正式单位、城市、车辆、角色和建筑的 3D 模型、骨骼、动画、VFX 和 SFX 仍未完成，不得把公告板、建筑 Sprite 或科技树背景写成建模完成。

## 怎样打开默认 3D 游戏

1. 用 Unity Hub 打开工程根目录，并确认编辑器版本为 `2022.3.62f1`。
2. 在 Project 窗口打开 `Assets/_Game/Scenes/GrayboxPrototype3D.unity`；这是默认 3D 场景，也是默认编辑和正式构建入口。
3. 按 Play 开始试玩；若 Console 有持续报错，先记下报错和操作步骤，不要直接改场景。
4. 想知道场景、脚本、界面所有者或美术接入点，请查看自动更新的[项目清单](Generated/Project-Inventory-ZH.md)。

## 当前 3D 场景与历史 2D 入口

默认且唯一启用的游戏场景是 `GrayboxPrototype3D.unity`，用于当前开发、试玩和正式构建。Task 14 已退役历史 2D `FormalPrototype.unity`、47 个只服务该运行时的脚本（共 51 个 `MonoBehaviour` 类型）和 legacy 2D build；当前正式构建只有 Windows Release 3D、Windows Development 3D 和 macOS universal 3D 三类。退役后的聚焦和完整自动化、项目质量门、三项构建、官方文档生成/校验和正式验证记录均已通过。退役只移除旧场景运行入口，不删除共享纯规则、稳定 ID、schema `1–30` decoder、迁移、固定回归样本或旧档中文识别。

## 主要按键和界面

以场景实际提示为准：`F` 展开/收起或打开撤离，`E` 打开背包和合成，`T` 打开科技树，`M` 打开军队与远征，`N` 打开多城市/前哨/运输，`P` 打开角色、内政与外交，`Space` 战术暂停，`Home` 返回镜头或科技树全览。M/N/P 三页互斥；需要选择远征、次城或前哨位置时，左键提交地图目标、右键取消。搜索框有焦点时第一次 `Esc` 只释放焦点，第二次才关闭；模态期间世界输入不得穿透。满足条件时按 `U` 主动开始文明升阶。开发修改器只在 Editor/Development 中由数字键 `0` 打开，系统菜单始终优先；Release 无入口。

## IDEA-0024 科技树与开发验收界面

按 `T` 打开的正式科技树使用 reference-fidelity v3 的 `1920×1080` 全屏不透明工业面板，尽量复刻用户图二的实际比例而不是只保留主题。v3 不再使用纯黑空画布，改为蚀刻枪灰金属、六边工程纹、分区线路暗纹、磨损和旧铜镶边。顶部单排依次显示项目标题/搜索、五个路线按钮、五个结构化状态按钮以及“当前研究/最新可研究”；中部保持正式 `44` 节点、`49` 条依赖边和 `6` 个双前置桥，以四泳道、双子列、`180×58` 普通节点、`90×112` 桥节点和 `350×74` 公共根自下而上排布，节点直接使用项目已有科技图标、材料图标与真实数量；底部按参考图拆为身份说明、研究消耗、研究时间、开始/取消、前置条件和状态图例六舱。打开时选中最新可研究项但保留全树概览，`Home` 仍恢复全览。状态来自正式研究运行时，不从中文文案反推；背景不烘焙文字、节点、图标或按钮，也不改变 ResearchCatalog、研究效果或存档。

Editor 和 Development Build 的启动页额外显示“验收管理台”，可通过正式“继续”或“新游戏”入口进入，再在成功进入游戏后打开开发修改器；覆盖确认、无有效存档时的继续禁用和返回仍由正式启动流程负责。Release 不包含该入口。进入游戏后，M/N/P 既可由键盘互斥打开，也可在同一个文明扩展面板内点击“军队/世界/政务”页签切换；页签必须阻断世界点击，不能顺便创建移动目的地或地图目标。

当前内城使用稳定 `InnerCityPlatform`，平台为 `8×6`，每个内城格与地面格都按 `1:1` 的一个世界单位显示；移动城和展开城的视觉体量与既有玩法碰撞体分离，不能用放大碰撞体伪装视觉比例。BuildingCatalog 的 `35` 项已完成建筑使用共享透明 world Sprite，按占地比例竖直立在屋顶净空之上并朝向相机；施工中和废墟状态隐藏 Sprite。它们仍是可替换 billboard，不是正式建筑模型。

`IDEA-0024` 没有增加或迁移任何 schema 字段，该阶段正式存档仍为 schema `34`。本节只登记已经接入的生产文件和可执行检查边界；正式建模、用户人工视觉验收、真实 Windows 10 和 11 的视觉、GPU、显存和内存验证均未完成，不能由 Editor、Development 验收台或自动化结果代替。

## IDEA-0025 透明贴图比例规则

正式透明图继续保留原 PNG 和完整画布，不手工裁毁源图。统一视觉目录在构建时读取 Alpha≥16 的主体边界并扩一像素安全边：物品/科技的可见长边目标为槽位 `78%`，建筑/人物/单位为 `82%`，世界标记为 `80%`。科技节点、材料成本、顶部资源栏、背包、仓库、合成、建筑目录、人物头像和文明页都必须通过这项策略显示；面板、按钮九宫格、分隔线和整屏背景不套用内容图标裁切。

世界矿点的 Quad 直接使用主体 UV，因此 Near/Mid/Far 的参考像素表示实际矿物主体，而不是带透明边的 256 方形画布。完成建筑仍是屋顶上方的垂直公告板，但宽度和底边按可见 Alpha 计算。科技树背景保持原始 `16:9`，非 16:9 窗口允许留出底色，不允许纵横拉伸。替换任何正式图后运行“Build Unified Visual Catalog”即可重算边界；不得把比例补偿写回资源、建筑、科技或存档真值。

## IDEA-0027 高级科技状态操作边界

44 个科技节点保持原稳定 ID、49 条依赖边和 6 个桥节点；原 15 个预览节点已进入正式研究路径，合金装甲与御剑术仍要求文明 Lv.2。科技详情继续显示研究前后值、作用范围、触发、叠加和实际接线状态。防御详情会显示过载、剑意、感染、共鸣和精神操控；核心 HUD 同时显示生命与护盾。选中已解锁的激光塔后，可通过详情按钮触发 `5` 秒增幅、`3` 秒过热和总 `30` 秒冷却的能量过载，不新增散落快捷键。

跨帧状态由防御、建筑、军队或角色 owner 持有，UI 只读。暂停会冻结状态规则时间；受控敌人成为本次战役友军，可跨同一战役波次保留，但不计入敌军存活与胜负。主十波战役和压力战役使用彼此隔离的科技状态容器。维修、护盾和再生继续服从既有建筑运行、物流连接和玩家暂停真值，不由科技系统复制物流判断。

正式存档当前为 schema `35`。`34→35` 只建立空状态、空来源—目标周期窗口和空奖励账本，不根据旧科技或战斗历史补状态或补奖；活动状态、来源塔—目标敌人冷却、护盾、受控关系、临时特质和奖励幂等键均需往返。未知效果、悬空目标、错误来源塔、重复来源—目标、非法阶段/层数/时间、死亡角色特质和未挣得奖励键会拒绝加载，不静默修正。

Editor/Development 的数字键 `0` 管理台新增中文科技状态列表和输入搜索，可施加、设为一层、补满、清除、立即到期或触发选中激光塔过载；Release 不暴露入口。管理台结果只用于验收，不能替代自然研究、用户试玩或真实 Windows 10 和 11 验证。

## IDEA-0020 关注度、命轨与文明升阶操作

新进度会先要求从袖珍宇宙、虚空债、回溯锚点中选择一条并二次确认。袖珍宇宙改变各类首座生产旗舰的产出与坍缩范围；虚空债允许施工透支并按周期结算关注度；回溯锚点 Lv.1 有一槽、Lv.2 有两个稳定槽。命轨详情中的锚点创建、指定槽读取与清理都使用真实按钮，读取需要二次确认；锚点不是第二个玩家存档槽，跨等级读取会保留当前关注度、文明 Lv.2、命轨 Lv.2 和两个现役槽。

关注度达到 `30、60、90` 会依次安排压力，当前十波或另一压力活动时只排队。90 阶段出现程序化占位的晶壳母体。完成遗产解析、至少两座玩家已完成机枪塔、击败晶壳母体且当前有生产建筑可运行后，按 `U` 开始 `Scanning→Confirmed→Warning→Results`；成功只发生一次，并增加 `25` 关注度。系统菜单、命轨模态、文本输入、建造、背包、研究与结算拥有更高输入边界，不应同时触发升阶。

## IDEA-0014 六段流程与真实输入边界

当前自动流程 `GrayboxFormalEvacuationVerticalSliceTests` 使用正式场景、虚拟键盘/鼠标和真实 Input System UI 主循环依次检查六段：1）驾驶城市到合法位置并按 `F` 展开；2）按 `B` 建成研究站并按 `T` 完成基础冶金、弹药装配和自动防御；3）用建造界面建立两座采矿站、两座冶炼厂、一座装配厂和一座机枪塔；4）等待真实采矿、加工、产弹、补弹、索敌和射击；5）敌人存活时按 `F` 打开撤离清单，通过真实按钮分配并确认外城资产；6）等待处理和收起完成，回到 Mobile 后再次驾驶。修复 `BUG-0007` 后，该流程必须保持正式人口 `100`，不得调用开发人口修改；夹具仍只可提供获批的确定性资源和规则时间加速。该测试没有直接完成研究、创建建筑、注入产物或弹药、杀敌、切换城市模式或调用撤离提交，因此能证明正式输入链已经接通；它仍不能代替玩家对手感、文案、遮挡和视觉反馈的试玩确认。

## 正式开局的已知生产边界

正式 3D 会话按 GDD 的自然开局资源初始化，人口为 `100`、容量为 `150`。首轮研究站人口门槛为 `0`，自然开局只要成本、格位和城市规则满足即可施工；开发人口修改器不是解锁研究站的正式玩法。开局石料为 `0`，而现有建筑目录中的冶炼厂施工仍需要 `6` 石料。`IDEA-0019` 的 seed `8128` 正式 v2 世界固定提供 8 个铁矿、4 个石料、4 个能晶、4 个水和 4 个生物质节点；铁矿、石料和能晶节点继续经过统一采矿站兼容检查，因此自然开局有正式石料获取路径。建筑施工成本与 GDD A16.2 仍有既存差异，未经独立变更控制不得静默改数值；开发修改器也不能当作正式玩家解决方案。

背包、合成、生产、研究、防御、撤离、文明进程，军队/远征、settlement/运输、角色/内政/外交，以及高级科技活动状态已进入 schema `35` 正式 3D 存档。schema `31→32→33→34→35` 单向迁移；`33→34` 只创建清洁文明扩展初态，`34→35` 只创建空高级状态，不反推不存在的历史。schema `1–30` 继续保持旧 2D 身份。Sprite、公告板比例、锚点、染色、菜单选择、悬停和预览不保存，重开后由权威状态重新投影。

## IDEA-0015 正式存档的用户边界

进入默认 3D 场景后先选择“开始新进度”或“继续”。通过解码与语义校验的 schema `35` 主档或备份，或可单向迁移的 schema `31`、`32`、`33`、`34` 三维档可以继续；覆盖已有内容必须确认。系统菜单“保存并退出”写入同一个正式玩家槽位，直接关闭进程不能替代该命令。

自动检查点在新进度就绪、首次展开、首座机枪塔建成、教学战斗开始、撤离批次确认、撤离工作提交和收起完成时触发，不按每帧或短周期反复写盘。正式主档为 `formal-world.json`；实现会先写同目录临时文件，刷新并复读验证，再更新 `.bak` 备份并原子替换主档。主档损坏而备份有效时会提示“主存档损坏，已恢复备份”；版本过新、旧 2D 档、读写失败或没有有效存档也会显示对应中文原因。

schema `1–30` 属于旧 2D payload，继续按原语义识别，绝不会被 3D 入口静默解释成新世界；启动页会明确提示且“继续”不会载入。玩家新开 3D 进度时旧档先按原身份归档，不伪装成 schema `31`、`32`、`33`、`34` 或 `35`。Task 14 虽退役旧场景和 legacy build，仍保留共享规则、decoder、迁移和固定样本。

## IDEA-0017 十波结算与最近波前重试

任一正式防御塔完成后会触发单城市十波战役。战斗界面提供暂停、`1×` 和 `2×`；系统菜单与结算模态优先阻断建造和世界输入。第十波全部清除后只显示“防御战役完成”，这不是整个游戏通关，按钮只允许继续当前地图的沙盒；核心归零后显示“城市核心失守”，按钮只允许“读取最近波前”或“返回标题”。操作执行中不会重复提交；失败时面板保留并显示中文原因。

结算列出规则时间、完成波次、敌人击杀、塔伤害/击杀、耗材支出、建筑损失、核心生命、生产批次与效率、坚守/机动、迁移部分统计和修改器使用标记。没有符合运行资格的生产时间时，效率显示“无可用数据”，不显示伪造的 `0%`。开发修改器成功改变资源、科技、人口、城市形态、施工速度或施工完成状态后，本局会标记“使用过开发修改器”；只打开、搜索、查询、失败或没有实际变化不会标记。

失败重试读取独立内部最近波前档。它不是第二个玩家槽，也不会覆盖 `formal-world.json`；只保存完整通过当前 schema `35`、codec 与语义校验的 Formal3D envelope，新波前原子替换旧波前，失败保留旧有效档。

## 开发修改器只在开发版本出现

开发修改器用于快速检查建造、资源和文明进程，在 Unity Editor 或 Development Build 中按键盘上方数字键 `0` 开关；`F10` 无行为。资源、科技和文明进程动作都显示游戏中文名，并同时提供列表浏览与输入搜索；参数区支持数值、当前资源、压力阈值和锚点。查询不会标记本局，只有实际改变正式 owner 的命令才标记“使用过修改器”。强制命轨选择前 dev-only `0` 仍可打开，但系统菜单最高；文字控件聚焦时 U/0 不得穿透，第一次 `Esc` 释放焦点、第二次关闭面板。Release 无 Facade、无面板、无入口，修改器结果不能当作自然玩家流程或平衡证据。

## 新电脑交接最短路径

安装 Git、Git LFS、Unity Hub、Unity `2022.3.62f1` 及 Windows Build Support；克隆 Private 仓库后运行 `git lfs pull`，再用 Unity Hub 打开工程根目录。等待 Unity 恢复依赖后，打开默认 3D 场景，查看 Console，并先执行相应的自动检查。不要复制其他电脑的 `Library`、`Temp`、`Logs`、`Builds`、`TestResults` 或 `UserSettings`。

## 出问题时先做什么

先停止继续叠加操作，记录版本或提交、场景、复现步骤、期望和实际结果；截图或录屏比“看起来不对”更有用。接着查看[测试与 Bug 定位指南](08-Testing-and-Bug-Location-Guide-ZH.md)。自动报告只是排查起点，它告诉我们先从哪里看，不能替代复现、阅读上下文和人工确认。
