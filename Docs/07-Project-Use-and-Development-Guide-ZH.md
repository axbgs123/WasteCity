# 废土移动城市使用与开发入门

## 这份说明适合谁看

适合第一次打开这个项目的试玩者、非程序背景的协作者，以及刚加入项目的新开发者。先约定五个词：EditMode（不启动游戏画面、在编辑器里检查规则和资料的测试）、PlayMode（启动游戏流程、检查实际互动的测试）、组件（挂在场景物体上的一小块功能）、程序集（把相关代码一起编译成可用单元的集合）和稳定 ID（不随改名或资源替换而变化的固定编号）。不熟悉这些词也可以继续阅读；本页先讲该怎么用，技术细节放在后面的链接里。

## 游戏目前能做什么

当前默认入口是一座可移动的三维灰盒城市：可以进入三维场景，观察城市、地形、相机和建造相关交互。`IDEA-0011` 至 `IDEA-0013` 已接入采矿、冶炼和装配生产、建筑内部缓存与城市物流、30 格背包、两条应急合成配方、六节点首版科技树、顶部资源状态栏，以及一座机枪塔、一种啃噬者和一轮教学波组成的首个防御闭环。这些功能已通过自动化与构建，但用户试玩和真实 Windows 复验仍未完成，不能写成已经人工验收。

## 明确尚未完成的内容

“移动→展开→建造→生产→防御→撤离”的完整正式循环尚未完成。最小敌人与防御已经由 `IDEA-0013` 实现待验证；`IDEA-0014` 当前正在补正式展开/收起、战斗撤离、物资后果、撤离界面和六段连续验收。正式 3D 存档适配、前哨、迷雾、其余敌人与炮塔，以及完整首版美术仍属于后续工作。不要把灰盒废墟称为前哨，也不要把自动化通过描述成用户试玩完成。

## 怎样打开默认 3D 游戏

1. 用 Unity Hub 打开工程根目录，并确认编辑器版本为 `2022.3.62f1`。
2. 在 Project 窗口打开 `Assets/_Game/Scenes/GrayboxPrototype3D.unity`；这是默认 3D 场景，也是默认编辑和正式构建入口。
3. 按 Play 开始试玩；若 Console 有持续报错，先记下报错和操作步骤，不要直接改场景。
4. 想知道场景、脚本、界面所有者或美术接入点，请查看自动更新的[项目清单](Generated/Project-Inventory-ZH.md)。

## 两个场景的区别

默认 3D 场景是 `GrayboxPrototype3D.unity`，用于当前开发、试玩和默认构建。冻结 2D 场景是 `FormalPrototype.unity`，它保留旧版二维规则的回归基线，用来确认旧内容没有被意外破坏。冻结 2D 场景不是新功能模板；新功能从默认 3D 场景及其现有规则开始，并在需要时保留 2D 回归检查。

## 主要按键和界面

以场景实际显示的提示为准：相机可拖动，`Home` 可回到指定视角；建造、选择和城市展开相关操作由当前三维界面处理。`E` 打开背包与应急合成，`T` 打开六节点科技树；顶部资源栏显示城市库存、容量和近期净变化，点击资源可查看 15 种正式资源账本。生产详情显示配方、内部输入/输出、进度、物流连接、节点剩余量和停工原因，并允许对单座建筑暂停/恢复。系统菜单优先于这些面板，面板优先于建造和世界操作；若出现点击穿透或快捷键同时触发多个系统，应按 Bug 记录。开发修改器只会在开发版本出现，不能把它当作正式玩家功能，也不能据此判断平衡或发布体验。界面与输入的准确归属可在[项目清单](Generated/Project-Inventory-ZH.md)中查找。

## 正式开局的已知生产边界

正式 3D 会话按 GDD 的自然开局资源初始化，其中石料为 `0`；现有建筑目录中的冶炼厂施工仍需要 `6` 石料。`IDEA-0012` 已在 seed `8128` 原始内容区加入可到达的石料节点，并允许采矿站按同一资源节点真值采集石料，因此自然开局现在有正式石料获取路径。建筑施工成本与 GDD A16.2 仍有既存差异，未经独立变更控制不得静默改数值；开发修改器也不能当作正式玩家解决方案。

背包、合成队列、3D 生产实例和六节点研究进度目前都是会话状态，退出后不会写入正式存档；schema 仍为 `30`。冻结 2D `FormalPrototype` 只用于回归，没有接入这些新界面。

## 开发修改器只在开发版本出现

开发修改器用于开发时快速检查建造和场景状态，在 Unity Editor 或 Development Build 中按键盘上方数字键 `0` 开关；`F10` 不再触发修改器。`0` 在搜索框、数值输入框等文字控件聚焦时仍作为普通字符输入；建造栏第 10 格保留鼠标点击入口，不再占用 `0` 快捷键。修改器出现时，请把它看作测试辅助；正式构建是否提供、提供什么功能，都必须另行确认。发现它遮挡操作、抢走输入或与普通界面冲突时，按本页的排查步骤记录问题。

## 想修改某个功能先看哪里

先读[用户反馈与变更控制](06-User-Feedback-and-Change-Control-ZH.md)，确认该事项是否已经批准、属于修复还是新构思。然后到[项目清单](Generated/Project-Inventory-ZH.md)找相关场景、组件、程序集和文件，到[测试清单](Generated/Test-Inventory-ZH.md)找相应检查。需要复用已有内容时，再读[可复用项目目录](09-Reusable-Project-Catalog-ZH.md)，尤其要遵守“仅限场景”“冻结回归”和“禁止用于新功能”的边界。

## 新电脑交接最短路径

安装 Git、Git LFS、Unity Hub、Unity `2022.3.62f1` 及 Windows Build Support；克隆 Private 仓库后运行 `git lfs pull`，再用 Unity Hub 打开工程根目录。等待 Unity 恢复依赖后，打开默认 3D 场景，查看 Console，并先执行相应的自动检查。不要复制其他电脑的 `Library`、`Temp`、`Logs`、`Builds`、`TestResults` 或 `UserSettings`。

## 出问题时先做什么

先停止继续叠加操作，记录版本或提交、场景、复现步骤、期望和实际结果；截图或录屏比“看起来不对”更有用。接着查看[测试与 Bug 定位指南](08-Testing-and-Bug-Location-Guide-ZH.md)。自动报告只是排查起点，它告诉我们先从哪里看，不能替代复现、阅读上下文和人工确认。
