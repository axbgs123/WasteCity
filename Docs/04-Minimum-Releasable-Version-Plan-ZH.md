## 1. 产品边界

### 1.1 一句话定义

一款 2D 俯视角单机游戏：玩家驾驶可移动城市穿越废土，在资源点展开生产与防御；发展会提高关注度，迫使玩家在继续坚守和收起转移之间做选择。

### 1.2 项目目标

本版本只验证三件事：

1. 移动城市是否比固定基地更有操作价值和辨识度；
2. 展开生产的收益是否能与暴露、守城和撤离风险形成真实取舍；
3. 玩家是否能理解“生产弹药直接服务战斗”的因果链。

### 1.3 目标玩家

- 喜欢生产、建造或轻量塔防的 PC 玩家；
- 能接受中等学习成本，但希望数分钟内获得明确反馈的玩家；
- 对废土、移动基地和文明遗产题材感兴趣的玩家。

### 1.4 平台与模式

- 平台：Windows 10/11，64 位；
- 模式：纯单机；
- 输入：键盘与鼠标；
- 主要验收分辨率：1920×1080；
- 支持窗口和全屏；
- 不开发联网、多人、云存档或跨平台功能。

### 1.5 团队与时间

- 基准团队：1 名开发者；
- AI 只作为生产工具，不计为可独立负责验收的团队成员；
- 建议周期：6–8 周；
- 有效工作量：160–220 小时；
- 如果实际每周投入低于 20 小时，按阶段交付，不压缩测试门。

### 1.6 预算与发行决定

| 项目 | 当前决定 | 执行规则 |
|---|---|---|
| 现金预算上限 | 不作为当前约束 | 仍优先复用和低成本方案；实际购买或外包由项目负责人逐项决定 |
| 商业模式 | 当前不讨论 | 内部候选版不进行收费、定价或商业化设计 |
| 发布渠道 | 暂不发布 | 不制作Steam/itch.io商店页面，不提交平台审核 |
| AI订阅与额度 | 已有工具 | 不以增加账号或无限额度替代范围控制 |
| 外包 | 按需决定 | 核心玩法和关键验收不得依赖尚未确定的外包 |

### 1.7 明确不做

- 多城市、多星球、外交、政治和继承；
- 多人联机；
- 开放世界和完整程序化地图；
- 四条文明路线和完整科技树；
- 领袖“岑烬”及救援分支；
- 三条完整命轨和命轨升级；
- 多结局和大量过场；
- 完整 Mod 系统、Steam Workshop、脚本 Mod；
- 多语言；
- 手柄和自由按键重映射；
- 云存档、多槽位和旧版本复杂迁移；
- 六首独立配乐、全量装饰动画和全部概念资产；
- 正式版 B 卷中的长期系统。
- 商店页面、公开宣传片、平台审核和发布后运营。

## 2. 最小核心体验

### 2.1 核心循环

```text
驾驶城市探索
  → 在两个固定资源区中选择
  → 展开城市并开放建造网格
  → 建立铁矿→合金→弹药生产链
  → 建造炮塔抵御定向攻击
  → 发展提高关注度
  → 坚守或收起城市转移一次
  → 击败两阶段 Boss
  → 完成升阶并进入结算
```

### 2.2 长、中、短反馈

- 长循环，20–35 分钟：移动→生产→防守→转移→Boss→结算；
- 中循环，5–8 分钟：选址→展开→扩产→承受攻击→回收或收起；
- 短循环，20–60 秒：采集/生产→获得资源→建造/补充弹药→防御提高。

### 2.3 玩家操作

| 操作 | 默认输入 | P级 |
|---|---|---:|
| 城市移动 | WASD | P0 |
| 选择、建造、确认 | 鼠标左键 | P0 |
| 取消、返回 | 鼠标右键或 Esc | P0 |
| 镜头移动 | 鼠标中键拖动 | P1 |
| 镜头缩放 | 滚轮 | P1 |
| 展开/收起 | X | P0 |
| 建造面板 | B | P1 |
| 暂停 | Space | P1 |
| 1倍/2倍速度 | 1/2 | P1 |

### 2.4 胜利、失败和重试

完成条件：

- 击败简化版晶壳母体；
- 城市核心仍存活；
- 至少一座生产建筑仍在运行；
- 玩家主动执行一次升阶并进入结算。

失败条件：

- 城市核心耐久归零。

重试：

- 失败后 10 秒内可重新开始；
- P0 阶段允许直接重开当前流程；
- P1 阶段加入 Boss 前单检查点。

### 2.5 核心乐趣验证门

在任何正式美术批量生产前，使用灰盒版本邀请 5 名未参与设计的玩家测试。

继续开发必须同时满足：

1. 至少 3/5 玩家能主动说出“城市本身会移动并参与战斗”；
2. 至少 4/5 玩家能在少量提示下完成展开、采矿和建塔；
3. 至少 3/5 玩家在受到压力后主动考虑收起或转移；
4. 至少 4/5 玩家能指出弹药短缺来自生产瓶颈；
5. 无阻断流程、持续报错或无法恢复的失败。

如果未满足：

- 暂停命轨、Boss表现、叙事和正式美术；
- 优先修改移动手感、展开收益、资源反馈和收起代价；
- 连续两轮仍有三项不达标时，停止当前方案扩展，重新评审核心循环。

## 3. 功能优先级

### 3.1 优先级定义

| 优先级 | 定义 | 处理规则 |
|---|---|---|
| P0 | 没有就不能形成完整游戏 | 必须完成并通过测试 |
| P1 | 最小发布版本需要 | 核心门通过后开发；延期时允许简化 |
| P2 | 后续版本可增加 | 不进入当前版本关键路径 |
| P3 | 成本过高或当前无调用者 | 当前删除，只保留设计记录 |

### 3.2 功能清单

| 功能 | 优先级 | 当前处理 | 必要性与验收摘要 |
|---|---:|---|---|
| 城市移动、碰撞、转向 | P0 | 保留 | 可连续驾驶，不穿越阻挡，不持续报错 |
| 城市碾压与尸体资源 | P0 | 保留 | 移动城市能直接击杀基础敌人并产生反馈 |
| 展开、收起与取消 | P0 | 保留 | 状态切换稳定；移动和建造限制正确 |
| 固定地图和两个资源区 | P0 | 简化 | 不做随机；两个选址存在收益/风险差异 |
| 建造网格与合法性检测 | P0 | 保留 | 占格、冲突、取消和资源扣除正确 |
| 铁矿、合金、弹药 | P0 | 保留 | 资源不出现负数和凭空生成 |
| 采矿、冶炼、装配、机枪塔 | P0 | 保留 | 完整生产链可持续支持一座塔 |
| 城墙 | P1 | 保留一种 | 提供最小防线布置选择 |
| 回收和80%返还 | P1 | 简化 | 非战斗即时回收；战斗读条可延期 |
| 敌人生命、伤害与寻路 | P0 | 保留 | 两种普通敌人可完成攻击和死亡流程 |
| 两轮攻击 | P0 | 保留 | 第一轮教学，第二轮制造弹药压力 |
| 两阶段关注度 | P1 | 简化 | 变化原因可见，阈值每局只触发一次 |
| 晶壳母体 | P1 | 两阶段 | 可被击败；所有高伤害攻击有预警 |
| Boss战中转移一次 | P1 | 简化 | 固定地形和固定窗口，不做复杂动态追击 |
| 两条简化命轨 | P1 | 核心门后决定 | 只做一次选择和单一规则效果，不升级 |
| 结尾升阶 | P1 | 简化 | 结算前按钮和短演出，不做完整科技树 |
| 最小HUD、目标和提示 | P0/P1 | 保留 | 玩家始终知道资源、城市状态和当前目标 |
| 音量、窗口、全屏、震动开关 | P1 | 简化 | 设置独立保存 |
| 退出保存 | P1 | 保留 | 保存当前最小状态；损坏不覆盖有效备份 |
| Boss前单检查点 | P1 | 保留 | 失败后可恢复核心状态 |
| 本地测试日志 | P1 | 简化 | 只记录核心循环事件，不联网 |
| 领袖、人口、救援分支 | P2 | 延期 | 不直接验证移动城市核心 |
| 五科技、研究队列 | P2 | 延期 | 改用流程目标和少量直接升级 |
| 生物质经济 | P2 | 延期 | 避免第二套经济用途增加认知负担 |
| 局部随机、迷雾、遗迹 | P2 | 延期 | 固定地图更利于验证和调试 |
| 第三条命轨与命轨升级 | P2 | 延期 | 避免规则组合测试矩阵扩大 |
| 多槽位、云存档 | P3 | 删除 | 当前没有首发必要性 |
| 旧版本迁移、未知Mod代理 | P3 | 删除 | 当前没有已发布旧存档和外部Mod |
| 外部Mod加载和Workshop | P3 | 删除 | 长期安全与兼容维护成本过高 |

## 4. 首发内容上限

### 4.1 地图

- 1 张固定地图，建议 64×48 或按实际镜头调整；
- 出生区、安全矿区、高收益矿区、Boss入口和转移狭口；
- 两个资源区；
- 一次主流程转移；
- 不做随机地图、非主线遗迹和程序化生成。

### 4.2 资源和建筑

资源：

- 铁矿；
- 合金；
- 弹药。

建筑：

- 城市核心；
- 采矿站；
- 冶炼厂；
- 装配厂；
- 机枪塔；
- 城墙。

基准生产链：

```text
2 采矿站 → 2 冶炼厂 → 1 装配厂 → 1 座持续射击机枪塔
```

### 4.3 敌人和波次

普通敌人：

1. 啃噬者：基础近战，可被城市碾压；
2. 啸叫者或晶壳兽二选一：提供远程或重甲压力。

Boss：

- 晶壳母体，两阶段；
- 阶段一验证基础防线；
- 阶段二迫使玩家考虑转移；
- 不做护盾恢复、复杂召唤组合和多种危险区叠加。

波次：

- 教学攻击；
- 高压攻击；
- Boss。

### 4.4 叙事

只保留三个节点：

1. 开局：城市来自前代文明；
2. 中段：攻击在主动追踪生产活动；
3. 结尾：升阶信号被未知存在确认。

不解释完整联邦史、监察者三派、循环次数和正式版结局。

## 5. 资产生产范围

### 5.1 原则

- 灰盒通过前不批量生产正式美术；
- 同系列资产共用底座、尺寸、材质、光向和色板；
- 规则图形优先在 Unity 或矢量工具中制作；
- AI图只作为概念或初稿，进入游戏前必须人工检查；
- 每项外部资产记录来源、工具、日期、修改、许可和最终路径；
- 来源或使用权限不清晰的资产不得进入候选构建。

### 5.2 最小美术清单

| 分类 | 最大数量 | 复用策略 |
|---|---:|---|
| 城市主体 | 1套 | 收起和展开共用主体，状态使用部件和灯光切换 |
| 建筑 | 5–6个 | 共用底座、接口、阴影和状态覆盖 |
| 普通敌人 | 2个 | 共用受击、死亡和阴影逻辑 |
| Boss | 1个主体、2阶段 | 阶段变化使用部件、颜色和特效，不重做整套角色 |
| 地面 | 1套模块 | 通过贴花和色相区分两资源区 |
| UI | 1套 | 面板、按钮、提示、资源项组件复用 |
| 图标 | 约15个 | SVG母版导出多尺寸PNG |
| 特效 | 8–10组 | 粒子、材质和参数复用 |

禁止在MRV中制作全部48项原美术清单。

### 5.3 最小音频清单

- 菜单/结尾短音乐：1条；
- 探索与经营循环：1条；
- 战斗与Boss循环：1条；
- 核心音效：10–15个；
- 同类命中、建造和UI音效允许调音高、音量和混音复用；
- 不为每个建筑和敌人单独制作完整声音套件。

## 6. 技术方案

### 6.1 技术栈

- Unity `2022.3.62f1`；
- C#；
- URP 2D Renderer；
- Unity Input System；
- Unity Test Framework / NUnit；
- TextMeshPro；
- Git 与 Git LFS。

### 6.2 架构约束

- 纯规则优先使用普通 C# 类；
- MonoBehaviour只负责场景适配、生命周期和表现；
- 内容配置使用 ScriptableObject；
- 系统间通过公开接口和类型安全事件通信；
- UI只读取公开状态并发送命令，不直接修改规则字段；
- 当前只允许一套库存、时钟、事件总线、本地化和存档入口；
- 稳定ID使用至少三段小写格式，例如 `core.resource.iron`；
- 玩家可见文本使用TextKey；
- 禁止引入ECS、大型依赖注入、联网框架或完整Mod框架；
- 没有当前调用者的抽象层不得开发。

### 6.3 性能目标

- 1920×1080目标60 FPS；
- 高压场景1%低帧不低于45 FPS；
- MRV同屏目标上限：80名敌人、200个活跃弹丸；
- 连续运行30分钟无明显内存持续增长；
- 候选构建无持续Console错误、异常刷屏或阻断流程问题。

正式版150敌人/500弹丸压力目标不进入MRV验收。

## 9. 测试计划

### 9.1 测试轮次

| 轮次 | 时间 | 人数 | 重点 |
|---|---|---:|---|
| T0开发者自测 | 每日 | 1 | 新功能、回归、明显Bug |

小样本使用“人数/总人数”和观察证据，不使用看似精确的百分比统计。

### 9.2 自动化测试最低范围

- 稳定ID和内容重复；
- 库存增减、容量和负数保护；
- 生产输入、输出和阻塞；
- 展开/收起状态转换；
- 建造占格、扣款、取消和回收；
- 伤害、死亡和对象池回收；
- 关注度阈值幂等；
- 检查点保存/恢复；
- 主流程PlayMode冒烟；
- Windows构建场景引用。

### 9.3 Bug严重度

| 等级 | 定义 | 候选版规则 |
|---|---|---|
| P0 阻断 | 崩溃、坏档、无法继续、无法启动、核心资源无限或负数 | 必须为0 |
| P1 严重 | 核心系统错误、明显性能问题、主要流程需要重开 | 必须修复；无法修复则删除相关功能 |
| P2 一般 | 局部反馈、UI、数值或非阻断表现问题 | 可作为已知问题保留，但必须记录 |
| P3 轻微 | 装饰、罕见边缘和不影响理解的问题 | 进入后续待办 |

### 9.4 性能与兼容

- 1920×1080窗口和全屏；
- 60 FPS目标，高压1%低帧≥45 FPS；
- 30分钟连续运行；
- 中文用户名和中文存档路径；
- 退出保存和首次启动；
- 解压到干净目录运行；
- Windows输入法、焦点、DPI和常见分辨率；
- 杀毒软件误报检查；
- 无开发者本机绝对路径泄漏。

- Windows干净环境完整通关；

- 存档与失败重试通过；
- 所有候选版资产来源和许可可追溯；

“代码已经写完”“编辑器中能运行”或“美术已经生成”均不能单独视为完成。
