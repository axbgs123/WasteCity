## 1. 文档定位

本文件记录正式版持续开发的真实基线与后续顺序。主 GDD `01-Game-Design-Document-ZH.md` 提供产品和系统目标；本文件负责把目标拆成可独立验收、可提交、可回归的开发里程碑。

历史 MRV 与 14 天 Demo 计划继续保留，但不再限制正式版后续功能范围。发生冲突时：

1. 已运行代码、自动化测试和 Windows 构建结果代表当前事实；
2. 主 GDD 代表正式版目标；
3. 本路线图代表后续实现顺序；
4. 历史 MRV、Demo 计划和旧进度记录只用于追溯决策。

- 领袖救援、主动技能、基因剪接光环和意识网络救援；

### 2.3 表现资源接口

当前功能默认使用灰盒 Sprite、色块和程序化占位。所有新增单位、建筑、角色和关键特效必须：

- 使用稳定 ID；
- 通过 `VisualSlot`、`VisualDefinition` 和 `VisualLibrary` 接入；
- 允许后续用 Prefab 或 Sprite 替换，不修改玩法逻辑；
- 不把碰撞、生命、攻击或存档状态放入纯美术 Prefab；
- 正式模型/贴图导入前记录来源、许可证和目标 Unity 路径。

## 3. 后续开发阶段

### 阶段 F1：单城市正式玩法补齐

目标：让四条路线在单城市循环内都有完整生产、防御和单位选择。

1. 统一友军单位规则：目标选择、集结点、脱战跟随、死亡统计和组织再生（已实现：`d5baf17`；真实 Windows 冒烟待补）；
2. 科技路线无人机与过载机制（已实现：`fd42357`；正式无人机美术和真实 Windows 冒烟待补）；
3. 血肉路线感染/寄生状态闭环（已实现：`9792fcb`；正式巨兽美术反馈和真实 Windows 冒烟待补）；
4. 修仙路线剑意、御剑台升级与傀儡维护（已实现：`6200703`；正式美术和真实 Windows 冒烟待补）；
5. 灵能路线精神灼烧、集体意识的单城等价效果（已实现：`95abb35`；正式美术和真实 Windows 冒烟待补）；
6. 发电站、代谢炉、意识网络等缺失路线建筑（已实现：`2e13d6e`；正式资源拆分、美术和真实 Windows 冒烟待补）；
7. 四路线资源、建筑和研究说明统一显示。

验收门：每个功能先写规则测试；全部 EditMode/PlayMode、编译、Windows 构建和冒烟通过；每个里程碑独立提交。

### 阶段 F2：跨路线桥节点

目标：把六个桥节点从研究文本升级为可观察、可制造、可存档的玩法。

1. 灵能机甲厂；
2. 高周波飞剑铸造台；
3. 生物机库与半机械巨兽；
4. 灵植园；
5. EMP 塔与机械敌人瘫痪；
6. 血肉灵丹的三倍效果和突变风险。

桥节点不得复制第二套生产或战斗系统，必须复用现有资源库存、建筑运行时、友军控制器、伤害矩阵和存档入口。

### 阶段 F3：军队与远征

目标：从自动护城单位扩展到玩家可理解、可指挥的军队系统。

- 军队面板、单位分类、上限和维护成本；
- 集结点、守卫/跟随/出征三种命令；
- 领袖带队士气加成；
- 远征结算、伤亡、战利品和撤退；
- 存档与加载后的命令恢复；
- 占位选择框、路径线和状态图标。

本阶段先做单城市军队，不提前实现多城市共享军队。

### 阶段 F4：多城市与正式世界层

目标：实现主 GDD 正式版的多城市决策价值。

- 城市实例 ID 与城市存档模块化；
- 多城市总览和焦点切换；
- 城市间资源运输与风险；
- 多城市关注度、危机轨道和监察者打击；
- 集体意识共享研究的真实效果；
- 世界地图节点与城市迁移。

进入本阶段前必须先完成存档 schema 迁移设计和旧单城市存档回归样本。

### 阶段 F5：外交、继承与长期文明

目标：实现长期正式版的政治和叙事层。

- 势力关系、外交选项与代价；
- 领袖忠诚、受伤、死亡与继承；
- 文明等级 3 以上的条件、奖励和危机；
- 三派监察者叙事与长期结局；
- 跨循环继承与多存档管理。

该阶段不得早于 F4 的数据和存档稳定门。

### 阶段 F6：正式表现、可用性与候选版

目标：用正式资源替换占位并形成可长期试玩的内部候选版本。

- UI 信息架构、设置、键位和可访问性；
- 城市、建筑、单位、敌人、特效、音频和音乐资源替换；
- 统一比例、锚点、排序层、碰撞代理和动画事件；
- 首次引导、科技说明、战斗反馈和失败解释；
- 性能预算、长局稳定性、存档回归和 Windows 兼容；
- 人工试玩、问题分级、版本说明和候选包归档。

## 4. 固定质量门

每个功能里程碑必须同时满足：

1. 开始前 `git status`，不覆盖用户改动；
2. 规则测试先于运行时实现；
3. 纯规则优先为普通 C#，MonoBehaviour 只适配输入、场景、物理和显示；
4. 不删除测试、不降低断言、不忽略异常；
5. 全部 EditMode 测试通过；
6. 全部 PlayMode 测试通过；
7. Unity 无界面编译通过；
8. Windows 构建成功；
9. 独立程序至少 12 秒冒烟，0 运行时异常；
10. `git diff` 只包含当前里程碑；
11. 提交后工作区干净；
12. 新表现提供稳定的正式美术替换槽。

## 5. GitHub 与保密要求

- GitHub 仓库必须设置为 **Private**；
- 当前不创建公开 Release、Pages、公开 Issue 模板或商店页面；
- Unity 工程与本文档目录放在同一个仓库；
- `Library/`、`Temp/`、`Logs/`、`Builds/`、`TestResults/` 和本地存档不提交；
- 大型二进制资源继续由 Git LFS 管理；
- 不提交账号令牌、机器凭据、个人存档或许可证文件；
- 正式美术加入后按资产批次提交，并保留来源与许可证记录。
