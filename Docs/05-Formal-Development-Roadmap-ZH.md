## 1. 文档定位

### 2.3 表现资源接口

当前功能默认使用灰盒 Sprite、色块和程序化占位。正式目标是保持同一俯视规则的 3D 场景，不改成第三人称。所有新增单位、建筑、角色和关键特效必须：

- 使用稳定 ID；
- 通过 `VisualSlot`、`VisualDefinition` 和 `VisualLibrary` 接入；
- 允许后续用 3D Prefab、动画或 Sprite 替换，不修改玩法逻辑；
- 不把碰撞、生命、攻击或存档状态放入纯美术 Prefab；
- 正式模型/贴图导入前记录来源、许可证和目标 Unity 路径。

## 3. 后续开发阶段

### 阶段 F1：单城市正式玩法补齐

目标：让四条路线在单城市循环内都有完整生产、防御和单位选择。

1. 统一友军单位规则：目标选择、集结点、脱战跟随、死亡统计和组织再生（已实现：`d5baf17`；真实 Windows 冒烟待补）；
2. 科技路线无人机与过载机制（已实现：`fd42357`；正式无人机美术和真实 Windows 冒烟待补）；
3. 血肉路线感染/寄生状态闭环（已实现：`9792fcb`；正式巨兽美术反馈和真实 Windows 冒烟待补）；
4. 修仙路线剑意、御剑台升级与傀儡维护（已实现：`6200703`；正式美术和真实 Windows 冒烟待补）；
5. 灵能路线精神灼烧、集体意识的单城等价效果（已实现：`95abb35`；正式美术和真实 Windows 冒烟待补）；
6. 发电站、代谢炉、意识网络等缺失路线建筑（已实现：`2e13d6e`；正式资源拆分、美术和真实 Windows 冒烟待补）；
7. 四路线资源、建筑和研究说明统一显示（已实现：`970ad60`；真实 Windows 冒烟待补）。

验收门：每个功能先写规则测试；全部 EditMode/PlayMode、编译、Windows 构建和冒烟通过；每个里程碑独立提交。

### 阶段 F1A：单城市场景与交互基础

目标：在进入大规模内容扩张和 3D 表现前，使单城市的移动、内外城建造、生产、物流、角色与前哨交互形成稳定且可读的基础层。

- 明确移动态和展开态：移动中允许内城轻型施工与维持，地面施工、重型工业和长周期研究需要展开；
- 移动态默认控制城市、展开态默认控制领袖；补齐目的地自动寻路、基础地形阻挡和展开位置合法性（规则与 2D 交互基础已实现：`8693086` 至 `11c90b9`；镜头跟随、自由拖动与快速返回已实现：`9bbcca5`、`118b3f0`；自动驾驶科技升级、正式表现和真实 Windows 冒烟待补）；
- 建立内城、地面、两者皆可的建筑位置标签，以及移动可运行、仅展开运行、地形依赖等运行标签（规则基础已实现：`60b891e`；内城放置交互、前哨和真实 Windows 冒烟待补）；
- 建造面板提供快捷栏、分类、搜索、置灰原因和可见性规则；隐藏、未接触路线和唯一特殊建筑不进入普通列表；
- 放置交互支持预览、合法性原因、旋转、连续放置、拖动城墙和取消规划；
- 保留城市范围内自动物流，补齐产销、缺口、阻塞、优先级和请求库存的可观察反馈；
- 建筑脱离城市范围后进入前哨状态，保留库存并显示补给、维护和通信问题；提供撤离清单与基础受袭警报；
- 迷雾采用未探索隐藏、已探索变暗、当前视野实时更新、最后情报可过期的规则；
- 领袖允许低效率手工采集以处理开局或紧急缺口，但不得替代自动采矿闭环；
- 镜头默认跟随当前控制对象，支持自由拖动和快速返回（2D 交互已实现：`9bbcca5`、`118b3f0`）；暂停允许规划和下令但不推进规则时间；
- 领袖基础行为可由 AI 执行，玩家可主动接管；Demo 继续使用抽象城市生产力，不生成实体施工工人；
- `BUG-0001` 必须在单独完成复现与验收澄清后修复，不得用新界面重构掩盖原问题。

验收门：先使用当前 2D 占位完成规则与交互验证；全部规则测试、PlayMode 主循环、旧存档回归、Windows 构建和真实环境冒烟通过后，才进入 F1B。

### 阶段 F1B：俯视 3D 垂直切片

目标：不重做核心玩法的前提下，把一个完整单城市循环转换为可验证的俯视 3D 表现。

- 保留规则网格、稳定 ID、输入动作、存档模块、逻辑坐标和碰撞代理；
- 建立 3D 地形、移动城市、内城平台、领袖、基础建筑、一个敌人和关键反馈的占位 Prefab；
- 相机继续采用俯视跟随、自由拖动与缩放，不进入第三人称；
- 玩法真值留在规则与运行时组件，模型、动画、材质和特效不得持有生产、生命、攻击或存档真值；
- 先完成“移动→展开→内外城建造→生产→防御→撤离”一条垂直切片，再决定正式资源批量制作。

验收门：2D 基线测试继续通过；3D 场景完成同一主循环；镜头、寻路、网格落点、选择、遮挡、性能和 Windows 构建具有独立验收记录。

### 阶段 F2：跨路线桥节点

目标：把六个桥节点从研究文本升级为可观察、可制造、可存档的玩法。

1. 灵能机甲厂；
2. 高周波飞剑铸造台；
3. 生物机库与半机械巨兽；
4. 灵植园；
5. EMP 塔与机械敌人瘫痪；
6. 血肉灵丹的三倍效果和突变风险。

桥节点不得复制第二套生产或战斗系统，必须复用现有资源库存、建筑运行时、友军控制器、伤害矩阵和存档入口。

### 阶段 F3：军队与远征

目标：从自动护城单位扩展到玩家可理解、可指挥的军队系统。

- 军队面板、单位分类、上限和维护成本；
- 集结点、守卫/跟随/出征/撤退命令，以小队为最小玩家指挥粒度；
- 领袖带队士气加成；
- 远征结算、伤亡、战利品和撤退；
- 存档与加载后的命令恢复；
- 占位选择框、路径线和状态图标。

本阶段先做单城市军队，不提前实现多城市共享军队。

### 阶段 F4：多城市与正式世界层

目标：实现主 GDD 正式版的多城市决策价值。

- 城市实例 ID 与城市存档模块化；
- 多城市总览和焦点切换；
- 已通信城市允许自由查看；直接控制前期需要领袖到场，远程指挥科技解锁后才允许跨城接管；
- 城市、前哨和生产区之间的实体资源运输、护送、拦截与风险；
- 前哨库存、补给、能源、维护、通信、委派角色、自动防御和分级受袭通知；
- 多城市关注度、危机轨道和监察者打击；
- 集体意识共享研究的真实效果；
- 世界地图节点与城市迁移。

进入本阶段前必须先完成存档 schema 迁移设计和旧单城市存档回归样本。

### 阶段 F5：外交、继承与长期文明

目标：实现长期正式版的政治和叙事层。

- 势力关系、外交选项与代价；
- 领袖倒地时限、角色或城市救援、重伤、永久伤势、遗体和装备回收；
- 临时议会、指定继承人、竞争候选、紧急选举和路线/制度继承方式；
- 忠诚、派系、政变、内战、城市归属与新领袖长期路线影响；
- 意识备份等路线能力对正常死亡流程的有代价改写；
- 文明等级 3 以上的条件、奖励和危机；
- 三派监察者叙事与长期结局；
- 跨循环继承与多存档管理。

该阶段不得早于 F4 的数据和存档稳定门。

### 阶段 F6：正式 3D 表现、可用性与候选版

目标：用正式资源替换占位并形成可长期试玩的内部候选版本。

- UI 信息架构、设置、键位和可访问性；
- 基于 F1B 已验证接口批量替换城市、建筑、单位、敌人、地形、特效、音频和音乐资源；
- 统一比例、锚点、排序层、碰撞代理和动画事件；
- 首次引导、科技说明、战斗反馈和失败解释；
- 性能预算、长局稳定性、存档回归和 Windows 兼容；
- 人工试玩、问题分级、版本说明和候选包归档。

## 4. 固定质量门

每个功能里程碑必须同时满足：

1. 开始前 `git status`，不覆盖用户改动；
2. 规则测试先于运行时实现；
3. 纯规则优先为普通 C#，MonoBehaviour 只适配输入、场景、物理和显示；
4. 不删除测试、不降低断言、不忽略异常；
5. 全部 EditMode 测试通过；
6. 全部 PlayMode 测试通过；
7. Unity 无界面编译通过；
8. Windows 构建成功；
9. 独立程序至少 12 秒冒烟，0 运行时异常；
10. `git diff` 只包含当前里程碑；
11. 提交后工作区干净；
12. 新表现提供稳定的正式美术替换槽。
