### 2.3 表现资源接口

当前功能默认使用灰盒 Sprite、色块和程序化占位。正式目标是保持同一俯视规则的 3D 场景，不改成第三人称。所有新增单位、建筑、角色和关键特效必须：

- 使用稳定 ID；
- 通过 `VisualSlot`、`VisualDefinition` 和 `VisualLibrary` 接入；
- 允许后续用 3D Prefab、动画或 Sprite 替换，不修改玩法逻辑；
- 不把碰撞、生命、攻击或存档状态放入纯美术 Prefab；
- 正式模型/贴图导入前记录来源、许可证和目标 Unity 路径。

### 2.4 2D 冻结点与 3D 迁移决策

- 镜头里程碑完成并通过全量验证后，冻结现有 2D 功能基线；冻结不等于删除，`FormalPrototype`、规则层、稳定 ID、schema `30` 存档和现有自动化测试全部保留；
- 停止新增仅服务于 2D 场景的交互实现。尚未完成的建造菜单、内外城放置、物流观察、前哨、迷雾、领袖交互和其余 F1A 功能转到 3D 基础场景继续实现，不先制作重复的 2D 版本；
- 3D 迁移审计、设计规格、可执行计划和首个可回退“可操作 3D 基础”均已完成并通过独立验收；现有 2D 冻结基线继续保留；
- 默认编辑/构建入口已经独立切换到 3D；`FormalPrototype` 继续作为启用的 2D 回归场景保留，不进入默认正式构建；
- 首轮 3D 只使用方块、基础材质和占位 Prefab，不批量制作或导入正式模型、美术、动画与特效；
- 本决策只改变实现顺序，不改变主 GDD 的产品目标、已确认玩法规则或真实 Windows 10/11 冒烟门。

## 4. 固定质量门

每个功能里程碑必须同时满足：

1. 开始前 `git status`，不覆盖用户改动；
2. 规则测试先于运行时实现；
3. 纯规则优先为普通 C#，MonoBehaviour 只适配输入、场景、物理和显示；
4. 不删除测试、不降低断言、不忽略异常；
5. 全部 EditMode 测试通过；
6. 全部 PlayMode 测试通过；
7. Unity 无界面编译通过；
8. Windows 构建成功；
9. 独立程序至少 12 秒冒烟，0 运行时异常；
10. `git diff` 只包含当前里程碑；
11. 提交后工作区干净；
12. 新表现提供稳定的正式美术替换槽；
13. 3D 迁移不得删除 2D 回归基线，并必须保留可关闭或移除新灰盒场景的回退路径。
14. `DOC-0001` 质量基础设施：每次功能修改都要更新目录映射和对应测试，生成技术附录后做只读验证；生成器不改变玩法审批、人工试玩或验收结论。

这项自动化只帮助发现目录、文档和测试证据是否遗漏，不计入玩法完成度，也不提高主 GDD 或美术完成百分比。
