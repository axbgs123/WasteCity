### 2.3 表现资源接口

当前功能默认使用灰盒 Sprite、色块和程序化占位。正式目标是保持同一俯视规则的 3D 场景，不改成第三人称。所有新增单位、建筑、角色和关键特效必须：

- 使用稳定 ID；
- 通过 `VisualSlot`、`VisualDefinition` 和 `VisualLibrary` 接入；
- 允许后续用 3D Prefab、动画或 Sprite 替换，不修改玩法逻辑；
- 不把碰撞、生命、攻击或存档状态放入纯美术 Prefab；
- 正式模型/贴图导入前记录来源、许可证和目标 Unity 路径。

### 2.4 2D 冻结点与 3D 迁移决策

- 镜头里程碑完成并通过全量验证后，冻结现有 2D 功能基线；冻结不等于删除，`FormalPrototype`、规则层、稳定 ID、schema `30` 存档和现有自动化测试全部保留；
- 停止新增仅服务于 2D 场景的交互实现。尚未完成的建造菜单、内外城放置、物流观察、前哨、迷雾、领袖交互和其余 F1A 功能转到 3D 基础场景继续实现，不先制作重复的 2D 版本；
- 3D 迁移审计、设计规格、可执行计划和首个可回退“可操作 3D 基础”均已完成并通过独立验收；现有 2D 冻结基线继续保留；
- 默认编辑/构建入口已经独立切换到 3D；`FormalPrototype` 继续作为启用的 2D 回归场景保留，不进入默认正式构建；
- 首轮 3D 只使用方块、基础材质和占位 Prefab，不批量制作或导入正式模型、美术、动画与特效；
- 本决策只改变实现顺序，不改变主 GDD 的产品目标、已确认玩法规则或真实 Windows 10/11 冒烟门。

## 3. 后续开发阶段

### 阶段 F1：单城市正式玩法补齐

目标：让四条路线在单城市循环内都有完整生产、防御和单位选择。

1. 统一友军单位规则：目标选择、集结点、脱战跟随、死亡统计和组织再生（已实现：`d5baf17`；真实 Windows 冒烟待补）；
2. 科技路线无人机与过载机制（已实现：`fd42357`；正式无人机美术和真实 Windows 冒烟待补）；
3. 血肉路线感染/寄生状态闭环（已实现：`9792fcb`；正式巨兽美术反馈和真实 Windows 冒烟待补）；
4. 修仙路线剑意、御剑台升级与傀儡维护（已实现：`6200703`；正式美术和真实 Windows 冒烟待补）；
5. 灵能路线精神灼烧、集体意识的单城等价效果（已实现：`95abb35`；正式美术和真实 Windows 冒烟待补）；
6. 发电站、代谢炉、意识网络等缺失路线建筑（已实现：`2e13d6e`；正式资源拆分、美术和真实 Windows 冒烟待补）；
7. 四路线资源、建筑和研究说明统一显示（已实现：`970ad60`；真实 Windows 冒烟待补）。

验收门：每个功能先写规则测试；全部 EditMode/PlayMode、编译、Windows 构建和冒烟通过；每个里程碑独立提交。

### 阶段 F1A：单城市场景与交互基础

目标：保留已经验证的 2D 规则与交互基础，把未完成的单城市移动、内外城建造、生产、物流、角色与前哨交互作为 F1B 3D 灰盒场景的后续功能要求，不再先制作一套 2D 专属实现。

- 当前 2D 功能基线冻结于镜头里程碑 `808c0d6`；`FormalPrototype`、规则层、稳定 ID、存档与自动化测试继续作为强制回归基线；
- 明确移动态和展开态：移动中允许内城轻型施工与维持，地面施工、重型工业和长周期研究需要展开；
- 移动态默认控制城市、展开态默认控制领袖；补齐目的地自动寻路、基础地形阻挡和展开位置合法性（规则与 2D 交互基础已实现：`8693086` 至 `11c90b9`；镜头跟随、自由拖动与快速返回已实现：`9bbcca5`、`118b3f0`、`808c0d6`；自动驾驶科技升级、正式表现和真实 Windows 冒烟待补）；
- 建立内城、地面、两者皆可的建筑位置标签，以及移动可运行、仅展开运行、地形依赖等运行标签（规则基础已实现：`60b891e`；内城放置交互、前哨和真实 Windows 冒烟待补）；
- 建造面板提供快捷栏、分类、搜索、置灰原因和可见性规则；隐藏、未接触路线和唯一特殊建筑不进入普通列表；
- 放置交互支持预览、合法性原因、旋转、连续放置、拖动城墙和取消规划；
- 保留城市范围内自动物流，补齐产销、缺口、阻塞、优先级和请求库存的可观察反馈；
- 建筑脱离城市范围后进入前哨状态，保留库存并显示补给、维护和通信问题；提供撤离清单与基础受袭警报；
- 迷雾采用未探索隐藏、已探索变暗、当前视野实时更新、最后情报可过期的规则；
- 领袖允许低效率手工采集以处理开局或紧急缺口，但不得替代自动采矿闭环；
- 镜头默认跟随当前控制对象，支持自由拖动和快速返回（2D 交互已实现：`9bbcca5`、`118b3f0`、`808c0d6`）；暂停允许规划和下令但不推进规则时间；
- 领袖基础行为可由 AI 执行，玩家可主动接管；Demo 继续使用抽象城市生产力，不生成实体施工工人；
- `BUG-0001` 已明确为冻结 2D `FormalPrototype` 的历史问题，用户决定不修复，状态为“已明确 / 已批准 / 不适用”；它没有修复提交，新的 3D 建造功能不得被计作该问题的修复。

验收门：现有 2D 功能以 `808c0d6` 和全量自动化结果冻结，不再以“完成全部 2D F1A 交互”作为进入 F1B 的前置条件。3D 迁移审计、设计、实施计划与首个可操作基础已经通过独立验收；后续变更仍必须持续通过 2D 规则测试、PlayMode 主循环和旧存档回归。当前真实 Windows 10/11 独立程序冒烟仍待补，补验前不得标记为候选发布版。

### 阶段 F1B：俯视 3D 垂直切片

目标：在不重做核心玩法的前提下，立即开始可回退的俯视 3D 灰盒迁移，并在新的 3D 基础场景中继续实现尚未完成的 F1A 交互。

- 3D 迁移审计、设计规格和可执行计划已完成；批准规格为 `d3c10ec`，实施计划基线为 `52c4637`；
- 独立、可关闭或移除的 `GrayboxPrototype3D` 已建立，现有 2D 场景、规则网格、稳定 ID、schema `30` 存档模块、逻辑坐标和全部自动化测试均保留；
- 第一阶段已使用 Unity 原生 Plane、Cube、Capsule、基础 URP 材质和程序化占位建立地形、移动城市、领袖、直接控制与镜头基础；内城平台、基础建筑、敌人和对应关键反馈仍待后续子里程碑；
- 在 3D 基础场景中继续实现建造菜单、内外城放置、物流观察、前哨、迷雾、领袖交互和其余未完成 F1A 功能，不先补一套 2D 版本；
- `IDEA-0003` 已批准独立 3D 建造适配层设计：普通目录只接 `BuildingCatalog.BuildMenu` 28 项，支持底部快捷栏与完整目录、旋转、连续放置、外城半径 8 世界网格、随城移动的 `8×6` 内城网格、施工与确定性退款、收起前遗弃/完整拆除/快速拆除清单，以及仅 Editor/Development Build 可用的开发修改器；规格见 `Docs/superpowers/specs/2026-08-05-3d-building-placement-and-developer-modifier-design.md`，运行时尚未实现；
